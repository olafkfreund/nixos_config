# Intent: stop p620 hard-resetting when the RX 7900 XTX drops off the PCIe bus

## Problem

p620 has hard-reset twice in 34 hours (2026-09-13 22:34, 2026-09-15 08:02).
Each time the machine dies 1-3 s after a NixOS switch completes, with no
shutdown, no panic and nothing in the journal. The next boot's firmware error
record (BERT) shows the same fatal PCIe Completion Timeout both times, on the
root port that feeds the RX 7900 XTX. Every open session, VM, container and
agent job on p620 is lost, and any deploy to p620 is now a gamble.

Evidence so far:

- Same port, same error bits both times: `e0:03.1` → GPU switch `e1:00.0` →
  GPU `e3:00.0`, `aer_uncor_status 0x4000`
- Unchanged in every boot since 2026-09-08, crashes included: GPU firmware,
  BIOS, kernel command line, `ppfeaturemask` (LACT applies nothing)
- The units a switch restarts are identical in crashing and surviving switches
- ASPM L1 is enabled on the GPU link
- A Waydroid Android session (GPU-rendered) was active at both crashes
- The current PCIe link is healthy: Gen4 x16, zero AER counts

## Proposed outcome

The root cause is identified with evidence rather than correlation, and p620
survives deploys and normal GPU load without a PCIe fatal reset. If it still
fails, the failure leaves enough evidence to pinpoint it.

## Affected users and systems

- p620 only (workstation, Omarchy session, ollama-rocm, Waydroid, docker, VMs,
  self-hosted CI runner, most agent sessions)
- `hosts/p620/nixos/amd.nix`, `hosts/p620/nixos/boot.nix`, Waydroid feature

## Constraints

- No host restart or deploy of p620 without a bus announcement; experiments
  must not take the host down while other agents are mid-flight
- Keep ROCm/ollama working on the GPU
- Prefer reversible, runtime experiments before permanent config
- Hardware checks (reseat, cables, PSU) are the user's hands, not ours
