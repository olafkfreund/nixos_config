# Intent: Remove zellij and tmate

## Problem

zellij is configured and installed but never used. It is still wired into
the build in several places:

- a Home Manager module with layouts and aliases (`home/shell/zellij/`)
- a feature flag, `features.multiplexers.zellij`, set per host and per
  profile
- a flake input, `zjstatus`, plus an empty stub module that every host
  imports (`home/shell/zellij/zjstatus.nix`)
- bare `zellij` packages in the terminal config and the laptop package list

That wiring costs something. On 2026-09-22 nixpkgs marked `tmate` insecure
(CVE-2018-19387). tmate came in only through the zellij module, and razer
stopped evaluating. The one-line tmate removal (#1950) unblocks razer. The
rest of zellij is still dead weight that the next nixpkgs change can break
in the same way.

## Proposed outcome

- Nothing in the repo installs or configures zellij, zjstatus or tmate.
- `zellij` is not on `PATH` on p620, razer or p510.
- The `zjstatus` flake input is gone from `flake.nix` and `flake.lock`.
- Docs no longer describe zellij as available.
- tmux stays and keeps its configuration.

## Affected users and systems

- Hosts: p620, razer, p510. Only razer and p510 enable the zellij module
  today, but the zjstatus stub and the bare packages reach every host.
- Files, roughly: `home/shell/zellij/` (deleted), `home/shell/default.nix`,
  `flake.nix` and `flake.lock`, `Users/common/features.nix`,
  `Users/common/features-impl.nix`, `Users/olafkfreund/{profile,p620_home,razer_home,p510_home}.nix`,
  `hosts/{p620,razer}/home-manager-options.nix`,
  `home/profiles/{developer,server-admin}/default.nix`,
  `home/desktop/terminals/default.nix`,
  `modules/nixos/packages/host-specific/laptop-packages.nix`, plus docs
  (`README.md`, `home/shell/README.md`, `docs/architecture/theming.md`,
  `.agent-os/product/*`).
- User: olafkfreund.

## Constraints

- tmux, herdr and tuios are not touched.
- p510 is never built or deployed without asking. Evaluating it here is
  fine, but its deploy is the user's call.
- The one-line tmate fix (#1950) ships separately, ahead of this work.

## Open questions

- Should zellij's shell aliases (`zj`, `zja`, ...) and existing
  `~/.config/zellij` files be cleaned up on the hosts, or left to go stale?
  They are Home Manager-managed, so they disappear on the next activation
  anyway. Proposal: rely on that and do no manual cleanup.
