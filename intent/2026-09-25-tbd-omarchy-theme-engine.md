# Intent: Omarchy runtime theme engine for NixOS

## Problem

The current configuration uses Omarchy as the runtime theme source and Stylix
as the rebuild-time renderer. Changing an Omarchy theme updates Omarchy-owned
files immediately, but GTK, Qt, terminals, browsers, Flatpak applications,
and other user applications do not all change together without additional
manual reloads or a NixOS rebuild. Stylix-generated files are immutable store
outputs, while Omarchy's theme engine expects mutable user-session files.

## Proposed outcome

One Omarchy theme change updates the complete running desktop palette through a
single NixOS-packaged runtime engine and menu plugin, without requiring
`nixos-rebuild` for user-session applications. The engine reloads or restarts
applications where live theme reload is not supported and reports any remaining
stale applications. Stylix remains the declarative renderer for rebuild-time
and boot-time surfaces such as GRUB, Plymouth, fonts, icons, cursor, and other
static targets.

## Affected users and systems

- The `olafkfreund` desktop user.
- Nixarchy/Omarchy sessions on p620, razer, and p510.
- Omarchy theme hooks and Quickshell menu plugins.
- GTK, Qt/KDE, terminals, browsers, Electron applications, and Flatpak apps.
- Existing Stylix integration in `modules/desktop/` and Home Manager profiles.

## Constraints

- Omarchy `colors.toml` remains the runtime palette source of truth.
- No runtime writes to `/nix/store` or Nix-generated immutable files.
- NixOS and Home Manager integration must remain declarative.
- The engine must run as the desktop user with no unnecessary privilege.
- Runtime-owned files must not also be generated by Stylix.
- Flatpak access must be explicit and opt-in because it changes sandbox grants.
- Bootloader, initrd, Plymouth, and console artifacts may still require a
  rebuild or reboot.
- The menu plugin must delegate theme application to the engine rather than
  duplicate theme-generation logic.
- Existing unrelated worktree changes must be preserved.

## Open questions

- Which applications should be restarted automatically versus reported as
  stale?
- Should the first implementation package Omarchroma directly or implement a
  smaller Nix-native runtime engine using its palette and renderer model?
- Should the plugin be maintained in this configuration repository or as a
  separate public plugin repository?
