# Intent: clear the remaining Omarchy plugin and shell errors

Follow-up to Issue #2151, which covers quickshell's rescans, Omamail's
reopening, the plugin removals, nixarchy.microvm and bar-folder.

## Problem

The shell log review on p620 (2026-10-04, the Sep 24 boot and this one) found
these errors as well. Each one is a broken feature or recurring noise, and
together they bury the warnings that matter:

| Source | Error | Owner |
| --- | --- | --- |
| olafkfreund.ai-mirror `Overlay.qml` | "File name case mismatch" (6) | ours, flake input `ai-mirror` |
| nixarchy.menu `ResultRow.qml` | can't open `~/.local/share/icons/QuickWebApps/Gemini4352.svg` and `~/Pictures/claude-ai-icon.svg` (22) | user desktop entries |
| PluginRegistry | "unknown plugin" for nixarchy.hyprlandsettings and io.github.yanuarpmbd.winvm; "plugin not enabled" for nixarchy.pkg, which is listed in bar-folder's widgets | user config (`shell.json` and whatever calls `setEnabled`) |
| nixarchy.winvm `Menu.qml` | `isTransitioning` of undefined (2) | ours, olafkfreund/nixarchy-winvm (hand-installed copy, not Nix-managed) |
| aziz.hyprforge `Service.qml`, `Panel.qml` | null value; undefined→bool | upstream, AbdulazizAlwabel/omarchy-hyprforge |
| omarecorder `Service.qml` | FileView reads a missing `/run/user/1000/omarecorder/state.json` (48) | upstream, huey-holdings-llc/omarecorder (hand-installed, no git) |
| webcam `Panel.qml` | `applyState` is not a function (3) | upstream, kristoferlund/omarchy-webcam |
| `omarchy-crash-watch.service` | installed for every user session by nixarchy, so it also runs in the SDDM greeter's user manager (uid 175), fails and restarts every 5 s | nixarchy |
| Omarchy `shell.qml` | ReferenceError: `errorString` is not defined (6) | upstream Omarchy |

## Proposed outcome

- After a fresh login on p620 and razer, the shell log shows none of the
  errors above.
- The menu shows proper icons for Gemini and Claude.
- The greeter's user manager no longer restarts the crash watcher.
- Where the bug is upstream, there's a PR or an issue, and our copy runs the
  fix (from a branch or a pinned version) until upstream releases it.

## Affected users and systems

- p620 and razer (the Omarchy sessions with these plugins). p510 only
  through nixarchy (crash-watch), whose deploy is a separate decision.
- Repos: this one, olafkfreund/nixarchy (crash-watch),
  olafkfreund/nixarchy-winvm, the ai-mirror input, plus upstream
  hyprforge, omarecorder, webcam and Omarchy.

## Constraints

- No functional regressions in the plugins being fixed.
- Hand-installed plugins (hyprforge, webcam, omarecorder, winvm) are user
  state; a local patch must be recorded so an update doesn't silently undo it.
- Upstream PRs and issues go out under your GitHub account, so they're
  outward-facing. Each one gets shown to you before it's posted.
- p510 is never built or deployed without asking.
