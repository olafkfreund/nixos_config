# Intent: package tfm-tui as the nixos-tfm flake and install it on p620 and razer

## Problem

[tfm](https://github.com/clarkarch/tfm-tui) (clarkarch/tfm-tui, MIT, v1.0.0
released 2026-10-09) is a mouse-first terminal file manager: grid and list
views, a places sidebar, previews, tabs and dual pane, trash, archives, an
embedded terminal and plugins. It is not in nixpkgs, and its only install path
is `curl … install.sh | bash` into `~/.local/bin`. That path is imperative,
leaves the result unpinned, and gives NixOS a binary that expects
`/lib64/ld-linux-x86-64.so.2`.

The user wants it packaged the way `nix-craftapps` was (#2230): in its own
public flake that anyone can consume, with NixOS and Home Manager modules, and
then installed on p620 and razer.

Three upstream facts shape the work:

- The release is a single Bun-compiled binary per architecture, with the app
  embedded in an ELF `.bun` section. A probe on p620 showed that setting the
  interpreter with patchelf keeps it working (`tfm --version` prints
  `tfm 1.0.0`).
- Video thumbnails need ffmpeg. tfm never uses the system `PATH` for it: it
  looks at `$TFM_FFMPEG`, then a `tfm-ffmpeg` file next to the binary.
- tfm writes `~/.config/tfm/config.toml` itself from its Settings screen, by
  writing a temporary file and renaming it over the original. A read-only Home
  Manager store link would therefore be overwritten on the first save.

## Proposed outcome

- A public GitHub repo, `olafkfreund/nixos-tfm`, with a `flake.nix` that
  exposes:
  - `packages.<system>.tfm` (x86_64-linux and aarch64-linux) and an overlay.
  - A NixOS module `programs.tfm` that installs tfm, with options for the
    package, the optional helper tools and ffmpeg.
  - A Home Manager module `programs.tfm` with the same install options, plus
    `settings` that write `config.toml` from Nix in a way that does not break
    the in-app Settings screen.
  - A README with a "Getting started" section covering flake input, NixOS,
    Home Manager and `nix run`.
- In this repo, `nixos-tfm` is a flake input. tfm is enabled on p620 and run
  there as the test. razer follows once p620 checks out.
- `nix flake update nixos-tfm` picks up new tfm releases like any other input.

## Affected users and systems

- New repo: `github:olafkfreund/nixos-tfm` (public).
- Hosts: p620 (test) and then razer. p510 does not get it.
- This repo: `flake.nix` gains one input, a host or shared module enables it,
  and `flake.lock` changes.
- Docs: a page under `docs/`, with nav added to both `mkdocs.yml` and
  `mkdocs-full.yml`.

## Constraints

- Public repo: no secrets, hostnames or personal paths in it.
- The input follows our `nixpkgs`.
- Explicit imports only, and enabling goes through an option flag.
- The checkout at `~/.config/nixos` stays on `main`; work happens in the
  worktree.
- p620 deploy: announce on the agent bus first. razer builds on p620. p510 is
  not touched.
- Third-party binary: pin it by hash per release. Nothing downloads at
  runtime.

## Open questions

1. **Build from the release binary or from source?** The release binary is
   proven and small to package. A source build (Bun, plus a fixed-output
   `node_modules` derivation for the opentui native library and the npm
   dependencies) is more reproducible-from-source but fragile, and Bun 1.4
   must be in nixpkgs. Recommendation: the release binary, with source as a
   later option.
2. **How should Home Manager config work?** Recommendation: the module writes
   `settings` as TOML to the store and **seeds** `~/.config/tfm/config.toml`
   only when it is missing, so the in-app Settings screen keeps working. A
   `settings.force` (or a mode option) would make Nix overwrite the file at
   every activation for people who want fully declarative config.
3. **Should ffmpeg be on by default** (via `$TFM_FFMPEG` pointing at
   `ffmpeg-headless`, about 50 MB more closure), or opt-in?
4. **Should there be a daily update workflow** in the new repo, as
   nix-craftapps has (bump the version and hashes when upstream tags a
   release)?
