# Intent: a first agent-bus read returns the newest messages

## Problem

`read_new` and `peek` in `pkgs/agent-bus-mcp/agent_bus_mcp.py` ask Matrix
`/messages` for `dir=f` with no `from` when no cursor is saved. That starts
at the room's creation. A fresh session's first read is the oldest page
(measured 2026-10-15: six-week-old posts, where the docstring promises
"recent history"). `peek` pages forward 50 per Stop, so a new @-mention can
take many turns to surface.

## Proposed outcome

A first `read_new` or `peek` returns the newest `limit` messages, oldest
first, and later calls continue from the live end. Reads that already have
a cursor behave exactly as today.

## Affected users and systems

Every Claude Code session's agent-bus MCP server, on every host that has
the package. nixarchy re-vendors this file (`share/agent-bus/`), where the
same fix landed in olafkfreund/nixarchy#1275.

## Constraints

- No change to the cursor table, so existing marks keep working.
- Deploys only after the PR merges (the Justfile refuses a branch).
  Announce on the bus before switching p620.
