# Intent: install Flow Desktop via the nixos-FlowTube flake

## Problem

There is no privacy-respecting YouTube / YouTube Music desktop client on the
fleet. Flow Desktop (Flow-Tube/Flow-Desktop, Tauri 2) is one, and is the
desktop companion to Flow for Android, but it is not in nixpkgs. A packaging
flake now exists, `github:olafkfreund/nixos-FlowTube`, with a Home Manager
module (`programs.flow-desktop`), CI that builds and render-checks it on
x86_64 and aarch64, and a daily upstream-update workflow. Nothing in this
tree consumes it yet.

## Proposed outcome

On the chosen hosts, Flow appears in the Omarchy launcher, starts, plays
video with hardware-capable GStreamer decoders, and `flow://` links from the
browser extension open it. Updates arrive with `nix flake update flowtube`
(or `nhs`), like every other flake input.

## Affected users and systems

- `flake.nix`: one new input, following our `nixpkgs`.
- The olafkfreund Home Manager profile on the chosen hosts.
- Hosts: p620 and razer (interactive desktops). p510 only if asked.

## Constraints

- No inline service config; this is a user app, enabled per host the same way
  as other optional desktop apps (cf. `nix-craftapps` / `features.craftapps`).
- Explicit imports only; no auto-discovery.
- p510 is never built or deployed without asking.
- razer builds via p620 (`just deploy-via-p620 razer`): the app is a ~23 min
  Rust LTO build with no binary cache, so p620 builds it once and razer
  receives the store path.
- Flow is a beta app (0.1.0-beta2) that talks to YouTube; it carries its own
  updater, which the flake disables.

## Open questions

Resolved at approval (the approver accepted the proposed defaults):

1. Hosts: p620 and razer.
