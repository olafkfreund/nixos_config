# Intent: register the Craft apps' MCP servers with Claude Code

## Problem

Every Craft app has an MCP server built in (`<app>-cli mcp`, stdio).
nix-craftapps now exposes them as a module option,
`programs.craftapps.mcp.enable` (olafkfreund/nix-craftapps#4). That option
defines one server per enabled app in three places:

- `programs.craftapps.mcp.servers`;
- `/etc/craftapps/mcp.json`;
- Home Manager's `programs.mcp.servers`, for every user.

On p620 and razer, none of this reaches Claude Code:

- `features.craftapps` (`modules/desktop/craftapps.nix`) does not turn
  the option on.
- `flake.lock` pins nix-craftapps from before the option existed.
- This tree does not use Home Manager's `programs.claude-code`, so
  nothing reads `programs.mcp`. Claude Code's servers are written into
  `~/.claude.json` by the `claudeSharedMcpServers` activation in
  `home/development/claude-code-mcp.nix`. Only servers declared there
  follow a rebuild (#1933).

So an agent on either host cannot drive PhotoCraft, WordCraft or the
others, although they are installed.

## Proposed outcome

- On every host with `features.craftapps.enable` (p620, razer), each
  enabled Craft app shows up in `claude mcp list` after a rebuild and a
  new session. Each one connects and answers `tools/list`.
- An app excluded through `features.craftapps.apps.<name> = false` gets
  no server.
- The servers follow each update. The store paths in `~/.claude.json`
  are reconciled on every activation, like `agent-bus` and
  `ollama-code`.
- Hosts without `features.craftapps` see no change.

## Affected users and systems

- **Hosts:** p620 and razer, the two that enable `features.craftapps`.
  p510 is unaffected.
- **Files:** `flake.lock` (the nix-craftapps input),
  `modules/desktop/craftapps.nix` and
  `home/development/claude-code-mcp.nix`.
- **Users:** the user's Claude Code sessions on those hosts. They get up
  to 12 more MCP servers.

## Constraints

- **Leave `/etc/claude-code/` alone.** Never write `managed-mcp.json`
  there; it takes exclusive control of MCP and would drop every other
  server. Use the existing `claudeSharedMcpServers` reconcile path only.
- **The reconcile must stay additive.** Servers that are not declared
  are left untouched, so the user's own servers survive.
- **Shared hosts:** announce on the agent bus before deploying p620
  (AGENTS.md rule 6). Build razer on p620 (`just deploy-via-p620 razer`).
- **Branch work stays in the worktree** (`../nixos-2348`). `/etc/nixos`
  stays on `main` (#2052).
- **Rebuild, then start a new Claude Code session.** A running session
  keeps its old server set, so judging the change from inside one is
  misleading.
- **The servers run headless,** with the defaults nix-craftapps sets
  (vectorcraft gets `--headless`). They write logs under `~/.config/<app>/`.

## Open questions

1. **Always on, or a switch?** Should every host with `features.craftapps`
   get the servers, or should there be a separate switch
   (`features.craftapps.mcp`)? Recommendation: a switch that defaults to
   `true`. A host can then keep the apps but drop the servers.
2. **All 12, or a subset?** Should every enabled app get a server, or only
   a few? Twelve more entries in `/mcp` is a lot of noise. Recommendation:
   every enabled app, which is the nix-craftapps default. Exclude apps with
   `apps.<name>.mcp.args` overrides only if one proves noisy.
3. **Also Codex and Antigravity?** `antigravity-config.nix` is gated like
   `claude-code-mcp.nix`. Should they get the servers too?
   Recommendation: Claude Code only for now. Add the others when someone
   needs them.
