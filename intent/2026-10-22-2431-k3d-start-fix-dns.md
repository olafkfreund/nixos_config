# Intent: k3d bootstrap must be able to restart the factory cluster after a reboot

## Problem

The k3d-factory cluster on p620 stayed down from the 2026-10-21 07:42 BST reboot
until a manual recovery on 2026-10-22. Every `k3d-cluster-bootstrap` self-heal
cycle failed, for two reasons.

1. k3d 5.9.0 applies its DNS fix on `k3d cluster start` as well as on create.
   `modules/containers/k3d.nix` sets `K3D_FIX_DNS=0` only for `create`, and the
   nodes mount the declared resolver over `/etc/resolv.conf`, so every start
   aborts with "Cannot activate DNS fix (K3D_FIX_DNS) when there's a file
   mounted at /etc/resolv.conf!".
2. After the reboot Docker failed to program the serverlb host port because
   tailscale was not up yet. The serverlb was left with no network attachment,
   and its nginx crash-looped on `host not found in upstream` for server-0,
   even once the server ran.

## Proposed outcome

After a reboot the bootstrap unit restarts the stopped cluster and the API
becomes reachable without manual steps.

## Affected users and systems

p620 (k3d-cluster-bootstrap, module `modules/containers/k3d.nix`).

## Constraints

- No destructive action: no cluster delete, PVCs and etcd are preserved.
- No deploy or restart as part of this change.
