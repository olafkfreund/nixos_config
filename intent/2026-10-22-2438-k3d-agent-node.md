# Intent: a second node (one k3d agent) for the p620 factory cluster

## Problem

The k3d-factory cluster on p620 is created with `--servers 1 --agents 0`, so it
has one node. TFactory wants to drop its ReadWriteOnce repo PVC (TFactory
#1160), which needs a second schedulable node. The module has no way to ask for
agents, and only the server gets the local-path storage bind mount, so a PVC
provisioned on an agent would live inside that container and be lost with it.

## Proposed outcome

A host can ask for N k3d agents. When p620's cluster is next recreated it comes
up with `k3d-factory-server-0` and `k3d-factory-agent-0`, both Ready, both
writing local-path PVs to the host storage dir, and the PV snapshot/restore,
self-heal and backup paths keep working.

## Affected users and systems

p620 (`hosts/p620/configuration.nix`), module `modules/containers/k3d.nix`.
Other hosts using the module keep zero agents.

## Constraints

- Default stays 0 agents: no change for any other host.
- Nothing changes on the running cluster; the setting applies only on a
  recreate, which the owner runs by hand.
- No deploy, no docker or cluster commands in this change.

None (owner decision recorded on #2438).
