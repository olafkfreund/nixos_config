# Intent: run the agy guard probe automatically, and document the coder guard

Follows #2453 (PR #2462).

## Problem

Since #2453, `agy-implement` refuses to run on an agy version until
`agy-guard-probe` has passed for that version on that host. That is the right
guarantee, but it costs a manual step. The nightly `package-autoupdate.yml`
job merges a new agy most days (#2447, #2459), so after each deploy someone
has to run the probe by hand on p620 and on razer before the next handoff.
Otherwise the handoff just stops with "run agy-guard-probe".

The coder guard, the probe and the gate are also undocumented. Nothing under
`docs/` mentions them. The only description is the skills, `AGENTS.md`
and the intent/spec/plan files, so a reader of the published site can't find
out why `agy-implement` refused or what it checks.

## Proposed outcome

- After an agy update, no one has to do anything before handing work to agy.
  The probe runs by itself for the new version on each host, and
  `agy-implement` works.
- The guarantee does not weaken. agy never gets write access on a version
  whose probe has not passed on that host.
- A failed probe is visible without anyone looking for it: it opens the
  deduplicated issue (as now) and `agy-implement` keeps refusing.
- A new page under `docs/tooling/` explains the agy coder guard: what it
  allows and denies, the version gate, the probe, what happens automatically,
  and what to do when the probe fails. It is linked in both `mkdocs.yml` and
  `mkdocs-full.yml`.

## Affected users and systems

- `home/development/antigravity-config.nix` (`agy-implement`,
  `agy-guard-probe`)
- p620 and razer. p510 doesn't run agy.
- Anyone, Claude or the user, who hands a plan step to agy.
- `docs/tooling/`, `mkdocs.yml`, `mkdocs-full.yml`, and the handoff skill's
  "After an agy update" section, which would no longer describe a manual
  step.

## Constraints

- **Fail closed.** If the automatic probe can't run (agy logged out, no
  network, a timeout), `agy-implement` refuses, as it does today.
- **The probe needs a logged-in agy**, so it runs on the host, not in CI
  (#1831, subscription login only). It can't run during a NixOS or
  Home Manager activation either, because that would add about 90 seconds and
  a network call to every deploy.
- It uses a little subscription quota: one probe per agy version per host,
  not one per handoff.
- No new privileges. The probe runs as the user, as it does now.
- Nothing about the guard checks themselves changes.

## Decisions (approved 2026-10-24)

1. **(a)** `agy-implement` runs the probe itself the first time it meets an
   unprobed agy version, then continues if it passes. There is no
   background timer.
2. **Docs:** one page at `docs/tooling/agy-coder-guard.md`, under "Tooling"
   in both nav files.
