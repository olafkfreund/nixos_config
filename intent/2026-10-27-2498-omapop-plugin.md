# Intent: omapop selection-bar plugin on p620 and razer

## Problem

There is no PopClip-style action bar on the Omarchy desktop: selecting text
with the mouse offers nothing, so copy, search and open-link go through the
keyboard or a context menu. [omapop](https://github.com/jondkinney/omapop)
(MIT, v0.4.11, commit `7d6b1aa`) provides one as an Omarchy shell plugin, but
its upstream install path does not work here:

1. **`omarchy plugin add` is imperative.** It clones into
   `~/.config/omarchy/plugins/`, which nothing in this repo tracks, and never
   updates. Every other plugin we run (omadroid, meeting-mode, pixelbuds …)
   is a store path set through `programs.nixarchy.plugins."<id>".src`.
2. **Every tool is a hardcoded `/usr/bin/...` path, and envfs cannot rescue
   them.** About 30 call sites across `Service.qml` and `bin/*.py` (python3,
   hyprctl, setpriv, wl-paste/wl-copy, echo, mkdir, xdg-open, dbus-send, bash,
   gdbus, openssl). Each child process starts with `clearEnvironment` and
   `PATH=/usr/bin:/bin` (`Service.qml:51-62`). envfs resolves `/usr/bin/X`
   from the caller's PATH, so from those processes almost nothing resolves.
3. **The Python helpers need modules the system python3 lacks.** They need
   PyYAML (extension parsing) and `gi` with the `Atspi-2.0` typelib
   (editable-field detection). `GI_TYPELIB_PATH` is dropped by the cleared
   environment, so even a correct python would fail quietly here.
4. **It breaks under our Qt.** We run Qt 6.12, whose `Color` singleton
   shadows omapop's theme colours. Upstream issue/PR #10 has the fix, still
   unmerged.
5. **Upstream has no tags or releases.** There were 30 commits from
   2026-09-08 to 09-10, nothing since, and a manifest version bump on nearly
   every commit. Upgrades need a deliberate tracking method.

## Proposed outcome

- After a rebuild on p620 and razer, the plugin is available as
  `io.github.jondkinney.omapop`. After a one-time
  `omarchy plugin enable io.github.jondkinney.omapop`, selecting text in a
  browser or editor (Shift-select in terminals) shows the bar, and Copy,
  Search and Open Link work.
- The bar icon shows the right theme colours.
- Editable-field detection works: Cut and Paste are offered only in fields
  that accept them.
- Weekly network refresh of the PopClip catalogue, and extension downloads,
  stay off by default.
- Upgrading is a single, reviewed bump: one commit changes the pinned rev and
  hash, the build fails loudly if an upstream change breaks a path
  substitution, and the repo's update tooling reports when upstream has new
  commits.

## Affected users and systems

- Hosts: **p620** and **razer** (Omarchy session). Not p510.
- New package under `pkgs/`, following `pkgs/omadroid/default.nix`.
- New `hosts/common/nixos/omarchy-omapop.nix`, imported from
  `hosts/{p620,razer}/nixos/nixarchy.nix`.
- Possibly the `check-updates` tooling, so it sees a pinned non-flake
  package.
- User: olafkfreund only (the Home Manager plugin option is per user).

## Constraints

- Must be declarative: a pinned store path, no `omarchy plugin add`, no
  writes into `~/.config/omarchy/plugins` by hand.
- Must not be a flake input that `nhs` bumps unreviewed. The plugin runs
  unsandboxed in the shell and can fetch from the network, so each upgrade
  is reviewed.
- Must not disturb the Hyprland/nixarchy wiring (#1562, #2275):
  `hyprctl` comes from the compositor package nixarchy runs, not a second
  Hyprland.
- `catalog/` and `ports/archives/` must stay byte-identical. Their SHA-256
  hashes and Ed25519 signature are verified at runtime.
- Must coexist with p620's accent-hold plugin. Both hook
  `input.keyboard.key` non-consuming, which is compatible.
- Keep the closure small. Optional PopClip-port tools (deno, node, zeal,
  espeak-ng, browsers) are not pulled in.
- Upstream bug #9 (directory installs fail for every approved package) is
  accepted as-is. We are not enabling directory installs.

## Open questions

1. **Accessibility probe.** It is on by default. It sets the session-wide
   `org.a11y.Status.IsEnabled` flag, so every GTK, Qt and Chromium app builds
   its accessibility tree, and Electron apps can slow down. With it off,
   Cut/Paste detection falls back to window-class rules. Keep upstream's
   default (on), or turn it off?
2. **JavaScript extensions.** Add `deno` so JS-based PopClip extensions work,
   or leave them disabled (default)?
3. **Upgrade signal.** Is a `# Bump against:` comment (as in omadroid) plus a
   check in the existing `check-updates` skill enough? Or do you want a
   `just` recipe that prints the rev and hash for a new upstream commit?
