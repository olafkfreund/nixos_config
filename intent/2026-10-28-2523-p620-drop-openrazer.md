# Intent: drop openrazer from p620

## Problem

p620 has no Razer hardware and `hardware.openrazer.enable` is false, yet the
user unit `openrazer-daemon.service` exists there. Something calls `org.razer`
over D-Bus, the daemon starts, finds no device and fails (seen 2026-10-28
07:39). It arrives because `customPkgs.user-python3` carries `ps.openrazer`
for the omarazer Omarchy plugin, and that propagates `openrazer-daemon` with
its systemd user unit and D-Bus service file. omarazer is installed on razer
only.

## Proposed outcome

On p620 the user profile holds no `openrazer-daemon.service` and no
`org.razer.service`, and the failed unit is gone. razer keeps the openrazer
library in its `python3`, so omarazer keeps working.

## Affected users and systems

- p620 and razer (both import `Users/olafkfreund/profile.nix`); p510 does not.
- `pkgs/default.nix` (`user-python3`), `Users/olafkfreund/profile.nix`.

## Constraints

- Must keep a single `python3` per profile: the nixarchy gitlab/github plugin
  overrides in `profile.nix` must use the same derivation as `home.packages`,
  or buildEnv collides.
- Must not change razer's closure.
- p510 is not built or deployed.

## Open questions

None. The user pre-approved intent, spec and plan on 2026-10-28.
