# Intent: Exposé and AI Kit keys that do nothing

## Problem

Two keys declared for both p620 and razer in `hosts/common/nixos/omarchy-keys.nix` do
nothing, and the keybindings menu still lists them as working features.

- **Exposé, SUPER+E** sends `expose.window-overview:toggle`. Nothing handles that event:
  the plugin `expose.window-overview` (upstream `kristofferR/omarchy-expose`) is not in
  `~/.config/omarchy/plugins` on either host. Nothing in the repo declares it, so it was probably a
  hand install on p620. Backups of p620's `shell.json` name it up to 2026-09-13.
- **AI Kit, SUPER+CTRL+J** runs `aikit`. On p620, `~/.local/bin/aikit` and its three
  siblings are dangling symlinks into `~/.config/omarchy/plugins/atypical.aikit`, which no
  longer exists. `aikit-sync.timer` is not found either, and `~/.local/share/aikit` was last
  written on 2026-08-29. razer has none of it.

Nothing in this repo declares either plugin, so they could vanish with no trace in git. I do
not know how or why they went. #2717 kept the keys because its intent said no existing
key may lose its bind, and it raised this issue to decide their future.

## Proposed outcome

For each of the two keys, one of these is true on p620 and razer:

- **Restored:** pressing the key does what its menu entry says, and a rebuild keeps it that
  way.
- **Removed:** nothing is bound to the chord any more, and neither the menu nor
  `docs/architecture/desktop.md` (the key table and the prose saying razer gets Exposé)
  mentions it. That includes any copy in the user-owned `bindings.lua`, not just the
  declaration in `omarchy-keys.nix`.

No declared key is left pointing at something absent, for these two chords. Issue #2723 is
then closed.

## Affected users and systems

- p620 and razer: the shared key list. p510 does not import `omarchy-keys.nix`, so it is
  out of scope.
- `hosts/common/nixos/omarchy-keys.nix`, `docs/architecture/desktop.md`.
- If a plugin is restored: a new `hosts/common/nixos/omarchy-<plugin>.nix`, its package or
  flake input, and the host imports. AI Kit also needs its CLI on `PATH` and possibly its
  sync timer, which a shell-plugin module like Altscape's does not provide.
- `~/.config/hypr/bindings.lua`, which is user-owned, holds its own copies: both binds on
  p620 (lines 61 and 116) and the AI Kit bind on razer (line 78). `repo-keys.lua` unbinds only
  chords it declares, so removing a declaration brings those copies back to life. The spec
  must say how they go.
- Leftovers on p620 only if AI Kit is removed: the four dangling symlinks and
  `~/.local/share/aikit`, including its database. Deleting that database is irreversible
  and needs its own approval.

## Constraints

- Declared Hyprland keys stay in `omarchy-keys.nix`; the repo wins on a declared chord.
- Restoring a plugin should follow a declared pattern such as `omarchy-altscape.nix` and
  not another hand install, or it can vanish again in the same way.
- No store-path or lock change beyond what the chosen outcome needs.
- Third-party plugin code runs inside the Omarchy shell, so restoring one adds a dependency
  to review. Exposé's upstream is MIT, active as of 2026-10-26, and says it adds no packages
  or daemons. Those are its own claims and are unverified here.

## Open questions

1. **Exposé:** restore or remove? Restoring brings back a live window overview on SUPER+E.
   Its top-left hot corner also comes on by default.
2. **AI Kit:** restore or remove? I have not found its upstream. The plugin ID is
   `atypical.aikit` and no public repository matched my searches, so restoring depends on
   you knowing where it came from.
3. **If restored, on which hosts?** The keys are declared for both, but I found neither
   plugin on razer and no sign it ever had them. Should a restored plugin go on both hosts,
   or p620 only with the key moved to p620's list?
4. **If Exposé is restored,** should its hot corner stay on or be turned off?
5. **If AI Kit goes, should `~/.local/share/aikit` go too?** It may be the only copy of
   whatever it held.
