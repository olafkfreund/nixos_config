# Intent: enable llm-index on p620 for Claude Code, Codex and agy

## Problem

`nixarchy-llm-index` indexes local documents and code and serves them to
agents over MCP. On 2026-11-12 it ran on p620 as a hand-started trial
(`llm-index-trial.service`, a transient user unit):

- 38k code files and 6k documents, indexed in about 15 minutes;
- memory at the 806 MB soft limit;
- private content never surfaced through the public tier.

Claude Code, Codex and agy each search it today, but the trial:

- stops at reboot or logout;
- points every agent at a binary and config in `~/llm-index-trial-*`;
- needs a manual `SQLITE_TMPDIR` workaround (nixarchy-llm-index#8);
- gives the agents no instructions saying when to use the index.

## Proposed outcome

- On p620, a declarative Home Manager user service `llm-index.service`
  indexes:
  - `/mnt/code/Source-home` (the real path of `~/Source`) as **public**;
  - `~/Documents` as **private**.
- Claude Code, Codex and agy each have the **public** MCP server
  registered, so after a rebuild a `search` call works in each one. The
  private server is not registered anywhere.
- All three get the module's tool instructions (`agentInstructions`).
- The trial unit, its files and its registrations are gone.

## Affected users and systems

- p620 only, user `olafkfreund`.
- Codex and agy instructions come from `home/development/agent-rules.nix`,
  which every host imports; the change must leave other hosts' output
  unchanged.
- No system service and no service credentials.
- `~/.gemini` syncs across hosts, so agy's registration also reaches razer
  and p510. There the binary does not exist and agy shows the server as
  failing to start. That is harmless and accepted. The plan must not
  fight it from the other hosts' activation, because that would flip-flop
  through the sync.

## Constraints

- The flake input is pinned to the nixarchy-llm-index commit that contains
  the #8 fix.
- Follow the existing pattern for a Home Manager module from a nixarchy
  flake: a `hosts/common/nixos/*.nix` file imported by p620, like
  `omarchy-meetingai.nix`.
  - AGENTS.md rules 1–2 (`modules/`, `DynamicUser`, `ProtectHome`) are for
    system services.
  - A user service that must read `~/Documents` cannot use `DynamicUser`
    or `ProtectHome`. It confines itself instead: the workers run under
    Landlock, read-only beneath the roots, and the coordinator can write
    only to its state dir.
  - This is the same exception the meetingai user daemon already has.
- MCP registration must survive Claude Code and Codex editing their own
  config files. The files are seeded and mutable, so registration is
  idempotent activation, as `codex-cli.nix` already does for `nixd`.
- Never register the private tier with a cloud agent.
- **What goes in the public tier.** The owner chose all of `~/Source`,
  including the Calitti client repositories (2026-11-12). The module's
  built-in denylist keeps secret-bearing files out (`.env*`, `*.pem`,
  `*.key`, `id_rsa*`, `.ssh/`, `.gnupg/` and others). Verify that a public
  search returns none of them and nothing from `~/Documents`.
- **Registration converges.** It works from a fresh config and from the
  trial's: an entry whose command differs is replaced, not skipped, and
  unrelated entries stay as they are. It is checked in a new session of
  each client.
- **Gated.** Instructions and registrations exist only where
  `services.llm-index.enable` is true. Hosts that do not import the module
  must evaluate exactly as before.
- Announce on the agent bus before deploying p620, and before stopping the
  trial unit. Build and test first.
