# Intent: Flux on p620 and razer

## Problem

Flux (olafkfreund/nixarchy-flux) links the desktop to the Android phone:

- files, clipboard and notifications
- calls and texts
- fingerprint approval
- Do Not Disturb sync

Neither p620 nor razer has it: there is no `fluxd`, no `flux-cli`, and no shell plugin. The Nixi companion's new phone
feature (olafkfreund/nixi-nixarchy#231) talks to `fluxd` over its local socket, so without Flux it shows only "Flux
isn't running". The owner wants Flux on both hosts, and the phone feature tested live on p620.

## Proposed outcome

- p620 and razer run `fluxd` as a user service for `olafkfreund`, from the Flux flake's NixOS module.
- `flux-cli` and the Qt app are installed.
- The firewall stays closed. `fluxd` opens the connections to the phone itself, and Tailscale covers away-from-home.
- After a one-time pairing on the phone (by hand), Nixi's Phone switch shows "Connected: <phone>" on p620.

## Affected users and systems

- Hosts: p620 and razer. p510 is not affected.
- `flake.nix` and `flake.lock` (a new `flux` input), and one shared host module that both hosts import.
- The owner's Android phone, which needs the Flux app built from nixarchy-flux#59 or later (CI artifact or release),
  then pairing.

## Constraints

- Merge nixarchy-flux#59 first, so the input carries the call, approval and Do Not Disturb state that Nixi uses.
- No PAM change in this task: fingerprint `sudo` approval (`approve.services`) changes how `sudo` authenticates, and
  stays a separate decision.
- No webcam module (`v4l2loopback`): not needed for the phone feature.
- `openFirewall = false`.
- Deploy each host from a clean worktree (memory "just deploy builds ~/.config/nixos"). razer deploys via p620.

## Open questions

- Fingerprint `sudo` approval on the phone: enable it now on p620 (`approve.services = [ "sudo" ]`), or later? This
  draft leaves it off.
- The Home Manager module also installs the Omarchy shell plugin and the browser extension. Use it instead of, or
  besides, the NixOS module? This draft uses the NixOS module only.
