# Intent: stop evaluation from building the omarchy package

## Problem

`modules/desktop/stylix-theme.nix:66-70` runs `builtins.pathExists` and `builtins.readFile` on a path inside
`inputs.nixarchy.packages.<system>.omarchy`, and `home/shell/fastfetch/default.nix:40` reads its fastfetch config
from the same package. That is import-from-derivation: every evaluation of every host has to build or download the
omarchy package before it can continue. `docs/NIXOS-ANTI-PATTERNS.md:72` and its checklist (:932) forbid it.

## Proposed outcome

Evaluating p620, razer and p510 no longer realises the omarchy package. The Stylix palette and the fastfetch
config are byte-for-byte what they are today.

## Affected users and systems

All three hosts (Stylix is fleet-wide; fastfetch is in Home Manager for `olafkfreund`).

## Constraints

- Identical results: same `stylix.base16Scheme`, same `programs.fastfetch.settings`, same closures.
- The package patches its copy: fastfetch's version line says `Nixarchy (Omarchy $version)` (nixarchy
  `pkgs/omarchy/default.nix:659`), and `osaka-jade` is added from a separate fetch. Both must survive.

None.
