# Intent: the guards catch every disruptive Justfile recipe

## Problem

Three hooks protect shared hosts by matching command text:

- the bus-announce hook (`busAnnounceScript`, `modules/programs/claude-code-managed.nix` ~534): Claude must announce
  on `#agents` before a deploy, GC, restart or reboot (`AGENT_BUS_ANNOUNCED=1`, self-asserted after posting);
- the p510 deploy guard (`deployGuardScript`, same file ~355): anything that changes p510 needs the owner's OK
  (`P510_DEPLOY_APPROVED=1`);
- the coder guard (`modules/programs/claude-coder-guard.sh`, `just)` case ~69): delegated coders (Codex, agy, the
  `coder` agent) may not run host-changing or history-changing commands at all.

For `just`, they match only recipe names containing `deploy` or equal to a host name. Recipes left after the Justfile
cleanup (#2950) change state under other names and pass all three:

| Recipe | Effect | Missed by |
|---|---|---|
| `gc` | `nix-collect-garbage --delete-old` | bus, coder |
| `cleanup` | `nix-collect-garbage` plus `nix store optimise` | bus, coder |
| `boot-space-clean HOST` | when `/boot` is short: prunes system generations and runs `switch-to-configuration boot` | bus, coder, p510 |
| `fix-agenix-remote HOST` | stops agenix and deletes `/run/agenix.d` on a host | bus, coder, p510 |
| `p510-clear-sessions` | ends user sessions on p510, including other agents' SSH jobs | bus, coder, p510 |
| `update` | meant to update inputs and switch; its body `nh os update` fails on nh 4.4.2 | bus, coder |
| `update-commit` | commits, pushes and opens a PR (no switch) | coder |
| `build-on-p620`, `_sign-drv` | sign derivations with p620's root signing key | coder |

The bus hook has no test at all (Codex and agy reviews), so none of this would have been caught.

## Proposed outcome

- The bus hook demands an announcement for `gc`, `cleanup`, `boot-space-clean`, `fix-agenix-remote`,
  `p510-clear-sessions` and `update`.
- The p510 guard also covers `p510-clear-sessions` and the two host-argument recipes when the host is p510.
- The coder guard blocks all of the table's recipes, including `update-commit`, `build-on-p620` and `_sign-drv`, and
  judges the recipe correctly after `VAR=value` overrides and `--justfile`/`-f`/`-d` options.
- `just update` works again (`nh os switch --update`), so the guarded recipe does what its name says.
- Non-disruptive recipes (inspection, builds, format/lint, docs) stay allowed for the bus hook.
- Tests: the bus hook gets an offline test like the p510 one, run by `just test-guards`. All three guards get cases
  for every new name, for the allowed neighbours (`boot-space`, `update-commit` for the bus hook, `check-updates`), and
  for `VAR=value` and `--justfile` forms.

## Affected users and systems

- Claude Code sessions and delegated coders on p620, razer and p510 (managed settings, `/etc/codex` and
  `/etc/antigravity` hook copies).
- The owner typing these recipes in a shell is unaffected; the hooks run only inside agent tool calls.

## Constraints

- No recipe is added or removed. Only `update`'s body changes, to the nh 4 spelling of what it already meant.
- Text matching stays cheap: no `just --show` expansion in a hook.
- Accepted false positives: the bus hook may also match the words "just update" in a quoted string; agents already
  write prose to files because of this.
- Deploying this changes managed Claude settings on every host. p620 and razer now; p510 only with the owner's OK.
