# Intent: the guards catch every disruptive Justfile recipe

## Problem

Two hooks protect shared hosts by matching command text:

- the bus-announce hook in `modules/programs/claude-code-managed.nix` (`disruptive`, ~line 534): Claude must
  announce on `#agents` before a deploy, GC, restart or reboot;
- the coder guard `modules/programs/claude-coder-guard.sh` (`just)` case, ~line 69): delegated coders (Codex, agy,
  the `coder` agent) may not run them at all.

For `just`, both match only recipe names that contain `deploy` or equal a host name. Six of the 44 recipes left after
# 2950 change a host's state under other names, and neither guard sees them:

| Recipe | Effect |
|---|---|
| `update` | `nh os update`: updates inputs and switches the local host |
| `gc` | `nix-collect-garbage --delete-old` |
| `cleanup` | `nix-collect-garbage --delete-older-than` plus `nix store optimise` |
| `boot-space-clean` | deletes old boot entries on a host |
| `fix-agenix-remote` | stops agenix and deletes `/run/agenix.d` on a remote host |
| `p510-clear-sessions` | ends user sessions on p510 |

Typing `nix-collect-garbage` is blocked until announced, but typing `just gc` is not. A coder that may not switch a
host can still run `just update`.

## Proposed outcome

- Both guards treat these six recipes like the deploy recipes: the bus hook demands the announcement, and the coder
  guard blocks them.
- Read-only recipes stay unblocked (`status`, `boot-space`, `boot-space-all`, `ping-hosts`, `test-*`, `check-*`,
  `validate*`, `diff`, `dry-run`, `secrets-status*`, `docs-*`, `format`, `lint-all`).
- The guard tests cover each new name, blocked and announced, and a read-only neighbour (`boot-space` beside
  `boot-space-clean`).

## Affected users and systems

- Claude Code sessions on p620, razer and p510 (managed settings hook), and delegated coders (coder guard, agy
  adapter).
- The owner typing these recipes in a shell is unaffected: the hooks run only inside agent tool calls.

## Constraints

- No change to which recipes exist or what they do.
- Keep matching cheap and text-based: no `just --show` expansion inside the hook.
- `update-commit` (flake update, build, commit, push, no switch) and `build-on-p620` (build only) stay allowed: they
  do not disrupt a host. `update-commit` pushes, but pushing is outside these two guards.
- Deploying this changes the managed Claude settings on every host. Ship it with a normal deploy; p510 only with the
  owner's OK.

## Open questions

1. Should `update-commit` also need an announcement, since it runs a long build that loads p620? Recommendation: no.
   Builds are not on the bus list today (`nix build` is deliberately absent).
2. Match these six by exact name (simple, must be kept in sync with the Justfile) or by a name rule? There is no
   clean rule: `gc`, `update` and `cleanup` share nothing. Recommendation: exact names, plus a comment in the
   Justfile beside each recipe pointing at the guards.
