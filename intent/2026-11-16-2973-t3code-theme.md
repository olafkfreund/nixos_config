# Intent: T3 Code follows the Omarchy theme declaratively

## Problem

T3 Code is enabled on p620 with `programs.nixarchy.apps.t3-code.enable`. It
does not follow the desktop theme on a fresh NixOS host.

On Arch, Omarchy's installer `omarchy-install-ai-t3-code` does three things
after installing the app:

1. creates `~/.t3/userdata`;
2. publishes the current palette with `omarchy-theme-set-t3code`, which writes
   `~/.t3/userdata/themes/omarchy.json`;
3. selects that theme with `t3 theme set omarchy`, which writes
   `defaultTheme` to `~/.t3/userdata/settings.json`.

On NixOS the app comes from the apps option, so none of these steps run.
`omarchy-theme-set` calls `omarchy-theme-set-t3code` on every theme switch,
but that script exits early when `~/.t3/userdata` does not exist. Even once
the palette is written, nothing selects it.

On p620 (2026-11-16) the state folder was created when the app first ran,
after the last theme switch. The palette was never written and the app stayed
on its built-in theme. It was fixed by hand there. Razer, p510 and any
reinstall would hit the same problem.

## Proposed outcome

On every host where `programs.nixarchy.apps.t3-code.enable` is true:

- after a `nixos-rebuild switch`, `~/.t3/userdata/themes/omarchy.json` holds
  the current Omarchy palette and T3 Code's selected theme is `omarchy`;
- later theme switches recolour T3 Code live, through Omarchy's existing hook,
  with no manual step;
- hosts without T3 Code are unchanged.

## Affected users and systems

- `olafkfreund` on p620, where the app is enabled today.
- Razer and p510 only if `t3-code` is enabled there later. The change is
  inert while the option is off.
- Files: one shared module under `hosts/common/nixos/`. All three hosts import
  it through their `nixarchy.nix`.

## Constraints

- No change to T3 Code settings other than `defaultTheme`. `settings.json` is
  app-owned state: never overwrite it as a whole file.
- Activation must not fail a switch if T3 Code's CLI or the palette file is
  missing.
- Must not re-run `t3 theme set` on every switch when the theme is already
  `omarchy`. That command rewrites `defaultThemeSetAt` and notifies running
  clients.
- p510 builds need the owner's OK, and nothing changes there until the option
  is enabled.

## Open questions

1. Should the config force `omarchy` back on every switch, overriding a theme
   picked in the app? Proposed: yes, because declarative means the config
   wins. The alternative is to set it only once, when no theme has been
   chosen.
2. Should this go in this repo, or upstream in nixarchy's apps module so every
   Nixarchy user gets it? Proposed: this repo now, as asked, with a follow-up
   upstream issue.
