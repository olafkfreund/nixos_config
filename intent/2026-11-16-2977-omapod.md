# Intent: omaPOD on p620 and razer

## Problem

omaPOD (podcast app plus Omarchy bar widget) now ships a Nix flake with a
package, a NixOS module and a Home Manager module
(olafkfreund/nixarchy-omapod#1, merged 2026-11-16, VM test and CI green). None
of it is on any of our hosts, so it has only been tested in a VM. The owner
wants to test it live on p620 and razer.

## Proposed outcome

After a deploy of p620 and razer, for `olafkfreund`:

- `omapod` runs and is in the app launcher; `podcast://`, `itpc://`,
  `pcast://`, `antennapod-subscribe://` links and OPML files open it.
- The bar widget is installed and turned on once per host, like Altscape.
- `Super+Ctrl+Shift` + K / comma / period / N / O control playback (toggle,
  rewind, forward, skip, show), loaded from a Nix-owned
  `~/.config/hypr/omapod-binds.lua`; media keys work through MPRIS.
- An hourly background refresh runs while omaPOD is closed.
- Nothing is imported or synced automatically. Neither host has an omaPOD
  library today (razer: no omaPOD paths; p620: only an empty
  `~/.local/share/omapod/run` from test runs); any data that exists by then is
  kept.

## Affected users and systems

- Hosts p620 and razer, user `olafkfreund`. Not p510.
- `flake.nix` / `flake.lock` (new input `omapod`), a new
  `hosts/common/nixos/omarchy-omapod.nix`, and one import line in each of
  `hosts/p620/nixos/nixarchy.nix` and `hosts/razer/nixos/nixarchy.nix`.
- Shared files the change writes into at activation: `~/.config/hypr/bindings.lua`
  (one appended `pcall(require, …)` line, as Altscape does).

## Constraints

- Follow the existing Omarchy plugin pattern (`omarchy-altscape.nix`):
  plugin through `programs.nixarchy.plugins.<id>.src`, enabled once with
  `local.omarchy.enableOnce`, binds file plus an append-only require line.
  So omaPOD's own `widget.enable` stays off here (it would write the same
  folder).
- The input follows our `nixpkgs` and `home-manager`.
- Keybindings must not clash with existing binds on either host (checked on
  p620 with `omarchy menu keybindings --print`, on razer from its
  `~/.config/hypr/*.lua`: `Super+Ctrl+Shift` K, O, N, comma, period are free
  on both).
- Build both hosts before deploying; razer builds on p620
  (`just deploy-via-p620 razer`). Merge the PR, then go live from `main` (the
  normal path; `ALLOW_BRANCH_DEPLOY=1` is not needed). Announce on the agent
  bus first.
- The two units omaPOD adds (`omapod-refresh`, hourly; `omapod-settings`, at
  login and rebuild) are Home Manager **user** units that must read and write
  `~/.local/share/omapod` and `~/.config/omapod`. AGENTS.md rule 2
  (`DynamicUser`, `ProtectHome`, `ProtectSystem = "strict"`,
  `NoNewPrivileges`) is written for system services and cannot hold as-is for
  them: `DynamicUser` does not exist in a user manager and `ProtectHome` would
  hide the very data they manage. They need a documented exception like Flux's
  `fluxd` user unit (`docs/applications/flux.md`), keeping whatever hardening a
  user unit can carry.
- No secrets: omaPOD's sync login and API keys stay in the app.

## Open questions

1. **Hardening exception.** Accept the user-unit exception above, documented
   in a new `docs/applications/omapod.md` and in AGENTS.md's exception list
   like Flux? Recommendation: yes.
2. **Refresh timer on razer** (a laptop): hourly like p620, or off on razer?
   omaPOD's `--refresh` already skips auto-downloads on battery by default.
   Recommendation: on for both.
