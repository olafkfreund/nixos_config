# Intent: p620 k3d factory cluster on Kubernetes 1.35

## Problem

The p620 k3d `factory` cluster runs k3s v1.31.5 (`modules.containers.k3d.k3sImage` default
`rancher/k3s:v1.31.5-k3s1`), which is end of life. RFactory #3 runs its agent desktops as KubeVirt VMIs on this
cluster, and no maintained KubeVirt (1.7 to 1.9) supports Kubernetes 1.31. RFactory is blocked on this now.

## Proposed outcome

- The cluster runs k3s **v1.35.10-k3s1**. Kubernetes 1.35 is the only version both KubeVirt 1.8 and 1.9
  support (kubevirt/sig-release `k8s-support-matrix.md`, checked 2026-11-18).
- Both nodes (`k3d-factory-server-0`, `k3d-factory-agent-0`) stay privileged and see `/dev/kvm`.
- All 43 ArgoCD apps come back Synced/Healthy, and the 16 Bound PVs come back with their data.

## Affected users and systems

- p620 only; every Factory service on the cluster is down during the recreate (roughly 15 to 30 minutes,
  plus image pulls).
- `modules/containers/k3d.nix` (image default, the sqlite datastore DSN), `hosts/p620/configuration.nix`
  (if the image is set per host), `docs/applications/k3d-cluster.md`.

## Constraints

- k3d does not upgrade nodes in place, so this is a recreate: stop the bootstrap unit, `k3d cluster delete
  factory`, deploy, let the bootstrap create the cluster. **Storage under `/mnt/code/k3d/storage` is kept**; the
  docs' "Full reset" (`rm -rf` storage) must not be used.
- Data comes back through the existing paths: the PV snapshot `/var/lib/k3d-factory/pv-snapshot.json` (taken on
  every bootstrap run, last 2026-11-18 09:18) restored pre-bound before any PVC (#1497), the agenix Secret seed,
  and ArgoCD from `factory-gitops`. Before the delete: fresh keycloak and skillai backups and a dated copy of the
  snapshot, as in the 2026-10-22 recreate (#2438).
- The `--datastore-endpoint` DSN is copied from the k3s binary's default plus `_auto_vacuum=full` (#2676).
  The 1.35 default changed: `_journal_mode=WAL&_busy_timeout=30000&_synchronous=NORMAL&_txlock=immediate&_stmt_cache_size=20&cache=shared`
  (read from the v1.35.10 binary); 1.31 used `_journal=WAL&cache=shared&_busy_timeout=30000&_txlock=immediate`.
- Checked compatibility: Docker uses cgroup v2 (1.35 drops cgroup v1); k3d is 5.9.0; no deprecated API was
  requested in the 26 days since the API server started (`apiserver_requested_deprecated_apis` empty).
- Announce on the agent bus before the delete. p510 is not involved.

## Open questions

1. Window: recreate **now** (recommended: RFactory needs it, and the bootstrap restores PVs and Secrets), or at
   a time you choose?
2. ArgoCD v2.13.1 is itself out of support and untested on 1.35 (Kyverno 1.18.2 and KEDA 2.20.1 are recent;
   the spec checks their support matrices).
   Keep it and check it after the recreate (recommended, smallest change), or upgrade ArgoCD first in
   `factory-gitops` (a separate repo and task)?
3. Set the image in the module default (recommended: one cluster uses it) or as a p620 host setting?
