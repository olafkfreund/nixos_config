# Intent: faster Omarchy shell startup (keepLoaded, app-dir rescans, dead bar keys)

## Problem

On p620 the desktop (shell, top bar and wallpaper) appears about 9.5 s after
login (journal and shell log, login of 2026-11-17 15:44:31). Hyprland is up in
under a second; the shell starts 2 s after login. The rest is the shell
loading plugins: `BackgroundIntro.qml` keeps a cover over every screen until
`desktopReady` (no plugin reload or registry scan in flight, bar present) and
the background service is ready, then fades for 420 ms. Anything the shell
loads before that point delays the whole desktop.

Three causes in that window are in scope here:

1. **keepLoaded panels.** 21 installed plugins set `"keepLoaded": true`, so
   their panel, overlay or menu is built at startup instead of when first
   opened. Most come from our own repos.
2. **Application-folder rescans.** The shell watches
   `~/.local/share/applications` and rescans all ~650 desktop entries on any
   change. Two plugins change that folder at every shell start even when
   nothing differs: hyprforge (`nixarchy.hyprlandsettings`) creates and
   removes a temp file there, and omamail rewrites `omamail.desktop` and runs
   `update-desktop-database`. The rescan at 15:44:37 landed in the middle of
   plugin loading, on the shell's single QML thread.
3. **Dead bar settings.** `~/.config/omarchy/shell.json` carries per-entry
   `"hidden": "hover"|"always"` keys and `bar.hiddenRevealByRegion` /
   `bar.revealIcons`, apparently left from the skal.bar era. The stock bar
   reads none of them, so they suggest icons are hidden when they are not.

## Proposed outcome

- Our own plugins load their panels on first use, except where a keybind,
  external caller or always-on behaviour needs them loaded; each exception is
  named with its reason.
- A shell start no longer modifies `~/.local/share/applications` when the
  desktop files it manages are already current, so login has no desktop-entry
  rescan from these plugins.
- `shell.json` on p620 and razer holds no keys the shell does not read.
- The next login on p620 is measured against the 9.5 s baseline and the
  result reported.

## Affected users and systems

- Hosts: p620 and razer (both run the Omarchy desktop). p510 also runs it but
  is not built or deployed without the owner's OK.
- Repos (own): olafkfreund/nixarchy (hyprforge, rebuild panel), and
  nixarchy-devenv, -distrobox, -flatsnap, -ghtui, -gltui, -herdr, -microvm,
  -pkg, -podman, -winvm, ai-mirror, nixi-nixarchy where the audit allows.
- Repo (third-party): huacnlee/omamail.
- This repo: flake input bumps once the plugin repos are released; any
  runtime cleanup of `shell.json`.

## Constraints

- No keybind, voice command, menu row or notification may stop working. A
  plugin whose own IPC target is called directly stays keepLoaded unless the
  caller moves to `omarchy-shell shell toggle|show <id>` in the same change.
- Third-party plugins (expose, flux, omarecorder, voxtype-osd, vimarchy,
  omarchroma) are not patched for item 1 (owner decision, 2026-11-19).
- `shell.json` is runtime state the shell rewrites from memory: edit it only
  through a path the shell honours, never a blind file write.
- Agent-bus announcement before any switch or shell restart; p510 untouched.
- Plugin repo changes go through PRs; nixarchy's own CI and conventions apply.
