# Intent: graphify knowledge graph for Claude Code, Codex and Antigravity

## Problem

Agents answer architecture questions ("what calls X", "how does A reach B")
by grepping and reading files one by one. graphify
(Graphify-Labs/graphify, nixpkgs `graphify`) builds a local tree-sitter graph
of a repo and answers those questions with `query`/`path`/`explain`, but
nothing installs it or tells the agents about it.

## Proposed outcome

On p620 and razer:

- `graphify` is on PATH.
- Claude Code, Codex and agy see a `graphify` skill (`/graphify`, `$graphify`).
- All three have a `graphify` MCP server that answers graph queries for any
  project that has a `graphify-out/graph.json`.
- p510 is unchanged.

## Affected users and systems

olafkfreund on p620, then razer once verified. Home Manager modules
under `home/development/` (skills, Claude MCP, Antigravity MCP, Codex).

## Constraints

- Subscription only (#1831): no API-key LLM backends. Default to a code-only
  graph (`GRAPHIFY_BACKEND=none`); the skill's semantic pass uses the agent's
  own session model.
- No always-on PreToolUse hooks or `--strict` mode: they would fight the
  existing guard hooks and llm-index/semble.
- Don't run `graphify install`: it writes mutable files into the
  Syncthing-synced `~/.claude`. Link the skill declaratively from the store.
- p510 is never built or rolled out without asking. Leave it out.
- Generated `graphify-out/` must never be committed.

## Open questions

None. The owner approved the recommendation and asked for the MCP server too.
