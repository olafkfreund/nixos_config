# Intent: agy guard probe proves the guard with calls agy will make

## Problem

`agy-implement` starts agy with write access only after `agy-guard-probe`
has passed for that agy version (`home/development/antigravity-config.nix`).
For agy 1.5.14 the probe fails its `acp` check, so `agy-implement` refuses to
start. Every plan step routed to agy since then has fallen back to the lead.

The probe report has the `-p` guard log, but nothing from the ACP session.
In the ACP turn agy refused `git commit -am x` and `touch ~/.gemini/probe`
itself: "I must enforce these rules directly rather than relying on an
external guard". That explains the missing commit-deny line. The single
`FAIL acp` does not show which of its four checks failed, though: turn
count, word recall, unchanged HEAD, or the deny line.

A harmless ACP session on 2026-11-23, run through the same wrapper on p620,
logged:

```text
edit_file allow
write_file deny agy-implement may only write inside /tmp/... (#2296)
```

So in ACP mode the hook runs for file tools, allows an edit inside the
workspace and denies a write outside it. That run did not exercise
`run_command`.

The probe fails because it depends on agy attempting commands that agy now
refuses on its own. The `-p` half does the same, so a later agy can fail it
the same way.

## Proposed outcome

- `agy-guard-probe` passes for agy 1.5.14 on p620. `agy-implement` starts
  again, and plan steps routed to agy run through agy.
- In both the `-p` and the ACP mode, the probe proves with live calls:
  - **file tools:**
    - an edit inside the workspace is allowed and lands, with the exact
      content expected;
    - a write outside the workspace is denied and has no effect;
  - **`run_command`:**
    - a harmless command is allowed;
    - a command the coder guard blocks is denied and has no effect. It is a
      guarded git command that only touches the throwaway repo and that agy
      will attempt (candidates: `git restore`, `git stash`,
      `git branch -d`);
  - each line is matched on the guard's reason, so a generic deny or a
    renamed tool does not pass (#2452).
- **ACP keeps its session checks:** two turn files, and the word from turn
  one recalled in turn two.
- **Self-refusal never counts as a pass.** If agy declines to make one of
  these calls, that mode fails with its own named sub-check. A refusal looks
  the same as a hook that is not wired. Probe actions are chosen so this does
  not happen in normal runs.
- **The report names every sub-check per mode,** for example
  `acp-turns`, `acp-recall`, `acp-run-deny`, `p-write-deny`, and includes
  the ACP log and the exit status of each mode.
- The other per-rule checks (`~/.gemini`, `.envrc`, hard links, path forms)
  stay in the unit test `modules/programs/agy-guard-adapter.test.sh`. They go
  through the same payload fields that the live calls prove.

## Affected users and systems

- `home/development/antigravity-config.nix`:
  - `agyGuardProbe`;
  - `agyImplement`, where the probe cache key is checked and written (lines
    173, 179, 186) along with the probe's write (296).
- p620 and razer, the hosts with agy. Whether p510 enables
  `programs.antigravityConfig` gets checked in the spec.
- The cache `~/.cache/agy-implement/probed`. Its key moves from `acp1` to
  `acp2`, so every host runs the new probe once.
- `modules/programs/agy-guard-adapter.sh` only if a sub-check needs a log
  detail that the adapter does not record today. The guard's rules do not
  change.

## Constraints

- Do not weaken the guard or its rules. Do not add a probe-only deny rule:
  the probe must exercise the real rules.
- The probe must still fail if:
  - a mode's hook is not called;
  - a tool or its argument field was renamed;
  - a denied call changed disk or git;
  - an allowed edit did not land.
- Probe targets and cleanup stay inside its own temporary directories.
  Today the probe targets `$HOME/.gemini/probe` and deletes it on exit even
  if it existed before. That stops, and the `~/.gemini` rule stays covered
  by the unit test.
- agy runs without a sandbox by owner decision (#2812), so all the probe's
  actions are harmless outside the temp repo.
- Subscription login only (#1831).

## Open questions

- **Which guarded git command agy attempts reliably.** The spec checks the
  candidates live with agy 1.5.14 in both modes before choosing.
  Recommendation: the one agy attempts in both modes, with a second one as
  a fallback that the probe tries if the first is declined.
- **Whether one live run is enough evidence against model nondeterminism.**
  Recommendation: the spec runs the new probe three times before it is
  accepted.
