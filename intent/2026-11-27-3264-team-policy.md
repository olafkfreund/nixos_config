# Intent: Provider-neutral team policy, 2 reviews per task

## Problem

- The managed CLAUDE.md's "Model split (Claude Code only)" section holds
  the whole team policy, and `home/development/agent-rules.nix` cuts it
  out of the AGENTS.md files Codex and agy read. A session led from Codex
  or agy does not know the roles, the routing or the review rules.
- The model names in `agent-rules/codex-standards.md` and
  `agent-rules/agy-standards.md` are hand-written and already stale
  (`gpt-6-astra`), and the second-opinion skill runs reviews on whatever
  model each tool defaults to.
- With `agent-team: on`, every task gets five extra reviews (two on the
  plan, three on the diff). That is the biggest token and time cost in the
  workflow.

## Proposed outcome

- One "Team policy" section, with the role/model table from
  `modules/programs/agent-team.nix`, reaches Claude Code, Codex and agy.
  Claude-only mechanics (the `coder` agent, SendMessage) stay Claude-only.
- Default reviews drop to two per task: one plan review (Codex, or agy when
  Codex leads) and one diff review by a provider other than the one that
  implemented. A plan's `reviewers:` or the user can still ask for more.
- Reviews started by the second-opinion skill run on the reviewer model.

## Affected users and systems

Claude Code (managed CLAUDE.md), Codex and agy (AGENTS.md), the
second-opinion and handoff skills; p620, razer, and p510 (rule text only).

## Constraints

- Codex caps AGENTS.md at 32 KiB.
- Owner decision 2026-11-27: two reviews per task by default.
- Rule text only on p510; no p510 build or deploy.
