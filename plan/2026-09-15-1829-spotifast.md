# Plan: Spotifast native Spotify client on p620 and razer

Summary of the approved decisions:

- Install Spotifast (`github:crmne/spotifast`, MIT) on **razer and p620
  only**. p510 is not built, deployed or evaluated.
- Install only. No configuration, module or secret. Sign-in happens in the app.
  The GNOME `spotify-controller` extension and `mpris-album-art` are left
  unchanged.
- Wire it the same way as herdr: a flake input that follows our `nixpkgs` and
  `rust-overlay`, an overlay attribute `pkgs.spotifast`, and an entry in
  `Users/olafkfreund/profile.nix`. Only `p620_home.nix` and `razer_home.nix`
  import that file.
- The upstream `packages.default` ships `spotifast.desktop`, so it appears in
  the launcher with no extra code.
- It builds from source because no cache has it. Razer builds on p620.

## Steps

1. `flake.nix`: add the `spotifast` input after the `herdr` block, with
   `inputs.nixpkgs.follows = "nixpkgs"` and
   `inputs.rust-overlay.follows = "rust-overlay"`. Then run
   `nix flake lock --update-input spotifast`, or
   `nix flake update spotifast`, which adds only that node.
   → verify: `git diff flake.lock` adds only `spotifast`, and
   `nix flake metadata --json | jq '.locks.nodes.spotifast.inputs'` shows
   both inputs following ours.
2. `overlays/default.nix`: after the `herdr` line, add
   `spotifast = inputs.spotifast.packages.${prev.stdenv.hostPlatform.system}.default;`.
   → verify: `nix eval .#nixosConfigurations.p620.pkgs.spotifast.name`
   returns a spotifast name.
3. `Users/olafkfreund/profile.nix`: add `pkgs.spotifast` after `pkgs.herdr`.
   → verify: step 4's build contains it.
4. Build p620, which also warms the store for razer: `just test-host p620`.
   → verify: the build succeeds, and the built `spotifast` output contains
   `bin/spotifast` and `share/applications/spotifast.desktop`.
5. Build razer: `just test-host razer`. It reuses the store paths p620 just
   built.
   → verify: the build succeeds.
6. Commit the code as
   `feat(apps): add Spotifast to p620 and razer (#1829)`, push, and open a PR
   that links the intent, spec and plan.

Deployment is the user's decision after merge: `just p620`, and
`just deploy-via-p620 razer` for razer. Deploys are announced on the agent bus
first, as the repo rules require.

## Tests

- `nix flake metadata`: exactly one `nixpkgs` node is still locked.
- `just test-host p620` and `just test-host razer`: both exit 0.
- `grep -n profile.nix Users/olafkfreund/*_home.nix`: only `p620_home.nix` and
  `razer_home.nix`. This is the static p510 exclusion check, with no p510
  evaluation.
- After the user deploys, `spotifast` launches and appears in the launcher.

## Rollback

- Before merge: close the PR and delete the branch.
- After merge: revert the code commit. That removes the input, the overlay
  line, the `profile.nix` entry and the lock node. Redeploy p620 and razer.
  If a deployed host misbehaves, roll back with
  `sudo nixos-rebuild switch --rollback`.

## Deviation: rust-overlay toolchain

If step 1 or step 4 fails because our `rust-overlay` is too old for upstream's
`rust-toolchain.toml`, stop and ask before bumping `rust-overlay`. That bump
also affects herdr. Record the decision in this file.
