# Plan: Remove zellij and tmate

Approved decisions, carried over from the spec:

- Remove zellij at every layer: the Home Manager module, the feature flag
  and every place that sets it, the `zjstatus` flake input and overlay,
  bare packages, docs and tool config.
- Removing the option is the completeness check. Any setting that is
  missed becomes an evaluation error.
- `flake.lock` is pruned with `nix flake lock`, never `nix flake update`.
  Only `zjstatus` and the nodes only it uses go (`crane_2`,
  `flake-utils_7` and its `systems` node, `nixpkgs_12`, `rust-overlay_5`),
  and no other rev moves.
- tmux, herdr and tuios are untouched.
- The unimported `hosts/{p620,razer}/home-manager-options.nix` files lose
  only their zellij lines. They are not deleted.
- The Roadmap entry `Modern Zellij multiplexer setup` is removed, not
  unchecked.
- No manual cleanup on the hosts: Home Manager removes the aliases and
  `~/.config/zellij/layouts/*.kdl` at the next activation.
- p510 is evaluated here and deployed only when the user asks.
- tmate is already gone (#1950). This task confirms nothing reintroduces
  it.

## Rollback

The change is one squash commit. `git revert <sha>` restores the module,
the flag, the `zjstatus` input and its lock nodes exactly. `flake.lock` is
part of the commit, so the revert restores the same revs. A host that was
already deployed gets zellij back at its next rebuild. Only Home
Manager-owned files were ever involved, so nothing on the hosts needs
restoring by hand.
