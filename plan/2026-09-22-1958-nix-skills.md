# Plan: Install nix-skills on every host

Approved decisions, carried over from the spec:

- New flake input `nix-skills` (`github:olafkfreund/nix-skills`) that
  follows our `nixpkgs` and `home-manager`. It sits next to
  `claude-skills-borghei` in `flake.nix`.
- In `home/development/claude-code-skills/default.nix`: import
  `inputs.nix-skills.homeManagerModules.default` at the top level, and
  inside the existing `mkIf cfg.enable` set `programs.nix-skills` to
  `enable = true`, `agents = [ "claude" "codex" "antigravity" ]` and
  `skills = [ "nix-language" "nixpkgs-development" "microvm-nix" "home-manager" ]`.
  A comment explains why `devenv-project` and `nixos-wiki` are left out,
  and that Gemini CLI's `~/.gemini/skills` is not covered.
- Result: 12 links on each of p620, razer and p510 (4 skills × 3
  directories).
- In `home/syncthing-stignore.nix`: `managedSkillIgnores` takes
  `folder: subdir:`. `.claude` calls it with `"skills"`. `.gemini` calls it
  with `"skills"` and with `"config/skills"`. This closes the gap where
  Antigravity links under the synced `!config/**` would replicate and
  dangle. The exclusions stay derived from `home.file`.
- The lock changes only by adding nix-skills; no other input moves.
- Deploy order: p620 (local), then razer (via p620), then p510 with the
  user's go-ahead (given), handed to the user if the guard blocks it.

## Rollback

`git revert` the squash commit and redeploy. Home Manager removes the 12
links at the next activation, and the stignore returns to its previous
text. The links are Home Manager-owned, so nothing on the hosts needs
cleaning by hand. If a link did replicate before the stignore reached
another host, deleting that dangling link there is enough.
