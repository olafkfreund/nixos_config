# Plan: gliff remote desktop on razer and p510

Approved decisions (from the spec):

- **razer:** gliff-server defaults to `/dev/dri/renderD128` (NVIDIA), but
  Hyprland renders on the Intel iGPU. Upstream gliff reads
  `GLIFF_RENDER_NODE` (after `--render-node`, before the default), so razer
  sets it system-wide to the PCI-stable link
  `/dev/dri/by-path/pci-0000:00:02.0-render` (i915). Don't use a wrapper
  script or hard-code `renderD129`.
- **p510:** keep `programs.nixarchy.preinstalls = false`. Add only
  `inputs.nixarchy.packages.<system>.gliff`, the same derivation the other
  hosts get (`gliff-0.3.1`, `bnq9y2x4…`). There is no render-node setting
  (single GPU). It stays broken (`gbm: map`) until upstream supports NVIDIA
  capture, and that is accepted.
- **Upstream:** one issue on omacom/gliff for both bugs.

Two files and two code steps, below the coder handoff threshold, so the
session model implements it.

## Steps

1. `hosts/razer/nixos/nixarchy.nix`, after the `environment.systemPackages
   = [ pkgs.psmisc ];` line (line 74): add a short comment and
   `environment.variables.GLIFF_RENDER_NODE =
   "/dev/dri/by-path/pci-0000:00:02.0-render";`
   → verify with `nix eval --raw
   .#nixosConfigurations.razer.config.environment.variables.GLIFF_RENDER_NODE`.
   Traps: keep the comment short (minimal-comments rule). Don't touch
   `preinstallsExclude`.
2. `hosts/p510/nixos/nixarchy.nix`, after `programs.nixarchy.preinstalls =
   false;` (line 103): add a short comment and
   `environment.systemPackages = [
   inputs.nixarchy.packages.${pkgs.stdenv.hostPlatform.system}.gliff ];`
   → verify with `nix eval --json
   .#nixosConfigurations.p510.config.environment.systemPackages --apply 'ps:
   builtins.filter (n: builtins.match ".*gliff.*" n != null) (map (p:
   p.name or "") ps)'`, which should print `["gliff-0.3.1"]`.
   Traps: `inputs` and `pkgs` are already arguments of this file. Don't
   flip `preinstalls`.
3. Build both: `just test-host razer` and `just test-host p510` (build only,
   no switch).
   Traps: building p510's closure locally on p620 is fine. Deploying p510
   needs the user's explicit go-ahead. razer deploys via
   `just deploy-via-p620 razer`, and only from main after merge (deploy
   recipes refuse other branches). Announce on the agent bus first
   (AGENTS.md rule 6).
4. Open a PR linking the intent, spec and plan, plus #2251. Commit
   messages go through `-F -` heredocs, with no backticks (memory rule).
   Line-initial issue refs are written as "Issue #N".
5. File the upstream issue on omacom/gliff (body via `--body-file`) and
   link it from #2251.
6. After merge, with the user's go-ahead per host: deploy razer, then run
   the runtime check below. Deploy p510 only if the user asks.
