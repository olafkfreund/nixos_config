# Plan: register the Craft apps' MCP servers with Claude Code

## Approved decisions (self-contained)

- **Pin.** Bump only the `nix-craftapps` flake input, from `143197e` to
  current `main` (`edf59f8` or later). That release adds
  `programs.craftapps.mcp.enable`. It defines one server per enabled
  app as `programs.craftapps.mcp.servers.<app> = { command = "<store>/bin/<app>-cli"; args = [ "mcp" … ]; }`,
  and vectorcraft gets `--headless`.
- **New switch.** `features.craftapps.mcp`: bool, default `true`, which
  sets `programs.craftapps.mcp.enable`.
- **Claude Code integration.** Merge
  `osConfig.programs.craftapps.mcp.servers`, each entry plus
  `type = "stdio"`, into the `mcpServers` map of
  `home.activation.claudeSharedMcpServers`. That activation reconciles
  `~/.claude.json` on every activation (jq `+`: declared servers are
  replaced whole, undeclared ones untouched). Use `or { }` so a host
  without the module still evaluates.
- **Claude Code only.**
  - Never touch `/etc/claude-code/managed-mcp.json`.
  - Don't enable Home Manager's `programs.claude-code`.
  - Don't put the servers in the seed template, which is never re-read
    (issue 1933).
- **Removals are not reconciled.** The comment says so, and
  `claude mcp remove <app>` cleans up.
- **No new flake check.** Verify by eval, by build and on the live host.

## Steps

All edits happen in the worktree `~/.config/nixos-2348`, branch
`feat/2348-craftapps-mcp`. Never edit `/etc/nixos` (`~/.config/nixos`).
It stays on `main` (#2052).

## Rollback

- **Revert the change.** Revert the squash commit and redeploy, or set
  `features.craftapps.mcp = false` on a host.
- **Clean up `~/.claude.json` by hand.** Because removals are not
  reconciled, remove the entries after the rollback:

  ```bash
  for a in cadcraft deckcraft designcraft effectcraft filmcraft gridcraft lightcraft pdfcraft photocraft soundcraft vectorcraft wordcraft; do claude mcp remove "$a"; done
  ```

- **Back out the app updates too.** The app versions roll back with
  `flake.lock`.
