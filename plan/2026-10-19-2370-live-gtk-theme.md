# Plan: live theme switch reaches GTK apps

Approved decisions, carried over from the spec so that this file is enough
on its own:

- **Problem.** `omarchy theme set X` writes the live palette into
  `~/.config/gtk-{3,4}.0/hyprchroma.css` and `kdeglobals` (the theme
  engine, hyprchroma). Stylix's Home Manager targets put the palette baked
  in at the last rebuild back on top of it:
  - `gtk`: 88 `@define-color` rules in `gtk.css`, below the import, so they
    win. Also `Papirus-Dark` in `settings.ini`.
  - `gnome`: dconf `icon-theme` and `accent-color`.
  - `kde`: `kdeglobals`.
- **D1.** Turn off the Home Manager Stylix targets `gtk`, `gnome` and `kde`.
  The NixOS-level Stylix targets stay on: they only set system defaults,
  which user values override. `stylix.icons` (Papirus) stays.
- **D2.** One cleanup per host after its first deploy: `gtk.css` becomes the
  single line `@import url("hyprchroma.css");`. This adds no permanent code.
- **D3.** Override the engine package so its icon-theme check also looks in
  the NixOS icon dirs. Build it from `inputs`, never from
  `config.programs.nixarchyThemeEngine.package` (that recurses). This
  override was already built and run on p620: the warning went away and
  `kdeglobals` got `[Icons] Theme=Yaru-olive`. The Yaru themes are already
  installed by nixarchy, so nothing gets installed.
- **D4.** The docs say GTK, Qt colours and icons follow a switch live.
- **Accepted costs.** In the GNOME session, GNOME Shell loses the Stylix
  shell theme. libadwaita apps take only light/dark and the accent
  (unchanged). p510 is deployed only after the user approves.

## Rollback

`git revert` the step commits (or set the three HM targets back to `true`
and drop the `programs.nixarchyThemeEngine.package` override), then
redeploy. Home Manager puts Stylix's `gtk.css` link back. If it refuses
because of the plain file from D2, move `~/.config/gtk-{3,4}.0/gtk.css`
aside first.
