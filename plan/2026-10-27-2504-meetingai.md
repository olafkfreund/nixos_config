# Plan: nixarchy-meetingai meeting copilot on p620

## Approved decisions (copied from the spec)

- **Input:** `nixarchy-meetingai.url =
  "github:olafkfreund/nixarchy-meetingai/refactor/omarchy-quickshell-rewrite"`
  with `inputs.nixpkgs.follows = "nixpkgs"`, next to `nixarchy-meeting-mode`
  in `flake.nix`; locked with `nix flake lock --update-input
  nixarchy-meetingai`.
- **Module file** `hosts/common/nixos/omarchy-meetingai.nix`: imports
  `inputs.nixarchy-meetingai.homeManagerModules.default` into
  `home-manager.users.olafkfreund` and sets
  `programs.nixarchy-meetingai = { enable = true; ollamaCloud.keyFile =
  "/run/agenix/api-ollama"; };`. The header comment lists the two one-time
  steps. Default keybindings.
- **p620 only:** imported from `hosts/p620/nixos/nixarchy.nix` next to
  `omarchy-meeting-mode.nix`.
- **meetingai prerequisites (its own repo, before step 3):**
  `ollamaCloud.keyFile` → `LoadCredential=ollama:<path>`, read by the daemon
  from `$CREDENTIALS_DIRECTORY/ollama` before `OLLAMA_API_KEY` and the vault;
  the plugin is set through `programs.nixarchy.plugins."nixarchy.meetingai".src`
  when `programs.nixarchy` exists. Then the branch is pushed to GitHub.
- **One-time steps after deploy:** `omarchy plugin enable nixarchy.meetingai
  --section right`, and `pcall(require, "hypr.meetingai-binds")` in
  `~/.config/hypr/bindings.lua`.
- No new secrets; no other hosts.

## Repo traps

- Never check out a branch in `~/.config/nixos`; work in this worktree
  (`../nixos-2504`). Deploy recipes refuse a non-main branch.
- Conventional Commits with `(#2504)`; never commit to main; PR links the
  issue and all three artifacts.
- The pre-commit hooks format Nix files; commit after they pass.
- The flake input must exist on GitHub before `nix flake lock` can resolve
  it.

## Steps

1. **meetingai prerequisites** (in `mixarchy-meetingai`, after its UI fix
   round is committed): `ollamaCloud.keyFile` and the
   `programs.nixarchy.plugins` registration in `nix/hm-module.nix`, the
   daemon reading `$CREDENTIALS_DIRECTORY/ollama` (unit test), recorded as a
   deviation in its plan; `nix flake check` there; push the branch.
   → verify by `git ls-remote origin refactor/omarchy-quickshell-rewrite`
   showing the pushed commit.
2. **`flake.nix` input and lock** in this worktree.
   → verify by `nix flake metadata . | grep nixarchy-meetingai`.
3. **`hosts/common/nixos/omarchy-meetingai.nix`** and its import in
   `hosts/p620/nixos/nixarchy.nix`.
   → verify by `just test-build p620` (or `nixos-rebuild build --flake
   .#p620`) and `nix flake check`.
4. **PR** to `main` linking #2504 and the three artifacts; the owner merges.
5. **Deploy** from `main` with `just p620`.
   → verify: `systemctl --user is-active nixarchy-meetingai
   nixarchy-meetingai-whisper`; `nixarchy-meetingai ctl state.get`;
   `curl -s 127.0.0.1:8178` answers; `nixarchy-meetingai ctl
   providers.status` shows `ollama-cloud` ready.
6. **One-time desktop steps** (with the owner's OK): enable the plugin in
   the right section; add the `pcall` line to `bindings.lua`; reload the
   shell. Then the owner's checks: `SUPER+ALT+M` opens the overlay, a typed
   question is answered, a 30-second recording gives a transcript and notes.

## Tests

`nix flake check` and a p620 build in the worktree; the post-deploy checks
in steps 5–6.

## Rollback

Remove the import line (or revert the PR) and deploy; the user services and
plugin disappear with the generation. `omarchy plugin disable
nixarchy.meetingai` and deleting the `pcall` line undo the one-time steps.
Earlier generations stay bootable.
