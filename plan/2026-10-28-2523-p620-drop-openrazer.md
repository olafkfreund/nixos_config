# Plan: drop openrazer from p620

`customPkgs.user-python3` includes `ps.openrazer`, which propagates
`openrazer-daemon`. Its D-Bus-activated user unit fails on p620, which has no
Razer hardware. Only razer runs the omarazer plugin that needs the library.
Decisions carried over from the approved spec:

- `user-python3` takes `withOpenrazer ? true` through `pkgs.callPackage`, so
  `.override` works and the default derivation is unchanged.
- `profile.nix` sets it from `osConfig.hardware.openrazer.enable` (razer true,
  p620 false), with one `let` binding shared by all three call sites.
- Rejected: masking the unit, a new HM option, two named packages.

Two code files, two steps: below the coder handoff threshold, so the session
implements it.

## Steps

1. `pkgs/default.nix:110-115`: wrap the `user-python3` definition as
   `pkgs.callPackage ({ lib, python3, withOpenrazer ? true }:
   python3.withPackages (ps: [ ... ] ++ lib.optional withOpenrazer
   ps.openrazer)) { }`, removing `ps.openrazer` from the list itself.
   Add a line to the existing openrazer comment noting the flag.
   → verify by `nix eval` of `nixosConfigurations.razer.pkgs.customPkgs.user-python3.outPath`:
   it must equal the baseline value.
   Traps: none.
2. `Users/olafkfreund/profile.nix`: add `osConfig` to the arguments, bind
   `userPython3` in the `let`, and replace `pkgs.customPkgs.user-python3` at
   lines 234, 248 and 253.
   → verify by comparing razer's `home-manager.users.olafkfreund.home.path`
   outPath with the baseline (`rwf39xnl…`, must be identical) and checking
   that p620's path has changed.
   Traps: every call site must use the same derivation, or buildEnv collides
   on `bin/python3`.

## Tests

- `nix-store -qR` of p620's new home.path: no `openrazer` path.
- `nix build --no-link` of the p620 and razer toplevels: both succeed.
- p510 is not built (it does not import `profile.nix`, and it is an
  ask-first host).
- After deploying to p620 (with your go-ahead, announced on the bus first):
  `systemctl --user status openrazer-daemon` reports "could not be found".

## Rollback

`git revert` the implementation commit and redeploy p620. razer is unaffected
either way.
