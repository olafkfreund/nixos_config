# Plan: p620 boots cleanly: k3d comes up fast, boot-time downloads have DNS

Everything needed is here; the spec and intent are background.

## Approved decisions (from the spec)

- **D1, operational, no repo change:** convert the live `state.db` to
  `auto_vacuum = FULL` with `VACUUM`. The measurements: 11,464,585,216
  bytes (10,933 MiB), 99.8% free pages, 4,438 live rows, WAL mode, on the
  SSD `sde` at `/mnt/img_pool`, in volume `61eae3cf…`. The procedure is
  step 6. Nothing is deleted, and every row and `id` is kept.
- **D2:** `k3d cluster create` adds
  `--k3s-arg "--datastore-endpoint=sqlite:///var/lib/rancher/k3s/server/db/state.db?_journal=WAL&cache=shared&_busy_timeout=30000&_txlock=immediate&_auto_vacuum=full@server:0"`.
  That's the default DSN read from the pinned `rancher/k3s:v1.31.5-k3s1`
  binary plus `_auto_vacuum=full`. Only new clusters are affected.
- **D3:** after the API answers, the bootstrap logs
  `[k3d-bootstrap] datastore <N> MiB, wal <M> MiB, auto_vacuum=<none|full|incremental>`.
  - It reads `stat` sizes and the database header, with no SQLite client.
  - It warns, with a `<4>` prefix, when the db is over 2048 MiB, the WAL is
    over 256 MiB, or the mode is not `full`. Otherwise it logs at info.
  - It never fails the bootstrap.
- **D4:** one Nix value, `bootstrapTimeout = 3 * (cfg.apiWaitSeconds + 300) + 600`
  seconds. On p620 (`apiWaitSeconds = 1800`, `agents = 1`) that is 6900 s.
  `TimeoutStartSec` and the `/etc/hosts` pin loop both use it.
- **D5:** `ollama-model-loader` waits up to 60 s for DNS in `preStart`, then
  exits 0 either way. `restartIfChanged = false` stays.
- **D6:** delete `networking.networkmanager.connectionConfig` and its
  comment from `hosts/p620/nixos/dns-fallback.nix`. Everything else in the
  file stays.

### Deviations from the spec (found while planning)

- **The restore test** (spec D1 step 6) runs on an `--internal` Docker
  network, not "no network": k3s needs a non-loopback interface to pick a
  node IP. It runs without `--privileged`; that flag is added only if the
  server fails on a permission error.
- **D3's report** runs after the bootstrap's `kubectl get nodes` check
  (line 377). The spec said "after the API answers"; that line is where
  both the create and reboot paths have proved it.

   - **D3:**
     - **Where it lives:** define `datastore_report()` at the script's top
       level, next to `api_reachable()` (line 229), not inside the reboot
       branch. Call it once, right after `kubectl get nodes` (line 377), as
       `datastore_report || true`. Calling it with `||` turns `set -e` off
       inside it, so **every** command in it ends in `|| return 0`.
     - **Finding the file:** the volume comes from:

       ```bash
       docker inspect -f '{{range .Mounts}}{{if eq .Destination "/var/lib/rancher/k3s"}}{{.Source}}{{end}}{{end}}' \
         "k3d-$CLUSTER-server-0"
       ```

       Then `db=$vol/server/db/state.db` and `wal=$db-wal`. If the volume
       or `$db` is missing: log `[k3d-bootstrap] datastore: not found` and
       return 0.
     - **Sizes:** `db_mib=$(( $(stat -c %s "$db") / 1048576 ))`, and for the
       WAL `$(stat -c %s "$wal" 2>/dev/null || echo 0)`, also in MiB. A
       missing WAL is normal.
     - **Mode:** read each header field as one big-endian 32-bit number:

       ```bash
       od -An -tu4 --endian=big -j52 -N4 "$db" | tr -d ' '   # largest root page
       od -An -tu4 --endian=big -j64 -N4 "$db" | tr -d ' '   # incremental flag
       ```

       The first is `0`: `none`. Else the second is not `0`:
       `incremental`. Else `full`.
     - **Output:** if `db_mib > 2048`, `wal_mib > 256` or the mode is not
       `full`, `echo "<4>[k3d-bootstrap] WARNING: datastore …"`. Otherwise
       `echo "[k3d-bootstrap] datastore …"`.
