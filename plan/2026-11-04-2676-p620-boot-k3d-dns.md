# Plan: p620 boots cleanly: k3d comes up fast, boot-time downloads have DNS

Everything needed is here; the spec and intent are background.

## Approved decisions (from the spec)

- **D1, operational, no repo change:** convert the live `state.db` to
  `auto_vacuum = FULL` with `VACUUM`. The measurements: 11.46 GB, 99.8% free
  pages, 4,438 live rows, WAL mode, on the SSD `sde` at `/mnt/img_pool`, in
  volume `61eae3cf…`. The procedure is step 6 below. Nothing is deleted,
  and every row and `id` is kept.
- **D2:** `k3d cluster create` adds
  `--k3s-arg "--datastore-endpoint=sqlite:///var/lib/rancher/k3s/server/db/state.db?_journal=WAL&cache=shared&_busy_timeout=30000&_txlock=immediate&_auto_vacuum=full@server:0"`.
  That's the default DSN read from the pinned `rancher/k3s:v1.31.5-k3s1`
  binary plus `_auto_vacuum=full`. Only new clusters are affected.
- **D3:** after the API answers, the bootstrap logs
  `[k3d-bootstrap] datastore <N> MiB, wal <M> MiB, auto_vacuum=<none|full|incremental>`.
  - The volume path is read with `docker inspect k3d-$CLUSTER-server-0`.
  - The sizes come from `stat`, and the mode from the database header,
    with no SQLite client. Header bytes 52–55 (largest root page, big
    endian) are non-zero when auto_vacuum is on; bytes 64–67 are non-zero
    for incremental.
  - The line is printed with a `<4>` prefix (warning) when the db is over
    2 GB, the WAL is over 256 MB, or the mode is not `full`. Otherwise it
    goes out at info.
  - It never fails the bootstrap.
- **D4:** one Nix value, `bootstrapTimeout = 3 * (cfg.apiWaitSeconds + 300) + 600`
  seconds. `TimeoutStartSec` and the `/etc/hosts` pin loop both use it.
- **D5:** `systemd.services.ollama-model-loader.preStart` loops up to 60 s
  until `${pkgs.getent}/bin/getent hosts registry.ollama.ai` answers, then
  exits 0 either way. `restartIfChanged = false` stays.
- **D6:** delete `networking.networkmanager.connectionConfig` and its
  comment from `hosts/p620/nixos/dns-fallback.nix`. Everything else in the
  file stays.

1. **`modules/containers/k3d.nix`** (D2, D3, D4).

       `bootstrapTimeout = 3 * (cfg.apiWaitSeconds + 300) + 600;`, with a
       one-line comment saying why.
     - Line 911: `TimeoutStartSec = "${toString bootstrapTimeout}s";`.
     - Line 112: `seq 1 450` becomes

   - **D2:** in the `k3d cluster create` call (lines 277–288), add the
     `--k3s-arg "--datastore-endpoint=…@server:0"` line after the existing
     `--k3s-arg` lines. Add a comment: the defaults were read from the
     pinned `k3sImage` binary, and must be reread when `k3sImage` changes.
   - **D3:**
     - Add a `datastore_report` function next to `server_progress`. Call it
       once, right after the API-reachable section ends and before
       `Writing kubeconfig` (line 363), as `datastore_report || true`.
     - It resolves the volume with:

       ```bash
       docker inspect -f '{{range .Mounts}}{{if eq .Destination "/var/lib/rancher/k3s"}}{{.Source}}{{end}}{{end}}' \
         "k3d-$CLUSTER-server-0"
       ```

       then reads `server/db/state.db` and `state.db-wal` with `stat -c %s`.
       It reads the header with `od -An -tu1 -j52 -N4` and
       `od -An -tu1 -j64 -N4`.
     - Missing files mean it logs one info line and returns.
     - Add `coreutils` to the bootstrap's runtime inputs, for `od` and `stat`,
       if it isn't there already.

   → **Verify:**
   - `nix eval .#nixosConfigurations.p620.config.systemd.services.k3d-cluster-bootstrap.serviceConfig.TimeoutStartSec`
     returns `"6900s"` (default `apiWaitSeconds` 1800).
   - The rendered script, found through the unit's `ExecStart`, contains
     `seq 1 3450`, the `--datastore-endpoint` line and `datastore_report`.
   - `bash -n` on the rendered script.
   - `datastore_report`, extracted from the rendered script, run read-only
     against the live volume, prints `datastore 10934 MiB, wal … MiB,
     auto_vacuum=none`. That's the before state, and it must be a warning
     line.

   **Traps:**
   - The script is a Nix string: `''${` escapes, and no unescaped `${` for
     shell variables.
   - The bootstrap runs as root with Docker, so no hardening changes.
   - Do not touch `apiWaitSeconds`' default.
