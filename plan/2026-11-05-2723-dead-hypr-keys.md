# Plan: Restore Exposé and remove AI Kit

## Approved decisions (from spec, self-contained)

- **Exposé is restored on p620 and razer, with the hot corner off.** It is declared in the
  Altscape shape, so a rebuild keeps it. `SUPER + E` stays in the shared list in
  `omarchy-keys.nix`, and line 116 of p620's `bindings.lua` stays because `repo-keys.lua`
  unbinds that chord first.
- **The corner default is a package patch**, not a write to `shell.json`. The toggle in
  Exposé's settings still works. A saved `hotCornerEnabled: true` would win, so it is rechecked
  before the first login.
- **AI Kit is removed.** The declaration, the docs row, the `bindings.lua` copies and p620's
  dangling leftovers all go. **`~/.local/share/aikit` is not touched.**
- `workspace-gesture.lua` stays unused. Altscape, Flea, Omarchy's shell and every other
  declared key are not edited. p510 is out of scope.
- The first login on p620 is a gate: razer waits until the shell has started with the plugin
  loaded.

## Repo traps that apply

- Never check out a branch in `~/.config/nixos`. Work in `~/.config/nixos-2723` only.
- New files must be `git add`ed before any flake evaluation can see them.
- `--no-verify` is the established commit workaround. Verify a push by comparing the remote
  head. No backticks in `git commit -m`; use `-F`.
- Before any deploy: `read_new("#agents:freundcloud.org.uk")`, post, and run with
  `AGENT_BUS_ANNOUNCED=1`. Write prose through `--body-file`, because the guard matches words.
- **A branch deploy replaces what the host is running.** Flea (#2694) is on p620 from its own
  branch and is not on main yet. Deploying this branch before Flea merges would remove Flea.
  Step 6 is the gate for this.
- **Editing `bindings.lua` may reload a running session.** p620 has
  `misc:disable_autoreload` false, and a reload can lose layouts in a session older than the
  running system. Whether a change to this required file fires the watcher is unverified, so
  treat it as if it does: steps 7 and 8 edit it only in the fresh session after login, where a
  reload is harmless. The cost is that the dead `SUPER + CTRL + J` stays bound until the edit
  and a reload or the next login.
- Do not restart the Omarchy shell or Hyprland from an agent. The plugin goes live at the
  owner's next login.

## Rollback

- **Plugin misbehaves:** turn it off in Setup > Plugins. The marker keeps it off.
- **Shell fails to start or the system is wrong:** `sudo nixos-rebuild switch --rollback`, or
  pick the previous generation, then log in again. Do this on p620 before razer is touched.
- **`bindings.lua`:** copy the dated backup back, after checking for other edits since.
- **AI Kit leftovers:** the links pointed at nothing, so there is nothing to restore. Move
  `aikit-sync.service.d.removed` back to `~/.config/systemd/user/aikit-sync.service.d` if wanted,
  then run `systemctl --user daemon-reload`.
- **Repo, before the PR merges:** main is untouched, so deploy main. Flea stays, because step 6
  proved it is on main.
- **Repo, after the PR merges:** `git revert -m 1 <PR merge commit>`, which undoes only what this
  PR added to main, so Flea and other main work stay. AI Kit's key returns as dead as it was.
