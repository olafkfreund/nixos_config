# Plan: Omarchy login takes 20-27 s to settle

Approved in advance: the user approved this plan and asked for implementation before
reading its text, while it was being written.

Login does repeated work after the shell is up. Stop it in nixarchy-omatheme and
deliver that here through one flake input override.

Approved decisions:

- `--set-enabled` exits 0 before writing when all hold: recorded value equals the
  request (a missing key is not equal); no `--force`; for `true`, `status.json` has
  this target's field; for `false`, the target is not `dark-reader` or `qt-kde`.
- `framework remove` and `framework restore` pass `--force`.
- The plugin helper exits 0, with no IPC, when the id is a direct `.bar.layout` entry
  and not in `disabledPlugins`. Any other result takes the existing path.
- The forced GTK sync in `omarchy-theme-gnome` stays. Two shell syncs per login are
  accepted, because `omarchy-theme-set-gnome` resets `gtk-theme` at each login.
- A login no longer repairs destination files edited out of band.
- `flake.nix` overrides the input to the merged commit, and the override is removed
  once nixarchy pins that commit or later.

Correction to the spec: `bin/hyprchroma` is not in nixarchy-omatheme. It comes from
the third-party `github:NobleDoodle/omarchroma` input and is rewritten in the Python
block in `pkgs/hyprchroma.nix` `postPatch`. The guard goes there. Line numbers below
into `bin/hyprchroma` are for the built script.
