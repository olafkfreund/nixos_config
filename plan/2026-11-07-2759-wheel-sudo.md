# Plan: limit passwordless sudo for wheel

## Approved decisions (from the intent and spec)

- **Why.** `modules/security/default.nix:7` sets `wheelNeedsPassword = false`; every host evaluates to
  `%wheel ALL=(ALL:ALL) NOPASSWD:SETENV: ALL`, so any process running as `olafkfreund`, agents included,
  becomes root with `sudo -n`. Issue 2758 closes the Nix daemon path; this closes the sudo path. They land
  independently.
- **Policy.** p620 and razer: wheel needs the login password for every sudo, no NOPASSWD rule for wheel at
  all, and no approval cache (`Defaults timestamp_timeout=0`). An agent process that keeps the owner's
  terminal and session could reuse a cached approval, so the cache stays off. `execWheelOnly = true` stays.
- **p510 is unchanged**, through an explicit `security.sudo.wheelNeedsPassword = false` in its host file,
  until the owner schedules it. p510 is never built or deployed by an agent.
- **Rejected:** NOPASSWD limited to deploy commands (needs a store-path wildcard, and any user can build a
  derivation with a script at that path); ssh-agent auth without a touch-required key (agents share
  `SSH_AUTH_SOCK`; `ssh-add -c` is a click-through dialog); run0/polkit (no password over SSH, desktop
  click-through); a root SSH key (same ssh-agent); keeping the sudo cache.
- **Remote password path.** nixos-rebuild-ng 26.11 `--ask-elevate-password` asks once locally (`getpass`)
  and feeds remote `sudo --prompt= --stdin`. nh 4.4.2 does the same for a sudo elevation strategy; whether a
  sudo path selects that flow, and how often nh asks per run, are measured in step 15.
- **Owner decisions:** extra prompts are accepted (one to three per remote recipe, two for `nhs` with the
  boot fallback, one more for the issue-2758 signing step). A deploy an agent starts waits at the prompt
  rather than failing; accepted, because deploys go through the owner.
- **Unattended jobs:** `nixos-upgrade` runs as root (`User=` empty) and never calls sudo; the
  `nixos-update-checker` timer runs as a non-wheel system user and calls no sudo. Unaffected.
- **Out of scope:** the word-matching guards stay as they are (this makes them a second line); the polkit
  rule letting `users` power off and reboot is issue 2761.
- **Issue 2758's signing step** (`sudo nix store sign -r ...` before a `.drv` upload) asks once more
  locally. Nothing to change here.
- **Lockout safety, in this order:** pin the known-good generation with a GC root; prove the password on
  each host (`su`); keep a root shell open on razer until `ssh -t razer sudo` works; no reboot during the
  test; the rollback test targets the first new-policy generation and rechecks `sudo -n true`.

## Who does what

Steps 1-8 and 16, and the test markers in step 15, edit files: the `coder` agent. Builds, reviews,
commits and pushes: the lead. Bus announcements, deploys, password entry, root shells and the GC roots:
the owner, with the lead driving the commands the owner approves. p510 is never built or deployed.

Repo traps for every step: agent-run commands get `</dev/null` (the owner's interactive commands in
steps 11-19 do not: `ssh -t`, `su`, `sudo -i` and password prompts need the terminal as stdin); prose
goes in a file (`-F`, `--body-file`) because the guard matches deploy words; no line may start with an
issue number; pre-push lints whole files (markdownlint MD013 at 120, shellcheck at info level); if the
commit hook reformats, `git add` again and recommit; after a push compare `git rev-parse HEAD` with
`git ls-remote`.

Rollout (steps 11-19): before each host change, `read_new("#agents:freundcloud.org.uk")`, `post` what
and how long, then run with `AGENT_BUS_ANNOUNCED=1`. The branch is deployed with
`ALLOW_BRANCH_DEPLOY=1`, after merging `origin/main` into it so the deploy does not roll back main's
changes.

## Rollback

  `wheelNeedsPassword = false` on p620 and razer. The revert's own deploy asks for the password once, which
  step 12 proved the owner knows.
- **A host that cannot elevate:** razer, from the root shell before step 17:
  `/nix/var/nix/profiles/system-<G0>-link/bin/switch-to-configuration switch`; after step 17,
  `ssh -t razer sudo ...` with the password. p620: the console, or `<P0>` from the boot menu. Both `<G0>` and
  `<P0>` are pinned until step 19.
- **p510** is not touched, so it needs no rollback.
