# Plan: require auth for power actions by the users group (polkit)

Intent: `intent/2026-11-07-2761-polkit-power.md`. Spec: `spec/2026-11-07-2761-polkit-power.md`. Both approved.

## Approved decisions (copied from the spec)

- **Option C on p620 and razer.** `org.freedesktop.login1.reboot`, `reboot-multiple-sessions`, `power-off` and
  `power-off-multiple-sessions` return `polkit.Result.AUTH_ADMIN` for every caller, the active session and the
  Omarchy menu included. The spec confirmed that the Omarchy shell's built-in polkit agent
  (`PolkitAgent.qml`, registered with polkitd) answers these requests.
- **`AUTH_ADMIN`, not `AUTH_SELF`, and no `_KEEP`.** A prompt on every reboot and power-off; nothing kept for an
  agent to ride on. Admin is `unix-group:wheel` (the owner only), so it is the owner's password today.
- **No group, `subject.local` or `subject.active` test.** The point is to cover the active session. Root is not
  affected: logind lets `CAP_SYS_BOOT` callers through before polkit.
- **Left out:** `halt` and the `-ignore-inhibit` actions (already `auth_admin_keep` by default), and `suspend` /
  `hibernate` (owner decision 2: no prompt).
- **p510 keeps today's rule** through `lib.mkBefore` on `security.polkit.extraConfig` in
  `hosts/p510/configuration.nix`. `extraConfig` has type `lines`, so `mkBefore` puts today's `Result.YES` rule
  ahead of the module's `AUTH_ADMIN` rule, and polkit stops at the first rule that returns. Not `mkForce`: that
  would drop every other module's rules (nh `pkexec`, libvirt, NetworkManager, CUPS, fwupd). Not a new
  `features.*` option: one host's temporary exception; the prepend is deleted when p510 follows.
- **Remote power actions** go through password `sudo` (issue 2759). No extra rule for SSH sessions.
- **Accepted by the owner:** a cancelled or timed-out menu reboot leaves the windows closed and no reboot
  (nixarchy closes windows before `systemctl`; tracked upstream in nixarchy).
- **What an agent can still do afterwards** (must go in the PR text): `suspend` and `hibernate`; and, on any host
  where issue 2759 has not shipped, passwordless `sudo systemctl reboot`. This change stops agents only together
  with 2759. On p510 nothing changes.

## Steps

1. `modules/security/default.nix:26-41`: replace the `extraConfig` string (today's `users`-group `Result.YES`
   rule) with exactly this, keeping `enable = true;` and the `sudo` block above untouched:

   ```nix
         extraConfig = ''
           // Power actions need the administrator's password from every caller, the active session included (#2761).
           polkit.addRule(function (action, subject) {
             if (action.id == "org.freedesktop.login1.reboot" ||
                 action.id == "org.freedesktop.login1.reboot-multiple-sessions" ||
                 action.id == "org.freedesktop.login1.power-off" ||
                 action.id == "org.freedesktop.login1.power-off-multiple-sessions") {
               return polkit.Result.AUTH_ADMIN;
             }
           });
         '';
   ```

   → verify with the eval check in Tests (p620 and razer). The module header stays `_: {`; it needs no `lib`.
   Traps: `git add` before evaluating (flakes ignore untracked/unstaged-new files); the commit hook may reformat
   (nixpkgs-fmt) — re-`git add` and commit again if it fails; keep the JS comment inside the Nix string, not as a
   Nix `#` comment; do not touch `security.sudo` (issue 2759 owns it).

2. `hosts/p510/configuration.nix`, after `networking.firewall.enable = false;` (line 529) and before
   `nixpkgs.config` (line 531): add today's rule as a prepend. `lib` is already a module argument (line 3).

   ```nix
     # Today's power rule, kept on p510 until the owner schedules it (#2761). Runs before the
     # AUTH_ADMIN rule from modules/security/default.nix, so it wins.
     security.polkit.extraConfig = lib.mkBefore ''
       polkit.addRule(function(action, subject) {
         if (subject.isInGroup("users") && (
             action.id == "org.freedesktop.login1.reboot" ||
             action.id == "org.freedesktop.login1.reboot-multiple-sessions" ||
             action.id == "org.freedesktop.login1.power-off" ||
             action.id == "org.freedesktop.login1.power-off-multiple-sessions")) {
           return polkit.Result.YES;
         }
       });
     '';
   ```

   → verify with the p510 eval check in Tests (eval only). Traps: **p510 is never built or deployed by the team
   or the coder** — `nix eval` of the rules text only, never `just test-host p510`, `just p510` or `nixos-rebuild`;
   `mkBefore`, never `mkForce`; p510 reboots unattended with autologin and Sunshine, which is why it is pinned.

Not a step: docs. A search of `docs/` found no page describing this rule, so no doc or mkdocs nav changes.

## Tests

NetworkManager, CUPS, fwupd), so check only the login1 power rules, not every `Result.YES`.

1. **Eval, p620 and razer** (no build):

   ```bash
   for h in p620 razer; do
     nix eval --raw ".#nixosConfigurations.$h.config.environment.etc.\"polkit-1/rules.d/10-nixos.rules\".text" \
       </dev/null >"/tmp/rules-$h.js" || exit 1
     grep -c 'login1.power-off-multiple-sessions' "/tmp/rules-$h.js"   # expect 1
     grep -A8 'login1.reboot"' "/tmp/rules-$h.js" | grep -o 'Result\.[A-Z_]*'  # expect AUTH_ADMIN only
     grep -c 'isInGroup("users")' "/tmp/rules-$h.js"                   # expect 0 unless another module adds one
   ```

   Baseline today (p620, read on 2026-11-07): the power rule is the first `addRule`, returning `Result.YES`.

   must show the `users`-group power rule's `Result.YES` line number **before** the `AUTH_ADMIN` line, and
   `grep -c 'login1.power-off-multiple-sessions'` must give 2.

   (so the guard hook does not match the command text) running
