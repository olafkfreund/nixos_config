# Plan: require auth for power actions by the users group (polkit)

Intent: `intent/2026-11-07-2761-polkit-power.md`. Spec: `spec/2026-11-07-2761-polkit-power.md`. Both approved.

## Approved decisions (copied from the spec)

- **Option C on p620 and razer.** `org.freedesktop.login1.reboot`, `reboot-multiple-sessions`, `power-off` and
  `power-off-multiple-sessions` return `polkit.Result.AUTH_ADMIN` for every caller, the active session and the
  Omarchy menu included. The spec confirmed that the Omarchy shell's built-in polkit agent
  (`PolkitAgent.qml`, registered with polkitd) answers these requests.
- **`AUTH_ADMIN`, not `AUTH_SELF`, and no `_KEEP`.** A prompt on every reboot and power-off; nothing kept for an
  agent to ride on. Admin is `unix-group:wheel` (the owner only), so it is the owner's password today.
- **No group, `subject.local` or `subject.active` test.** The point is to cover the active session. Root is not
  affected: logind lets `CAP_SYS_BOOT` callers through before polkit.
- **Left out:** `halt` and the `-ignore-inhibit` actions (already `auth_admin_keep` by default), and `suspend` /
  `hibernate` (owner decision 2: no prompt).
- **p510 keeps today's rule** through `lib.mkBefore` on `security.polkit.extraConfig` in
  `hosts/p510/configuration.nix`. `extraConfig` has type `lines`, so `mkBefore` puts today's `Result.YES` rule
  ahead of the module's `AUTH_ADMIN` rule, and polkit stops at the first rule that returns. Not `mkForce`: that
  would drop every other module's rules (nh `pkexec`, libvirt, NetworkManager, CUPS, fwupd). Not a new
  `features.*` option: one host's temporary exception; the prepend is deleted when p510 follows.
- **Remote power actions** go through password `sudo` (issue 2759). No extra rule for SSH sessions.
- **Accepted by the owner:** a cancelled or timed-out menu reboot leaves the windows closed, the "reboot
  required" marker cleared and no reboot (nixarchy does both before `systemctl`; tracked upstream in
  nixarchy). A timeout (the menu unit's 30 s `RuntimeMaxSec`) ends with no notification.
- **What an agent can still do afterwards** (must go in the PR text): `suspend` and `hibernate`; and, on any host
  where issue 2759 has not shipped, passwordless `sudo systemctl reboot`. This change stops agents only together
  with 2759. On p510 nothing changes for members of `users` (every login user there); a non-root caller
  outside `users` in p510's active session would now need authentication. No such caller is known.

## Tests

NetworkManager, CUPS, fwupd), so check only the login1 power rules, not every `Result.YES`.

Save this checker to `/tmp/power-rules.py` (it prints every login1 rule's result, whether it tests the `users`
group, and whether it names exactly the four actions):

```python
import re, sys
text = open(sys.argv[1]).read()
blocks = text.split("polkit.addRule(")[1:]
ids = ["reboot", "reboot-multiple-sessions", "power-off", "power-off-multiple-sessions"]
print("addRule blocks:", len(blocks))
for b in blocks:
    if "org.freedesktop.login1." not in b:
        continue
    have = sorted(set(re.findall(r'"org\.freedesktop\.login1\.([a-z-]+)"', b)))
    res = re.findall(r"polkit\.Result\.([A-Z_]+)", b)
    print("power rule:", ",".join(res), "users-group" if 'isInGroup("users")' in b else "any-caller",
          "ids-ok" if have == sorted(ids) else "ids=" + ",".join(have))
```
