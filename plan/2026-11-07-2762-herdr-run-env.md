# Plan: herdr-run passes only an allow-list to its pane

## Summary of the approved decisions

Carried over from the approved intent and spec, so this plan stands alone.

- **Problem.** `herdr-run` writes the caller's whole exported environment, credentials included
  (`GITHUB_API_TOKEN` and five more, from `modules/secrets/api-keys.nix`), to `$dir/env` under `/tmp`
  on disk, and the pane's command sources it.
- **Fix.** One list, in a new file `home/development/agent-env.sh`, shared by Nix concatenation
  (`builtins.readFile`), never sourced at run time. `herdr-run` writes only the names on that list.
- **The list** (`agent_env_names`): #2757's base (`PATH HOME LANG TERM TMPDIR SSL_CERT_FILE NIX_REMOTE
  NIX_CONFIG`), #2757's markers (`CODEX_CODER AGY_CODER AGY_WORKTREE AGY_GUARD_LOG`), plus
  `XDG_RUNTIME_DIR XDG_CACHE_HOME USER LOGNAME SHELL AGY_IMPLEMENT_PROBING`, plus `XDG_CONFIG_HOME
  XDG_DATA_HOME` (owner decision on the spec, 2026-11-07).
- **Not on the list**, by owner decision: every `HERDR_*` name, `SSH_AUTH_SOCK`, every credential,
  and `DBUS_SESSION_BUS_ADDRESS` (the default path is found without it; `gh auth status` passes
  under `env -i` with `HOME` and `PATH`).
- **What is exported** is read from `env -0`, never `compgen` (minimal bash has none) and never
  `[[ -v ]]` (bash sets `SHELL` and `TERM` itself without exporting them).
- **Unchanged:** the helper keeps the caller's `HERDR_*` (it makes the tab and reports state); the
  runner's `env -i … source "$0/env"`; the headless path (`exec "$@"` with the full environment);
  the `run` file and argv (spec section 3).
- **`agent-sandbox.sh`** (from #2757) builds its base environment by walking `agent_env_base`, a `case`
  arm per name giving the sandbox value; a name with no arm aborts before the tool starts. It does
  not use `agent_env_markers` or `agent_env_names`; `agent-implement` adds only its own tool's
  markers, as #2757's spec section 7 says.
- **`agent-env`**, a new command, runs `env -i` with the list. The `second-opinion` skill's two
  agy commands use it in place of `env -u GEMINI_API_KEY -u GEMINI_API_KEY_FILE -u GOOGLE_API_KEY`.
  The Codex paths stay: `agent-review` already clears the environment.
- **Tests** prove by name only, never by value, that no decoy reaches the file or the command, and
  two mutants prove the test can fail.
- **Landing order.** After #2757 has merged to `main`. If #2757's merged base list differs from
  `agent_env_base`, the merged one wins and this plan records the difference (step 0).

   ```bash

   # #2757's sandbox: what both tools get. agent-sandbox.sh gives each name its own value.
   agent_env_base=(PATH HOME LANG TERM TMPDIR SSL_CERT_FILE NIX_REMOTE NIX_CONFIG)
   # #2757's per-tool markers: CODEX_CODER for codex; AGY_CODER, AGY_WORKTREE, AGY_GUARD_LOG for agy.

   # What a herdr pane or agent-env passes on from its caller (#2762).
   agent_env_names=("${agent_env_base[@]}" "${agent_env_markers[@]}" XDG_RUNTIME_DIR
     XDG_CACHE_HOME XDG_CONFIG_HOME XDG_DATA_HOME USER LOGNAME SHELL AGY_IMPLEMENT_PROBING)
   # Prints, NUL-separated, each name on agent_env_names that the caller exported.
   agent_env_exported() {
     local -A exported=()
     local entry name
     while IFS= read -r -d '' entry; do exported[${entry%%=*}]=1; done < <(env -0)
     for name in "${agent_env_names[@]}"; do
       if [[ -n ${exported[$name]:-} ]]; then printf '%s\0' "$name"; fi
     done
   }
   ```
