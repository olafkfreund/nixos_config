# Plan: Flux on p620 and razer

Issue #2905. The intent (`9c196d7a3`) and the spec (`a2029b7f9`) are approved. This plan stands on its own.

Where the work happens: the worktree `~/.config/nixos-flux-2905`, on a new branch `feat/2905-flux` cut from

## Approved decisions

- **Flake input** `nixarchy-flux` = `github:olafkfreund/nixarchy-flux`, with `inputs.nixpkgs.follows = "nixpkgs"`.
  Flux has no other inputs. It is locked to master after nixarchy-flux#59 merges.
- **Module** `modules/desktop/flux.nix`, imported in `modules/desktop/default.nix` beside `tfm.nix`, gives
  `features.flux`:
  - `enable` (`mkEnableOption`)
  - `trustedConnections`: `nullOr (listOf str)`, default `null`, a list of NetworkManager connection UUIDs
  - It imports `inputs.nixarchy-flux.nixosModules.default`.

  When enabled:
  - **NixOS:** `services.flux = { enable = true; users = [ ]; openFirewall = false; approve.services = [ ];
    webcam.enable = false; }`.
  - **Home Manager:** `home-manager.users.${username}.imports = [ inputs.nixarchy-flux.homeManagerModules.default ]`,
    and `home-manager.users.${username}.services.flux = { enable = true; plugin.enable = true; browser.enable = false; }`.
    No `NoNewPrivileges`: `fluxd` runs the user's phone commands, which may use `sudo`. No `LockPersonality` either:
    on a user unit it implies `NoNewPrivileges` (deviation, #2909).
  - **Avahi:** nothing beyond Flux's `mkDefault`s. p620's settings at normal priority, including `allow-interfaces =
    [ "enp1s0" ]`, win.
- **Guard,** only when `trustedConnections != null`:
  - **The table** `inet flux_guard`:
    - set `trusted`: `ifname`, holding `lo` and `tailscale0`
    - input chain, priority filter − 1, policy accept: `iifname @trusted accept`, `ct state new tcp dport
      12070-12108 drop`, `ct state new udp dport 12100 drop`
    - output chain, same priority and policy: `oifname @trusted accept`, then drop `udp dport 5353`, `udp sport 5353`
      and `udp dport 12100`
  - **`flux-guard.service`:**
    - `wantedBy multi-user.target`, `before` and `wants` `network-pre.target`
    - oneshot, `RemainAfterExit`
    - `ExecStart` and `ExecReload` load atomically: one `nft -f` file holding `table inet flux_guard`, `delete table
      inet flux_guard` and the definition
    - `ExecStop` deletes the table
  - **`flux-guard-sync.service`:**
    - `after NetworkManager.service flux-guard.service`, `bindsTo flux-guard.service`
    - `reloadPropagatedFrom flux-guard.service`, `wantedBy multi-user.target`
    - oneshot, `RemainAfterExit`
    - `ExecStart` and `ExecReload` run the reconcile script
  - **Reconcile script:**
    - takes an exclusive `flock /run/flux-guard.lock`
    - runs `nmcli -t -f UUID,DEVICE connection show --active` and keeps the devices whose UUID is trusted
    - in one `nft -f`, flushes `@trusted` and adds `lo`, `tailscale0` and those devices
  - **Dispatcher** (`networking.networkmanager.dispatcherScripts`, type `basic`): runs the reconcile script on `up`,
    `down`, `dhcp4-change` and `connectivity-change`.
  - **Executables:** `${pkgs.nftables}/bin/nft`, `${pkgs.networkmanager}/bin/nmcli`, `${pkgs.util-linux}/bin/flock`.
  - **Hardening** of both units: `CapabilityBoundingSet = [ "CAP_NET_ADMIN" ]`, `NoNewPrivileges`, `ProtectSystem =
    "strict"`, `ProtectHome`, `PrivateTmp`, `ReadWritePaths = [ "/run" ]`, `RestrictAddressFamilies = [ "AF_NETLINK"
    "AF_UNIX" ]`, `ProtectKernelModules`. A comment records the reasoned `DynamicUser` exception: they need
    `CAP_NET_ADMIN` in the host network namespace.
- **Hosts:**
  - p620: `features.flux.enable = true;` (no guard)
  - razer: `features.flux = { enable = true; trustedConnections = [ "2480c26b-7797-49e1-8a9f-af6bccc6d77c" ]; };`.
    This is the `home` Wi-Fi connection, read on razer on 2026-11-13. razer's Wi-Fi interface is `wlp3s0`; the spec
    said `wlan0`, and the guard doesn't depend on the name.
- **Docs:** `docs/applications/flux.md` and its MkDocs `nav` entry. They cover the hybrid, the hardening exceptions,
  the guard, and the manual steps: `flux-cli setup`, pairing razer from the phone, and adding the phone's Tailscale
  address.
- **Handover on p620:** the hand-started `fluxd` (pid 2397965, from agent session `9f0892`) uses the default XDG
  paths, so `~/.local/share/flux` with its certificate, key and `devices.json` carries the pairings over. The order
  is: announce on the bus, tell `9f0892`, stop the old process, switch, check.

## Rollback

- Set `features.flux.enable = false` on the host, or revert the PR, then `just p620` (razer: `just deploy-via-p620
  razer`).
- On razer, `systemctl stop flux-guard` removes the table at once.
- Pairings stay in `~/.local/share/flux` either way.

## Deviations

- **Step 2** (coder): `nix eval` used a `path:` flake ref, because `.#` ignores untracked files until they are staged.
- **Step 4** (Codex): `ReloadPropagatedFrom` sits in `unitConfig`, as this NixOS pin requires.
- **Step 4 checks:** `nft --check` and a set update ran in a user and network namespace (`unshare -rn`).
- **Step 5** (agy): `just docs-check` fails with 16 warnings that exist on main too (`reference/*` links that only
  `mkdocs-full.yml` generates). The full config's strict build passes.
- **Step 6 review fixes** (lead, from the Opus review):
  - **The lock** moved to nixarchy-flux `3042a94`, which is #59 merged. It had been locked before #59.
  - **The reconcile script** captures the `nmcli` output first, so a failure fails the unit.
  - **`pre-down`** is dropped from the dispatcher and the docs: a `basic` dispatcher script never receives it.
  - **The guard `upholds` the sync unit,** so a manual restart restores trust.
