# Plan: T3 Code follows the Omarchy theme declaratively

This plan carries every decision from the approved spec
(`spec/2026-11-16-2973-t3code-theme.md`), so it can be followed without
opening the spec. One PR, on branch `feat/2973-t3code-theme`, in the worktree
`~/.config/nixos-2973`.

## Approved decisions

- **One trigger.** A Home Manager activation entry,
  `home.activation.t3codeOmarchyTheme`, ordered
  `lib.hm.dag.entryAfter [ "writeBoundary" "nixarchySeed" ]`, whose body is
  `run ${script}`.
  - `nixarchySeed` stages the first-run theme headless
    (`nixarchy/modules/home.nix:1265-1276`), which covers a fresh install.
    Its existence is asserted by an eval check (step 2), not assumed.
  - Activation runs at every boot and every switch, so a skipped run is
    retried.
  - No post-boot hook and no `omarchy-theme-refresh`.
- **Gating.** `enabled = config.programs.nixarchy.apps.t3-code.enable` is read
  in the outer NixOS module. `lib.mkIf enabled` wraps the activation entry
  inside `home-manager.users.olafkfreund = { lib, ... }: { … }`, never the
  module function. The option is off on Razer and p510 today.
- **Paths.** `T3CODE_HOME` is `$HOME/.t3`, and `STATE` is
  `$T3CODE_HOME/userdata`. The theme file is `$STATE/themes/${themeId}.json`;
  this is where `omarchy-theme-set-t3code:9-13` writes. The settings file is
  `$STATE/settings.json`; `t3 theme set X --base-dir D` writes
  `D/userdata/settings.json` (tested on 2026-11-16). Every path in the script
  is written out in full from these two variables.
- **Binaries.**
  - `export PATH="${binPath}''${PATH:+:$PATH}"`, so an unset or empty `PATH`
    gives neither an error under `set -u` nor `.`.
  - In production, `binPath` is
    `${lib.makeBinPath [ coreutils gnugrep jq ]}:/etc/profiles/per-user/olafkfreund/bin:/run/current-system/sw/bin`.
  - `t3` works with an empty environment (tested: 0.4 s).
- **The script.** It uses `set -u`, no `-e`, and ends with an explicit
  `exit 0`. Each `log` goes to stderr with the prefix `t3code-theme:`; when
  it prints command output, every line gets the prefix. Steps, in order,
  where "stop" means `exit 0`:
  0. If `${HOME:-}` is empty, log `HOME unset` and stop. Otherwise
     `export T3CODE_HOME="$HOME/.t3"` and set `STATE="$T3CODE_HOME/userdata"`.
  1. For `omarchy-theme-set-t3code`, then `t3`: if `command -v` fails, log
     `<name> not found` and stop. This check runs first, before anything is
     written.
  2. `mkdir -p "$STATE"`.
  3. If `$HOME/.local/state/omarchy/current/theme/t3code.json` is missing,
     log `no Omarchy palette staged yet; next activation retries` and stop.
  4. Run `omarchy-theme-set-t3code`.
     - Non-zero exit: log `publisher exited <code>` and stop.
     - Exit 0 while the source contains `{{` (`grep -qF '{{'`): log `palette
       has unresolved colours; kept the previous one`, and continue.
  5. If `$STATE/themes/${themeId}.json` is missing, log `theme ${themeId} not
     published` and stop.
  6. Read the current theme with
     `jq -r '.defaultTheme // empty' "$STATE/settings.json" 2>/dev/null`.
     If the file is missing or broken, the current theme is empty. If it
     equals `themeId`, stop without calling `t3`.
  7. Run
     `timeout -k ${toString killSecs} ${toString timeoutSecs} t3 theme set ${themeId} --base-dir "$T3CODE_HOME"`.
     Its stdout and stderr go to a `mktemp` file, never a pipe.
     - On a non-zero result, including 124 and 137, log `t3 theme set exited
       <code>` and the last 5 lines of that file, each prefixed.
     - Always `rm -f` the file afterwards.
- **Theme id.** `themeId` is a parameter of the script builder, default
  `"omarchy"`, set in the module's `let`. The publish step always runs. #2974
  will set `omarchy-plus`.
- **Owner decisions.**
  - Force `themeId` whenever it differs, on every activation.
  - Open an upstream nixarchy issue, linked in the module header, so the
    module can be deleted once upstream ships it.

## Steps

### 1. Script builder (codex)

New file: `hosts/common/nixos/t3code-theme-script.nix`.

Interface:

```nix
{ pkgs }:
{ binPath, themeId ? "omarchy", timeoutSecs ? 30, killSecs ? 5 }:
pkgs.writeShellScript "t3code-omarchy-theme" ''…''
```

Implement steps 0-7 exactly as written in "Approved decisions". Quote every
expansion. Prefix the output lines with a `while IFS= read -r` loop; `gnused`
is not on `binPath`.

Verify:

```bash
nix-instantiate --parse hosts/common/nixos/t3code-theme-script.nix
nix build --impure --expr 'let pkgs = (builtins.getFlake (toString ./.)).inputs.nixpkgs.legacyPackages.x86_64-linux; in import ./hosts/common/nixos/t3code-theme-script.nix { inherit pkgs; } { binPath = "/x"; }'
shellcheck result
```

Traps:

- Nix `''` strings: write bash `${` as `''${`.
- Integers need `toString`.
- No `set -e`.
- `run` is a Home Manager function and is not available inside the script.

### 2. Module and imports (coder)

New file: `hosts/common/nixos/omarchy-t3code-theme.nix`, with this shape:

```nix
{ config, pkgs, lib, ... }:
let
  enabled = config.programs.nixarchy.apps.t3-code.enable;
  themeId = "omarchy";
  script = import ./t3code-theme-script.nix { inherit pkgs; } {
    inherit themeId;
    binPath = "${lib.makeBinPath [ pkgs.coreutils pkgs.gnugrep pkgs.jq ]}:/etc/profiles/per-user/olafkfreund/bin:/run/current-system/sw/bin";
  };
in
{
  home-manager.users.olafkfreund = { lib, ... }: {
    home.activation.t3codeOmarchyTheme = lib.mkIf enabled
      (lib.hm.dag.entryAfter [ "writeBoundary" "nixarchySeed" ] ''
        run ${script}
      '');
  };
}
```

- The header comment says what the module does, and why: these are installer
  steps NixOS never runs. It links #2973 and the upstream issue, whose number
  the lead files before this step.
- Add `../../common/nixos/omarchy-t3code-theme.nix` to the `imports` in
  `hosts/{p620,razer,p510}/nixos/nixarchy.nix`, right after the
  `omarchy-stylix-theme.nix` line. Import order does not matter for module
  evaluation.

Verify. Each command must print the expected value:

### 3. Check (coder)

New file: `checks/t3code-theme.nix`. Add one line to `checks/default.nix`:

```nix
t3code-theme = import ./t3code-theme.nix { inherit pkgs; };
```

It is a `pkgs.runCommand` that:

- builds two script instances from the step 1 builder, both with
  `timeoutSecs = 2; killSecs = 1;`:
  - `full`, whose `binPath` holds stubs for `t3` and `omarchy-theme-set-t3code`
    plus coreutils, gnugrep and jq;
  - `noT3`, whose `binPath` holds only the publisher stub plus those tools;
- runs `shellcheck` on `full`;
- uses stubs made with `pkgs.writeShellScript` (sandbox: there is no
  `/usr/bin/env`). The stubs read their behaviour from variables in a per-case
  file, and append their arguments to a per-case call log;
- has a `t3` stub that, on `theme set X --base-dir D`, writes
  `{"defaultTheme":"X"}` to `D/userdata/settings.json`;
- gives each case its own `HOME` from `mktemp -d` under `$TMPDIR`. It runs with
  `env -i HOME=… PATH=<coreutils only>`, so only `binPath` supplies the stubs.

Cases. Each asserts exit 0, and checks the call log, stderr and the files:

1. No staged `t3code.json`: no `t3` call; stderr contains `no Omarchy palette`.
2. The publisher stub exits 1: no `t3` call; stderr contains
   `publisher exited 1`.
3. The source contains `{{`, the publisher exits 0, and a fixture
   `themes/omarchy.json` exists: the warning is logged, and `t3` is called.
4. The source contains `{{` and no `themes/omarchy.json` exists: `theme
   omarchy not published` is logged, and `t3` is not called.
5. No `settings.json`: `t3 theme set omarchy --base-dir $HOME/.t3` is called,
   and `$HOME/.t3/userdata/settings.json` then says `omarchy`.
6. `defaultTheme` is `ember`: `t3` is called.
7. `defaultTheme` is `omarchy`: `t3` is not called.
8. The `t3` stub exits 1 after printing two lines: stderr contains `exited 1`
   and both lines with the prefix.
9. The `t3` stub runs `trap '' TERM; exec sleep 60`: the script finishes within
   5 s, stderr contains `exited 137`, and no `tmp.*` file is left in its
   `TMPDIR`.
10. `noT3`: stderr contains `t3 not found`, and nothing is created under
    `$HOME/.t3`.

Verify:

```bash
nix build .#checks.x86_64-linux.t3code-theme -L
```

Then break one assertion on purpose, confirm the build fails, and revert the
change.

## Rollback

1. Revert the PR, then `git pull --ff-only` on `main` in `~/.config/nixos`.
2. Run the checks from step 4.2 on the reverted tree.
3. Announce on `#agents`, then `AGENT_BUS_ANNOUNCED=1 just p620`.
4. The revert stops enforcement. It does not change the theme T3 Code has
   selected, which stays `omarchy` in `~/.t3/userdata/settings.json`. To
   pick another one:

   ```bash
   t3 theme set <id>
   ```

   or choose one in T3 Code's settings.
5. The module only writes the theme selection, through the supported CLI, and
   `omarchy.json`, which Omarchy writes on every theme switch anyway. Nothing
   else needs cleaning up.

## Deviations during implementation

- D1 (Opus review): the script builder asserts that `themeId` matches
  `[a-z0-9-]+`, because it is spliced into shell and file names unescaped.
- D2 (Opus review, found with mutation tests):
  - Case 2 now has a fixture `themes/omarchy.json`, so it fails if the script
    keeps going after the publisher fails.
  - Case 1 also asserts that the publisher is not called.
  - The check's `binPath` no longer ends in `:`; an empty `PATH` entry means
    the current directory.
