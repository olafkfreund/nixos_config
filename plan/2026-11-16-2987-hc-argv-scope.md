# Plan: herdr-app argv launches get their own systemd scope

Branch `fix/2987-hc-argv-scope`, worktree `~/.config/nixos-2987`, stacked on `feat/2978-herdr-app-parity` (PR #2990).
The PR targets `feat/2978-herdr-app-parity` until #2990 merges, then `main`.

## Approved decisions (from the spec)

- herdr-app starts argv launches (+ menu agents, `tab.new --argv`, `terminal.open`, splits) as
  `$SHELL -ic "<argv>"; exec $SHELL -i`, bypassing hc's `shell = [hcShell]`. Fix: an interactive-bash guard that
  re-execs such a shell once through `hcShell` (`home/development/herdr.nix:43`), which strips the inherited
  identities and execs `paneShell` (`:33`, `systemd-run --user --scope --unit=herdr-pane-$$`, exec in place).
- The guard fires only when all hold: `HC_TERMINAL_ID` set; the user bus socket exists (the same test `paneShell`
  uses, so the re-exec always lands in a scope); the cgroup file reads successfully and has no
  `/herdr-pane-[0-9]+\.scope(/|$)` component; `/proc/$$/cmdline` reads into a non-empty array. Then
  `exec <hcShell> "${argv[@]:1}"`.
- No marker variable and no `HERDR_ENV` test: both can leak into app terminals. The cgroup test is the loop guard.
- `HC_ARGV_GUARD_CGROUP` (default `/proc/self/cgroup`) exists only for the test.
- Placement: `programs.bash.initExtra` at `lib.mkOrder 50`, after Home Manager's interactive check and before its
  completion block (order 100), bash-preexec (1000), starship (1900) and the tail (2000). Gated by
  `programs.herdrSkill.enable`.
- `herdr-team` members (`hc run … -- bash launch`) are out of scope.
- Upstream: an issue asking herdr-app to start argv launches through hc's configured `shell`. Its text goes in the
  PR body; it is filed only after the owner says so.

## Steps

- **Step 1:** `home/development/hc-argv-guard.bash` (new). The guard from the spec, with `@hcShell@` as the
  placeholder for the wrapper path, `2>/dev/null` on the cgroup read and on the cmdline read, and
  `unset _hc_cg _hc_argv` at the end. No shebang (it is sourced). One comment line with the why and `#2987`.
  Check: `bash -n home/development/hc-argv-guard.bash`; `shellcheck -s bash` on it clean.
  Traps: it is sourced into the owner's interactive shell, so it must not `set -e`/`-u`, leave variables or
  print anything when it does not fire.

- **Step 2:** `home/development/herdr-argv-guard-test.sh` (new). Takes the guard path as `$1`. In a temp dir: a
  fake bus socket (`python3 -c` binding an `AF_UNIX` socket), `XDG_RUNTIME_DIR` pointing there, a fake cgroup file
  `0::/user.slice/app.slice/hc-hold-1.scope`, and a fake `hcShell` that appends `wrap <pid>` to a log, writes
  `0::/user.slice/app.slice/herdr-pane-$$.scope` to a new cgroup file, exports `HC_ARGV_GUARD_CGROUP` to it and
  `exec bash "$@"`. The guard under test is the step 1 file with `@hcShell@` replaced (sed) by the fake.
  Run in the background with stdin from `/dev/null`, then `wait "$pid"`:
  `HC_TERMINAL_ID=t1 bash --rcfile <guard> -ic '<cmd>' n 'a b' '' '$x' "it's" 'say "hi"'`, where `<cmd>` logs
  `run $$ $0` and each positional argument. Assert:
  - the log has exactly one `wrap` line and one `run` line, both with the PID `$!` of the background run;
  - `$0` is `n` and the arguments are `a b`, the empty string, the literal `$x`, `it's` and `say "hi"`;
  - `-ic 'cmd; exec bash --rcfile <guard> -ic "<log run2>"'`: the second shell logs with the same PID and no second
    `wrap`;
  - no `wrap` when: the cgroup file names `herdr-pane-9.scope`; it names `herdr-pane-9.scope/child.scope`;
    `HC_TERMINAL_ID` is unset; the bus socket is missing; `HC_ARGV_GUARD_CGROUP` points at a missing file.
  - stderr, with bash's two no-tty warnings removed (`cannot set terminal process group` and
    `no job control in this shell`, which appear once per bash start), is empty in every case.
  Check: `bash home/development/herdr-argv-guard-test.sh home/development/hc-argv-guard.bash` passes; `shellcheck`
  clean.
  Traps: the Nix build sandbox has `/proc` but no user bus; the test makes its own socket. No `sleep` loops.

- **Step 3:** `home/development/herdr.nix`. In the `let`: `hcArgvGuard = pkgs.runCommand "hc-argv-guard" { } ''`
  run `PATH=<bash coreutils gnugrep gnused python3>:$PATH bash ${./herdr-argv-guard-test.sh} ${./hc-argv-guard.bash}`
  then `substitute ${./hc-argv-guard.bash} $out --replace-fail @hcShell@ ${hcShell}` `''`. In `config`: line 86
  `programs.bash.initExtra = claudeLauncher;` becomes
  `lib.mkMerge [ claudeLauncher (lib.mkIf cfg.enable (lib.mkOrder 50 "source ${hcArgvGuard}")) ]`.
  The derivation also runs `bash -n` and `shellcheck -s bash` on the guard and `shellcheck` on the test, like the
  `checkPhase`s in `home/development/agent-run.nix`. It is a standalone derivation rather than one of those
  packages' checks because the guard is a sourced file, not a package; sourcing its output makes every host build
  run it (clarifies the spec's "same build check").
  Check: `just test-host p620`; in the built `.bashrc`, the `source …hc-argv-guard` line comes after
  `[[ $- == *i* ]] || return` and before the completion block and every other `initExtra` contributor. (Home
  Manager puts history, shell options and aliases between the check and `initExtra`; the spec's "directly after"
  means first within `initExtra`.)
  Traps: `initExtra` is `types.lines`, so `mkOrder` applies; keep `claudeLauncher` at its default order.
  Deviation (done): the test PATH also needs `diffutils`, and the fake wrapper's shebang is written from
  `command -v bash` because the build sandbox has no `/usr/bin/env`. Steps 1-2: the cgroup read uses `cat`, since
  bash's `$(<missing)` reported success for a missing file.
  Deviation (Opus review): the guard now fires only when the cgroup names an `hc-hold-*.service` (the unit hc
  really uses), not on "anything but a pane scope", so shells the owner puts in their own scopes (`systemd-run
  --scope …`, `uwsm app`) and herdr-team member scopes stay where they are. It uses builtins only (`mapfile`,
  `[[ =~ ]]`, `$UID`), because the guard runs after Home Manager's aliases and `cat=bat` replaced its `cat`. The
  test adds those cases, an aliased run, and checks for stdout and leaked variables.

## Rollback

Revert the step 3 wiring (or the PR) and switch: newly started argv launches return to the shared `hc-hold-*` unit;
already running pane scopes stay until their shells exit. Nothing else depends on the guard. Prefer the revert over
`programs.herdrSkill.enable = false`, which also removes the managed Herdr skills.
