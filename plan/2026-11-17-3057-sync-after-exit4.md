# Plan: the checkout sync also runs after a switch that exits 4 but activated

## Approved decisions (from the spec)

- Only `scripts/sync-remote-checkout.sh` changes behaviour; no Justfile recipe changes.
- Invariant: syncing commit C is correct whenever the target runs exactly the system that C's tree evaluates to.
- On COMMAND exit 4 with an eligible source (`reason` empty), and only then:
  1. Source identity: `git status --porcelain` succeeds with empty output and `git rev-parse 'HEAD^{tree}'` equals
     the recorded `tree`. Checked before the evaluation and again after it. Failure:
     `exit 4; source moved during the command; skipped`.
  2. `expected=$(nix eval --raw ".#nixosConfigurations.$host.config.system.build.toplevel" 2>/dev/null)`; failure
     or empty output: `exit 4; could not evaluate the deployed system; skipped`.
  3. `sync_checkout "$tree" "$expected"`; its single result line is the only output.
- Every other non-zero exit keeps `command failed; skipped`. The wrapper exits with COMMAND's code. The exit-0 path
  is unchanged and never calls `nix`.
- The remote script gets `$2` (the expected path, empty after exit 0). When non-empty, right before
  `git merge --ff-only` (after the ancestor check and the commit count):
  `running=$(readlink -f /run/current-system 2>/dev/null) || running=`; if `$running != "$2"`, print
  `target is not running the deployed system; skipped` and exit 0. `already current` keeps its early exit.
- Accepted risk: an activation between that `readlink` and the merge is not caught.
- `sync HOST TREE` is unchanged (passes no expected path).
