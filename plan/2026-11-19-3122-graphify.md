# Plan: graphify knowledge graph for Claude Code, Codex and Antigravity

Decisions (from the approved spec):

- Package: `customPkgs.graphify` = nixpkgs graphify plus the `mcp` and `pdf`
  extras. No `leiden` (broken on py3.14).
- Flag: `features.development.graphify`, on in `Users/olafkfreund/profile.nix`
  (p620 + razer), off on p510.
- Skill: linked from the package store into `.claude/skills` (claude variant)
  and `.agents/skills` (agents variant, for Codex and agy).
- MCP: stdio `graphify-mcp` with no args, for Claude, Codex and agy.
- `GRAPHIFY_BACKEND=none`; `graphify-out/` globally gitignored.
- No hooks. No `graphify install`.

## Steps

1. `pkgs/default.nix`, after `ollama-mcp`: add
   `graphify = pkgs.graphify.overridePythonAttrs (o: { dependencies = o.dependencies ++ o.optional-dependencies.mcp ++ o.optional-dependencies.pdf; });`
   with a one-line why-comment (no leiden: graspologic pulls future, broken on py3.14).
   → verify: `nix build .#nixosConfigurations.p620.pkgs.customPkgs.graphify`
   Traps: none.
2. `Users/common/features.nix`, in the `development` block: add
   `graphify = mkEnableOption "graphify knowledge-graph CLI, skill and MCP (#3122)";`.
   In `Users/olafkfreund/profile.nix`, in `development`: add `graphify = true;`.
   Traps: do not touch `p510_home.nix`.
3. New `home/development/graphify.nix`, imported in `home/development/default.nix`
   next to `./codex-cli.nix`. `{ config, lib, pkgs, ... }`, with
   `config = lib.mkIf config.features.development.graphify { ... }` setting:
   - `home.packages = [ pkgs.customPkgs.graphify ]`
   - `home.sessionVariables.GRAPHIFY_BACKEND = "none"`
   - `programs.git.ignores = [ "graphify-out/" ]`
   - `home.activation.codexGraphifyMcp`, the same shape as `codexNixdMcp` in
     `codex-cli.nix`, using `bin = "${config.home.profileDirectory}/bin"`: if
     `${bin}/codex` exists and `codex mcp get graphify` fails, run
     `$DRY_RUN_CMD ${bin}/codex mcp add graphify -- ${bin}/graphify-mcp`.

   Traps: never `exit` in an activation entry. No `mkIf cond true`.
4. `home/development/claude-code-skills/default.nix`: add a
   `graphifySkill = variant: md:` `runCommand` that makes `$out/SKILL.md`
   (copy of `${pkgs.customPkgs.graphify}/${pkgs.python3.sitePackages}/graphify/${md}`)
   and `$out/references` (copy of `.../graphify/skills/${variant}/references`).
   Merge into `localSkills` with
   `lib.optionalAttrs config.features.development.graphify { graphify = { src = graphifySkill "claude" "skill.md"; to = [ "claude" ]; }; }`.
   The agents variant needs a second name key, which `localSkills` doesn't
   allow, so add a separate `home.file.".agents/skills/graphify"` entry
   (`recursive = true; force = true;`) under the same flag, built from
   `graphifySkill "agents" "skill-agents.md"`.
   Traps: `python3.sitePackages`, not a hard-coded python3.14.
   → verify: the HM build contains both trees.
5. `home/development/claude-code-mcp.nix` `sharedMcpDesired.mcpServers`: merge
   `lib.optionalAttrs config.features.development.graphify { graphify = { type = "stdio"; command = "${pkgs.customPkgs.graphify}/bin/graphify-mcp"; args = [ ]; }; }`.
   Add a comment that turning the flag off needs `graphify` in `retiredMcpServers`.
   Traps: `mcpRetireTest` must still pass (it is built with the HM config).
6. `home/development/antigravity-config.nix` `sharedMcpServers`: merge the same
   `optionalAttrs` with `{ command = ".../bin/graphify-mcp"; args = [ ]; }`.
   Traps: the module may have no `config` arg. If not, add it.
7. Lead: `just check-syntax`. Build p620 and razer. Check that p510's toplevel
   drv is unchanged from origin/main. Commit, open the PR, merge after review,
   then switch p620 (bus announcement first) and run the Tests. Then razer via
   `just deploy-via-p620 razer`, and run them again.

## Rollback

Set `graphify = false` in `profile.nix` and add `graphify` to
`retiredMcpServers`. Run `codex mcp remove graphify`. Or revert the PR and
switch to the previous generation.
