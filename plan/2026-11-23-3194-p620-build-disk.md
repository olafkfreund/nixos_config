# Plan: a dedicated NVMe for builds and the GitHub runners on p620

## Approved decisions (from the spec)

- **Disk:** `/dev/disk/by-id/nvme-Lexar_SSD_EQ790_1TB_QJC054R004014P221Q`. GPT, one partition named `build`, ext4
  labelled `build` with `-m 0`. Mounted at `/mnt/build` **by UUID** with
  `noatime nofail x-systemd.device-timeout=10s`, plus `x-systemd.before=systemd-tmpfiles-setup.service` and
  `x-systemd.before=nix-daemon.service`.
  TRIM is the existing weekly `fstrim`, with no `discard` option.
- **Directories:**
  - `/mnt/build/nix`, `0755 root root`: the build-dir;
  - `/mnt/build/vmtest`, `0755 olafkfreund users`: the agents' VM workspace.
- **Build-dir:** `services.nixarchy-runner.buildDir = "/mnt/build/nix"`. If the disk is missing, builds fall back to
  `/`.
- **Runners:** each `github-runner-nixarchy*` unit gets `unitConfig.RequiresMountsFor = [ cfg.buildDir ]`, so a
  missing disk stops CI rather than filling `/`. Still four runners.
- **Workspace:** the path stays `/mnt/data/vmtest`, as a bind mount of `/mnt/build/vmtest`, with `fsType = "none"`
  and `bind nofail x-systemd.requires-mounts-for=/mnt/build`. nixarchy needs no change; this is the approved change
  to the intent.
- **Prune:** the prune service gets `unitConfig.RequiresMountsFor = [ cfg.vmImageDir ]` in the module, plus
  `ConditionPathIsMountPoint = "/mnt/data/vmtest"` on p620.
- **`scratch`:** its `fileSystems` entry goes and the cutover unmounts it. Its data stays.
- **Cutover:** under a hold. Announce on the bus, drain and stop the runners, copy twice, switch, start the mounts,
  then unmount `scratch`. Nothing old is deleted.

## Repo facts and traps

- **Where the module lines are:** `modules/services/nixarchy-runner.nix`:
  - the prune service is at lines 158–176, inside `systemd = { … }`;
  - the buildDir tmpfiles rule is at line 191;
  - `build-dir` and `TMPDIR` are at lines 208–209;
  - `services.github-runners` starts at line 255, with one runner per `suffix`.

  `RequiresMountsFor` is a `[Unit]` key, so set it through
  `systemd.services."github-runner-nixarchy${suffix}".unitConfig`, never `serviceOverrides`. Merge it into the
  existing `systemd` attribute rather than adding a second one.
- **Where the host lines are:**
  - `hosts/p620/nixos/hardware-configuration.nix`:
    - `fileSystems."/var/lib/nix-build"`: lines 80–90;
    - the existing bind `fileSystems."/mnt/img_pool/docker/volumes"` (the model for the new one): line 107;
    - the BFQ udev rule and its comment: lines 121–130.
  - `hosts/p620/configuration.nix`: `services.nixarchy-runner` is at lines 64–74.
- **Bus guard:** it matches words in command text, so commit and PR bodies go in files.
- **Commits:** never with backticks in `git commit -m`.
- **Worktrees:** do all work in `~/.config/nixos-3194`. Check that no nhs is running before touching
  `~/.config/nixos`.
- **p510** is not touched.

## Steps

1. **Prepare the disk** (lead). It's blank and unused, so this needs no hold, only a bus note.
   - Re-check: `readlink -f` of the by-id path, `smartctl -i` (serial QJC054R004014P221Q, 1,000,204,886,016 bytes),
     `lsblk` (no children), `wipefs -n` and `blkid -p` (empty), `findmnt` (not mounted). Stop if anything differs.
   - `sgdisk --zap-all`, then `sgdisk -n 1:0:0 -t 1:8300 -c 1:build` on the by-id path. Then `partprobe` and
     `udevadm settle`.
   - Re-check `…-part1`: it exists, its parent is that disk, and `wipefs -n` is empty.
   - `mkfs.ext4 -L build -m 0` on `…-part1`. Record the UUID from `blkid -s UUID -o value`.

   → **Verify:** `lsblk -f` shows the partition `build` on the Lexar, ext4, with the recorded UUID.

2. **Module** (codex), `modules/services/nixarchy-runner.nix`:
   - in the prune service, add `unitConfig.RequiresMountsFor = [ cfg.vmImageDir ];` next to the existing
     `ConditionPathIsDirectory`;
   - for each runner suffix, add `systemd.services."github-runner-nixarchy${suffix}".unitConfig.RequiresMountsFor =
     [ cfg.buildDir ];`, merged with the existing `systemd` set;
   - add a short comment on each saying why: a missing build disk must stop CI rather than send it to `/`, and the
     prune must never run against a hidden fallback copy.

   → **Verify:** `nix eval .#nixosConfigurations.p620.config.systemd.services.github-runner-nixarchy-2.unitConfig`
   shows the key. Then `just check-syntax`.

3. **Host** (coder):
   - **`hosts/p620/nixos/hardware-configuration.nix`:**
     - Replace the `/var/lib/nix-build` entry (lines 80–90) with `fileSystems."/mnt/build"`: the UUID from step 1,
       ext4, and the options above. Add a comment: Lexar EQ790 1 TB, #3194, `nofail` with the two `before` options
       and why.
     - Add `fileSystems."/mnt/data/vmtest"`, shaped like the line-107 bind. Add a comment covering the fixed path
       for nixarchy's `AGENTS.md` and the stale copy underneath when the disk is missing, with the `rsync -n`
       reconcile note.
     - Update the BFQ comment from "both NVMe disks" to all three.
   - **`hosts/p620/configuration.nix`:**
     - set `buildDir = "/mnt/build/nix"`, and update its comment to the new disk, still four runners;
     - add `systemd.services.nixarchy-vm-image-prune.unitConfig.ConditionPathIsMountPoint = "/mnt/data/vmtest";`;
     - add the tmpfiles rule `"d /mnt/build/vmtest 0755 olafkfreund users -"` to the host's existing tmpfiles list
       if there is one, otherwise a new one.

   → **Verify:** `just check-syntax`, `just test-host p620`, and `nix eval` of:
   - `nix.settings.build-dir`;
   - `fileSystems."/mnt/build".options`;
   - `fileSystems."/mnt/data/vmtest"`;
   - the prune service's `unitConfig`.

4. **PR** (lead): run the Codex and agy reviews of the diff, open the PR linking intent, spec and plan, and merge it
   when CI is green. Don't deploy yet.

5. **Cutover** (lead), under a hold:
   1. `just test-host p620` from main, so nothing is left to build.
   2. Post the hold on the bus. Wait until:
      - no nixarchy runner job is in progress (`gh api` for runners and jobs on `olafkfreund/nixarchy`);
      - no `omarchy-edge` run is in progress;
      - there are no `nixbld` processes.

      Then `systemctl stop 'github-runner-nixarchy*'`.
   3. Mount `…-part1` on `/mnt/build` by hand. Create `nix` (`0755 root root`) and `vmtest` (`0755 olafkfreund
      users`). Then `rsync -a -H -A -X /mnt/data/vmtest/ /mnt/build/vmtest/`.
   4. Check `fuser -vm` and `lsof +D /mnt/data/vmtest`, and that there are no `nixbld` processes. If anything is
      open, ask on the bus and wait. Then run the final `rsync` with `--delete` (into the new copy only) and
      unmount `/mnt/build`.
   5. `just p620`. Then `systemctl start mnt-build.mount mnt-data-vmtest.mount` and `systemd-tmpfiles --create`.
   6. `systemctl restart nix-daemon`. Check `fuser -vm /var/lib/nix-build` is empty, then `umount /var/lib/nix-build`.
   7. Run step 6's checks, `systemctl start` the four runners, and post "done" on the bus.

   **Traps:** a switch doesn't start new `nofail` mounts that nothing requires, and doesn't unmount a removed
   entry (5.5 and 5.6). Never delete `/mnt/data/vmtest`'s old contents or `scratch`'s.

6. **Verify** (lead):
   - `findmnt` on `/mnt/build` and `/mnt/data/vmtest`;
   - `nix config show build-dir` is `/mnt/build/nix`;
   - `findmnt /var/lib/nix-build` is empty;
   - a small `nix build --rebuild` shows its tree under `/mnt/build/nix`;
   - a razer build through p620 builds there;
   - the next runner job grows `df /mnt/build`;
   - `systemctl show -p RequiresMountsFor` on a runner lists `/mnt/build/nix`;
   - `lsblk` shows `scratch` unmounted;
   - no failed units.

   **Fallback test,** in a later quiet window announced on the bus:
   1. stop the runners, unmount the bind and `/mnt/build`, then `systemctl mask --runtime mnt-build.mount`;
   2. a runner fails to start;
   3. `systemctl start nixarchy-vm-image-prune` is skipped;
   4. a small `nix build` works on `/`;
   5. unmask, start the two mounts, then start the runners.

   Post the results on #3194.

## Rollback

- **Config:** revert the PR and `just p620`. The old `/var/lib/nix-build` entry comes back and mounts `scratch`
  again; its data is untouched. `/mnt/data/vmtest` shows the old copy again (unmount the bind first).
  - **Before switching back,** list what changed in the new workspace with
    `rsync -n -a /mnt/build/vmtest/ /mnt/data/vmtest/`, and copy back what is wanted.
- **Disk:** the new disk only holds copies, so nothing on it needs keeping for a rollback beyond that workspace
  check.
