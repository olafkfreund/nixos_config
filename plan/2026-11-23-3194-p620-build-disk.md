# Plan: a dedicated NVMe for builds and the GitHub runners on p620

## Approved decisions (from the spec)

- **Disk:** `/dev/disk/by-id/nvme-Lexar_SSD_EQ790_1TB_QJC054R004014P221Q` (DISK below). GPT, one partition with
  partition label `build` (PART = `DISK-part1`), ext4 with label `build`, `-m 0`, default inode density.
- **UUID:** chosen now, `06f7240e-8946-4547-90fc-3fbc8e711309`, and given to `mkfs.ext4 -U`. The config can then
  carry it before the disk is formatted, and formatting still happens inside the hold, as the spec orders.
- **Mount:** `/mnt/build` by that UUID, options `noatime`, `nofail`, `x-systemd.device-timeout=10s`,
  `x-systemd.before=systemd-tmpfiles-setup.service`, `x-systemd.before=nix-daemon.service`. TRIM is the existing
  weekly `fstrim`, with no `discard` option.
- **Directories:**
  - `/mnt/build/nix`, `0755 root root`: the build-dir;
  - `/mnt/build/vmtest`, `0755 olafkfreund users`: the agents' VM workspace.
- **Build-dir:** `services.nixarchy-runner.buildDir = "/mnt/build/nix"`. If the disk is missing, builds fall back to
  `/`.
- **Runners:** all four `github-runner-nixarchy*` units get `unitConfig.RequiresMountsFor = [ cfg.buildDir ]`.
  Still four runners, and runner state stays where it is.
- **Workspace:** `vmImageDir` stays `/mnt/data/vmtest`, a bind mount of `/mnt/build/vmtest` with `fsType = "none"`
  and options `bind`, `nofail`, `x-systemd.requires-mounts-for=/mnt/build`. It also waits for its parent
  `/mnt/data`. nixarchy needs no change; this is the approved change to the intent. When the disk is missing, the
  old copy shows and may diverge. Reconcile it before the bind hides it again.
- **Prune:** `unitConfig.RequiresMountsFor = [ cfg.vmImageDir ]` in the module, plus
  `ConditionPathIsMountPoint = "/mnt/data/vmtest"` on p620.
- **Unchanged:** `/nix/store`, its `min-free`/`max-free`, and the daemon's BFQ best-effort priority 7. Only the BFQ
  comment is updated.
- **`scratch`:** its `fileSystems` entry goes and the cutover unmounts it. Its data stays. Nothing old is deleted.

## Repo facts and traps

- **The module, `modules/services/nixarchy-runner.nix`:**
  - `systemd = { services.nixarchy-vm-image-prune = …; timers.… ; }` is at lines 157–186; the prune service is
    lines 158–177;
  - `systemd.tmpfiles.rules` is at line 190;
  - `systemd.services.nix-daemon.environment.TMPDIR` is at line 208, then `nix.settings.build-dir` at 209;
  - `services.github-runners` is built with `lib.listToAttrs` over the suffixes at line 255.

  A computed `systemd.services` set can't sit beside dotted `systemd.services.x` bindings. Restructure as in step 1.
- **The host files:**
  - `hosts/p620/configuration.nix`: `services.nixarchy-runner` is at lines 65–74, with `buildDir` at 72. There is
    already a `systemd = { services = { … }; };` block at lines 532–549. Put every host systemd addition inside it,
    never as dotted `systemd.…` elsewhere: the file's lines 330–335 warn against mixing the two.
  - `hosts/p620/nixos/hardware-configuration.nix`: `/var/lib/nix-build` is at lines 80–90, the bind used as the
    model is at line 107, and the BFQ comment and rule are at lines 127–129. `options` are lists of strings.
- **Bus guard:** it matches words in command text, so commit and PR bodies go in files. No backticks in `-m`.
- **Worktrees:** work in `~/.config/nixos-3194`. Before pulling into `~/.config/nixos`, check that no nhs is
  running.
- **p510** is not touched.

## Steps

1. **Module** (codex), `modules/services/nixarchy-runner.nix`. Restructure `systemd.services` as one
   `lib.mkMerge`, keeping every existing setting:

   ```nix
   systemd = {
     services = lib.mkMerge [
       {
         nixarchy-vm-image-prune = lib.mkIf (cfg.vmImageDir != null) {
           # (existing body) plus:
           unitConfig.RequiresMountsFor = [ cfg.vmImageDir ];
         };
         nix-daemon.environment.TMPDIR = cfg.buildDir;   # moved from line 208
       }
       (lib.listToAttrs (map (i: lib.nameValuePair "github-runner-nixarchy${suffix i}"
         { unitConfig.RequiresMountsFor = [ cfg.buildDir ]; }) (lib.range 1 cfg.instances)))
     ];
     timers.nixarchy-vm-image-prune = …;   # unchanged
     tmpfiles.rules = [ "d ${cfg.buildDir} 0755 root root -" ];   # moved from line 190
   };
   ```

   - Factor `suffix` into a `let` binding that both this and the `services.github-runners` map at line 255 use.
   - Keep `nix.settings.build-dir` and the comments. Add one short comment on each `RequiresMountsFor`: a missing
     build disk must stop CI rather than send it to `/`, and the prune must never run against a hidden fallback
     copy.

   → **Verify:** `just check-syntax`. Then `nix eval` of `unitConfig` for `github-runner-nixarchy`,
   `-nixarchy-2`, `-3` and `-4`, of `nixarchy-vm-image-prune.unitConfig`, and of
   `nix-daemon.environment.TMPDIR`, on p620.

   → **Verify:** `just check-syntax`, then `just test-host p620`. Then `nix eval` on p620 of:
   - `nix.settings.build-dir`, which must be `/mnt/build/nix`;
   - `fileSystems."/mnt/build"` and `fileSystems."/mnt/data/vmtest"`, in full;

3. **PR** (lead):
   - review the diff against steps 1–2, and run the Codex and agy reviews;
   - open the PR linking intent, spec and plan;
   - merge it when CI is green. Don't deploy: the config needs the formatted disk (step 4).

4. **Cutover** (lead), under a hold.
   1. Check that no nhs is running. Then, in `~/.config/nixos`, `git pull --ff-only` and `just test-host p620`, so
      the switch builds nothing.
   2. **Hold:** post on the bus that p620 builds and `/mnt/data/vmtest` are on hold until "done". Wait until:
      - no nixarchy job is in progress (`gh api repos/olafkfreund/nixarchy/actions/runners`, every runner
        `busy: false`);
      - no `omarchy-edge` run is in progress;
      - there are no `nixbld` processes.

      Then stop the four runners and the prune:

      ```bash
      systemctl stop github-runner-nixarchy github-runner-nixarchy-2 github-runner-nixarchy-3 github-runner-nixarchy-4 \
        nixarchy-vm-image-prune.timer nixarchy-vm-image-prune.service
      ```

      Confirm all six are inactive.
   3. **Disk checks, before any write.** Stop if anything differs:
      - `readlink -f DISK`;
      - `smartctl -i DISK` shows serial `QJC054R004014P221Q` and 1,000,204,886,016 bytes;
      - `lsblk -n DISK` has no children;
      - `wipefs -n DISK` and `blkid -p DISK` are empty;
      - `findmnt -S DISK` is empty;
      - `ls /sys/class/block/$(basename $(readlink -f DISK))/holders` is empty.
   4. **Partition:** `sgdisk -n 1:0:0 -t 1:8300 -c 1:build DISK`, then `partprobe DISK` and `udevadm settle`.
      Check that PART exists, that `lsblk -no PKNAME PART` is the same disk, and that `wipefs -n PART` is empty.
      Stop otherwise.
   5. **Format:** `mkfs.ext4 -L build -m 0 -U 06f7240e-8946-4547-90fc-3fbc8e711309 PART`. Check that
      `lsblk -o NAME,PARTLABEL,LABEL,FSTYPE,UUID DISK` shows `build`, `build`, ext4 and the UUID.
   6. **First copy:**
      - `mkdir -p /mnt/build`, then `mount PART /mnt/build`;
      - `install -d -m 0755 -o root -g root /mnt/build/nix` and
        `install -d -m 0755 -o olafkfreund -g users /mnt/build/vmtest`;
      - check `findmnt -no SOURCE,UUID /mnt/build` is PART with the UUID, and that `findmnt -no TARGET -T
        /mnt/data/vmtest` is `/mnt/data`;
      - `rsync -a -H -A -X /mnt/data/vmtest/ /mnt/build/vmtest/`, which must exit 0.
   7. **Final copy:** check that `lsof +D /mnt/data/vmtest` is empty (not `fuser -m`, which would report all of
      `/mnt/data`) and that there are no `nixbld` processes. If either check fails, ask on the bus and wait.
      Re-check both mounts as in 4.6. Run `rsync -a -H -A -X --delete /mnt/data/vmtest/ /mnt/build/vmtest/`, which
      must exit 0. Then `umount /mnt/build`.
   8. **Switch:** `just p620`, then:

      ```bash
      systemctl start mnt-build.mount mnt-data-vmtest.mount
      systemd-tmpfiles --create
      ```

      Check that `findmnt /mnt/build` shows the UUID, and that `findmnt -no SOURCE /mnt/data/vmtest` shows the
      bind of `/mnt/build/vmtest`.
   9. **Retire `scratch`:** `systemctl restart nix-daemon`, then `nix config show build-dir`, which must be
      `/mnt/build/nix`. Check `fuser -vm /var/lib/nix-build` is empty (it is a mount point here), then
      `umount /var/lib/nix-build`.
   10. **Resume:** start the four runners and the prune timer by name. Confirm the four runners are active and that
       `systemctl show -p RequiresMountsFor github-runner-nixarchy` lists `/mnt/build/nix`. Check for failed units.
       Post "done" on the bus.

   **Traps:**
   - a switch doesn't start new `nofail` mounts that nothing requires, and doesn't unmount removed entries (4.8 and
     4.9);
   - never delete the old `/mnt/data/vmtest` contents or `scratch`'s data.

5. **Follow-up checks** (lead), after the hold:
   - **Local build:** a small `nix build --rebuild` of a test derivation, with
     `ls /mnt/build/nix` showing its `nix-*` tree during the build.
   - **razer:** the next razer build via p620 shows its tree under `/mnt/build/nix`.
   - **nixarchy:** the next nixarchy VM-install job: `ls /mnt/build/nix` shows its tree while that runner is busy.
   - **`scratch`:** `lsblk` shows it unmounted. A read-only `mount -o ro` shows its contents are still there; then
     unmount it.
   - Post the results on #3194.

6. **Fallback test** (lead), in a later quiet window the owner approves, under the same hold as step 4.2:
   1. stop the runners and the prune timer; `umount /mnt/data/vmtest /mnt/build`; then
      `systemctl mask --runtime mnt-build.mount`;
   2. `systemd-tmpfiles --create` recreates `/mnt/build/nix` on `/`;
   3. `systemctl start github-runner-nixarchy` fails on `mnt-build.mount`;
   4. `systemctl start nixarchy-vm-image-prune` doesn't run (record the reason), and the old copy's file count is
      unchanged;
   5. a small `nix build --rebuild` builds, with its tree under `/mnt/build/nix` on `/` (`findmnt -T` shows `/`);
   6. **always, even if a check fails:** `systemctl unmask --runtime mnt-build.mount`, start the two mounts, check
      that `/mnt/build` on `/` holds only the empty `nix` tree tmpfiles made (remove it once unmounted, if
      anything), then start the runners and the timer. Post "done".

   The boot ordering and the 10 s timeout are covered by the next reboot: check
   `systemd-analyze critical-chain nix-daemon.service` shows it after `mnt-build.mount`.

## Rollback

1. Check `/mnt/build` is mounted. Unmount the bind first: `umount /mnt/data/vmtest`. While it is up, the old and
   new paths are the same directory, so `rsync -n` would compare a directory with itself.
2. Check `/mnt/data` is mounted. List what changed with `rsync -n -a -i /mnt/build/vmtest/ /mnt/data/vmtest/`, then
   copy back what is wanted. The Lexar may hold the only copy of work done after the cutover.
3. Revert the PR, pull, `just p620`.
4. Start the old mount, which a switch doesn't do: `mount /var/lib/nix-build`. Check it shows `scratch`'s UUID.
5. `systemctl restart nix-daemon`. Check `nix config show build-dir` is `/var/lib/nix-build`, and that a small build
   writes there.
6. `umount /mnt/build`. Start the runners and the prune timer. Post "done".

If a step fails partway, stop there, leave the runners stopped, and report on #3194. Every earlier state keeps
both copies of the workspace.
