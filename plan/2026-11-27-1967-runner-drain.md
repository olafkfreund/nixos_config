# Plan: p620 switches itself after a green edge, without killing CI jobs

Decisions carried from the spec: option 1; marker
`/var/lib/guarded-upgrade/runners-closed` with `ConditionPathExists=!` on the
four units; the upgrade drains under the deploy lock, defers on anything
ambiguous, reopens on every path, and publishes `verified` only after the
runners reconnect; `autoActivate` stays false until step 5.

Worktree `/mnt/data/vmtest/wt-nc-drain`, branch `feat/1967-runner-drain`.
Implementers never stage, commit, push, build, deploy, switch, or touch the
running runner services; the lead does all of that.

## Steps

1. **Listener drain patch** (codex). `pkgs/github-runner-drain/` (or beside
   the runner module): a patch against actions/runner v2.338.2's
   `src/Runner.Listener` (`Runner.cs`, `JobDispatcher.cs`) adding the drain
   request and acknowledgement file, applied with
   `services.github-runners.<n>.package = pkgs.github-runner.overrideAttrs`.
   Verify (lead): the package builds (package tier, behind the gate); a local
   runner run against a disposable repo drains while idle and while busy.
2. **Admission marker** (coder). `modules/services/nixarchy-runner.nix`: add
   the `ConditionPathExists=!` to the four units. Verify (lead): p620 toplevel
   builds; the unit files carry the condition; with the marker present,
   `systemctl start` of a runner does nothing (a transient test unit, not the
   real ones).
3. **Orchestration** (codex). `scripts/guarded_upgrade.py`: drain, wait,
   defer, activate, verify, reopen, publish, per the spec; interrupted
   transactions keep the marker. `scripts/test_guarded_upgrade.py`: fixtures
   for each path (all four acknowledge; one withholds; deadline; rollback;
   interrupted). Verify (lead): unit tests pass, each fails with its guard
   removed.
4. **Disposable-repository harness** (agy). `scripts/runner-drain-test/`: a
   script that registers four runners with a unique label against a disposable
   repository on an isolated host, dispatches the four scenarios, and records
   job IDs, attempts, status transitions, acknowledgements and unit start
   times. Verify (lead): the lead runs it; all four scenarios pass; the
   recording goes in the PR.
5. **Turn on** (lead). After step 4 passes and one manual drain on p620 with
   runners idle succeeds: `hosts/p620/configuration.nix`
   `features.guarded-upgrade.autoActivate = true`. Deploy p620 and razer with
   a bus announce. Close nixarchy#1967.

## Tests

Steps 1–4's verifications.

## Rollback

`autoActivate = false` on p620 (one line) stops unattended switching at once;
reverting the module change removes the condition; the runner package falls
back to nixpkgs' by dropping the override.
