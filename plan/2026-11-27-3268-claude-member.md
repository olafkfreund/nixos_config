# Plan: Claude Code as a herdr-team member

Decisions (approved spec): roles `claude-review` (reviewer.claude model and
effort, `--permission-mode plan`) and `claude-implement` (worker.claude,
`--permission-mode bypassPermissions`, plus the coder guard as a
`PreToolUse` `Bash` hook), kind `claude`, both backends. A new sink runs as
the member's `UserPromptSubmit` and `Stop` hooks (given with `--settings`)
and writes the same turn files as the Codex and agy members, with
`source: "claude"`. No API key, no `--bare`.

Revised after the Codex plan review: prompts and answers are paired by
`prompt_id`; the sink extracts the bare pointer from an hc envelope;
the trust question is never answered (see Deviations), only when the
visible screen shows it for this worktree, and readiness waits for it to
close; the bypass-consent screen is never answered (owner action);
reviewer checks cover `claude-review`; the guard path is a build-time
prefix so tests use a fixture.

## Steps

1. Sink `home/development/claude-sink.py` (+ `claude-sink-test.py`),
   packaged in `home/development/agent-run.nix` as `herdr-team-claude-sink`
   (`writeShellApplication` exec'ing python3; checkPhase runs the tests on
   the packaged script).
   - `herdr-team-claude-sink prompt|stop <turns-dir>`, hook JSON on stdin
     (read at most 1 MiB). The turns dir must be a real directory, not a
     symlink, owned by the caller, mode 0700. All opens use `O_NOFOLLOW`
     and `fstat` the descriptor (regular file, size bound) before reading.
     Always exit 0, print nothing.
   - Correlation: both events need a string `prompt_id` matching
     `^[A-Za-z0-9._-]{1,128}$` (Claude Code's common hook field); without
     it, do nothing. State file: `<turns>/.claude-input.<prompt_id>`.
   - `prompt`: take `.prompt`; if any line of it matches
     `^Request [0-9]+-[0-9]+: read \S+ and answer it in your reply\.$`
     (herdr-team's pointer, possibly inside an hc envelope), save exactly
     that line; otherwise save nothing. Exclusive temp file, `os.replace`.
   - `stop`: needs the state file for this `prompt_id` (else nothing).
     Reply = `.last_assistant_message` when it is a non-empty string;
     otherwise read `.transcript_path` (no-follow, regular, at most
     16 MiB) as JSONL, take the entries of the turn whose user entry has
     this `prompt_id` (or, when entries lack it, the last user entry whose
     text contains the saved pointer) up to the next user entry, and use the
     text blocks of the last assistant entry of that turn only if it is the
     last entry in the file; otherwise emit nothing (the transcript may
     lag). Write `<turns>/<uuid4>.json` = `{turn_id, input, reply, source: "claude"}`
     through an exclusive `.<id>.tmp` and a no-clobber `os.link` + unlink,
     refusing an existing or symlinked target; then remove the state file.
     The first Stop for a `prompt_id` publishes; a later one for the same
     id finds no state file and does nothing.
   - Tests: text-only reply; reply in `last_assistant_message`; transcript
     fallback over two assistant entries with a tool call between (last one
     wins); a lagging transcript (last entry not assistant) → nothing; a
     later unrelated user turn is not crossed; `submit A → submit B →
     stop A → stop B` gives two turns with the right pairs; second Stop for
     the same id → nothing; hc-enveloped prompt → bare pointer saved; a
     prompt without a pointer → nothing; missing `prompt_id`; non-0700 or
     symlinked turns dir; symlinked state file, transcript or target;
     non-JSON stdin; oversize transcript.
   → verify: `python3 home/development/claude-sink-test.py home/development/claude-sink.py`
   prints `ALL PASSED`; the package builds.

2. `modules/programs/claude-code-managed.nix`: beside
   `environment.etc."claude-code/.claude/agents/coder.md"`, add
   `environment.etc."claude-code/hooks/coder-guard".source = coderGuardScript;`.
   → verify: the p620 toplevel builds and
   `readlink -f result/etc/claude-code/hooks/coder-guard` is the packaged

   - `agent-run.nix` prefix: `claude_sink=<herdr-team-claude-sink bin>`,
     `claude_guard=/etc/claude-code/hooks/coder-guard`,
     `claude_review_model/effort`, `claude_worker_model/effort` from the role
     map; the sink joins `home.packages`. The test edits a copy of the
     built script to point `claude_guard` at a fixture.
   - Header and both `up_*` role checks gain `claude-review` and
     `claude-implement`; `wrapper=claude`; `kind=claude`; lifetime as
     `review` / `implement`. For `claude-implement`, refuse unless
     `$claude_guard` is executable. For both claude roles, refuse unless the

   - Treat `claude-review` like `review` wherever the code compares the role
     name for reviewer behaviour: the dirty-diff refusal and implementer
     exclusivity in both `up_*`, `worktree_busy` (~153) and `reminder`

   - Argv (both backends): write `$work/claude-settings.json` with jq:
     `skipDangerousModePermissionPrompt: false` is not set (leave Claude's
     own consent flow alone); `hooks.UserPromptSubmit` and `hooks.Stop`,
     each `[{"hooks":[{"type":"command","command": <cmd>}]}]` where `<cmd>`

     for `claude-implement` also `hooks.PreToolUse` =
     `[{"matcher":"Bash","hooks":[{"type":"command","command":"<quoted $claude_guard>"}]}]`.
     Then:

     ```bash
     argv=(agent-env env -u ANTHROPIC_API_KEY -u ANTHROPIC_API_KEY_FILE claude
       --model "$m" --effort "$e" --permission-mode "$mode" --settings "$work/claude-settings.json")
     ```

     with `$m` / `$e` from `--model` / `--effort` or the role defaults.

       fail with `outcome: "owner_action"` and reason

     - an hc status of `blocked` is not ready.
   - `send_prompt` / `interrupt_member`: kind `claude` takes the non-agy

   - Ask loop (~1105): also accept `.source == "claude"` (the exact pointer
     comparison stays).
   - `finish` (~1409): accept `claude-implement`.
   - Tests: the fake herdr keeps per-pane state (kind, settings path,

## Tests

The sink tests and herdr-team tests (both in the build), both host builds,
and the live smoke tests in step 4.

## Rollback

Revert the PR and switch again. Two effects outlive it: Claude Code
remembers a trusted worktree in its own user state, and herdr-team's
archived conversation records stay where `down` archives them.

## Deviations

- Step 1 (Codex): the pointer pattern also accepts the 16-character
  hexadecimal generation ids herdr-team uses today (`herdr-team.sh:483`),
  not only decimal ones; the tests cover it inside an hc envelope.
- Trust question (found by the coder before implementing step 3): Claude
  Code 2.1.332 builds the dialog with `cancelFirst` and focus on "No, exit"
  (or "No, continue without these permissions"), so Enter would end the
  member or drop its permissions. herdr-team therefore never answers it, on
  either backend, and fails with `owner_action`; the owner trusts a new
  worktree once by running `claude` in it. Spec updated in the same commit.
