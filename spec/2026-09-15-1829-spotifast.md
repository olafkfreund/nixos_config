# Spec: Spotifast native Spotify client on p620 and razer

## Design

Use the same wiring as herdr, so there is nothing new to learn.

1. `flake.nix`: add a `spotifast` input next to `herdr`:

   ```nix
   spotifast = {
     url = "github:crmne/spotifast";
     inputs.nixpkgs.follows = "nixpkgs";
     inputs.rust-overlay.follows = "rust-overlay";
   };
   ```

   The upstream flake has only these two inputs, so both follow ours and the
   lock stays at one nixpkgs.
2. `overlays/default.nix`: expose
   `spotifast = inputs.spotifast.packages.${prev.stdenv.hostPlatform.system}.default;`
   next to the `herdr` line.
3. `Users/olafkfreund/profile.nix`: add `pkgs.spotifast` to the package list.
   Only the p620 and razer home configs import this file, so p510 never gets
   the package.

Upstream's `packages.default` already installs `spotifast.desktop`, so it
appears in the launcher without any extra code. There is no configuration,
module or secret.

## Alternatives rejected

- **Upstream snippet as written** (`environment.systemPackages` in a host
  config): it would put a package inline in the host config, and it would
  split from the herdr pattern that `profile.nix` already uses for these same
  two hosts.
- **Package it under `pkgs/`**: it would duplicate a maintained upstream
  derivation, including the rust-toolchain pin and the libprojectM CMake
  build, and we would have to bump it by hand.
- **Not following nixpkgs**: it would add a second nixpkgs to the closure and
  waste the cache for its dependencies.

## Risks

- **Source build.** The package isn't in any cache. On razer, build on p620
  (`just deploy-via-p620 razer`).
- **Toolchain mismatch.** Upstream pins its compiler with
  `rust-toolchain.toml` through rust-overlay. If our pinned `rust-overlay` is
  too old for that version, evaluation fails. The fix is
  `nix flake update rust-overlay`, or dropping that one `follows`.
- **Upstream at HEAD.** The input tracks HEAD, not the `v0.8.0` tag, which is
  the same as herdr. A broken upstream commit only shows up at a flake update,
  and the build catches it.

## Verification

- `nix flake metadata` shows one nixpkgs node, and `spotifast` follows it.
- `just test-host p620` and `just test-host razer` build.
- In the built p620 closure, `bin/spotifast` and
  `share/applications/spotifast.desktop` exist.
- p510's configuration does not contain spotifast: no p510 build, evaluation
  only.
- After the user deploys, `spotifast` launches on p620.
