# Spec: global Claude standards for every Codex session

## Design

Extend the existing Home Manager generation in
`home/development/agent-rules.nix`. Codex continues to receive its global
instructions through `~/.codex/AGENTS.md`, across repositories. No launcher,
runtime synchronization service, or Codex configuration change is needed.

### Version-controlled source

Add `home/development/agent-rules/codex-standards.md`, copying the current
global `/home/olafkfreund/.claude/CLAUDE.md` with these explicit adaptations:

- Replace the Claude title and purpose with a Codex global standards title
  and purpose. Record the source and copy date instead of its stale update date.
- Retain the detailed PLAN, ACT, REFLECT, REVISE, mandatory behaviours,
  quality gates, output examples, and example cycle.
- Retain the approved-plan exception. Also retain the existing requirement
  to update `plan/` in the same commit as an implementation deviation.
- Retain the Agent OS standards paths, their on-demand loading, and the
  warning that project standards override the Rails/PostgreSQL/React defaults.
  If a referenced file is absent on another host, report that absence instead
  of inventing its contents.
- Identify `/plan-product`, `/create-spec`, `/execute-tasks`, and
  `/analyze-product` as Claude commands, not native Codex commands. In Codex,
  follow the included artifact workflow and available task-relevant skills.
- Replace the unavailable Codex `nixos-standards` skill reference with the
  installed `nixos` skill and applicable specialized NixOS skills.

This is an explicitly maintained copy, as requested, not a live import of a
home-directory file. Future edits to Claude's global file do not silently
change Codex. Updates to the tracked copy take effect after a rebuild.
Claude's file and its Syncthing ownership remain unchanged.

### Generated global instructions

Refactor the existing short concatenation only enough to share the common
global rules, managed workflow policy, and workflow templates between outputs.
Generate the Codex document in this order:

1. `home/development/agent-rules/global.md` (existing NixOS and Git rules).
2. `home/development/agent-rules/codex-standards.md` (detailed protocol).
3. The existing managed artifact policy, with its current sentence adaptation.
4. The existing artifact workflow skill body, with frontmatter stripped.

Codex's detailed protocol replaces its short `parr-protocol.txt` inclusion;
do not include both versions. Preserve the current generation assertions for
the managed policy and template frontmatter on both outputs.

Antigravity continues to receive byte-identical content from the current
sources, including the short PARR protocol. Its store path may change but its
instructions must not. Correct the module comment claiming Codex cannot load
skills: always-loaded policy is inlined so it does not depend on skill selection.

### Scope and activation

The module already participates in the developer Home Manager configuration.
The change is available to each host importing it after that host is rebuilt.
Validate and activate on p620 for this task; other hosts receive it through
their normal deployment workflow. Do not build or deploy p510 for this task.

Verify a fresh local Codex session outside the repository using the default
Codex home. Existing sessions should be restarted to load the new instructions.
Custom `CODEX_HOME` directories and cloud or remote environments are outside
this local installation's reach and need their own copy. No global override
file should mask the installed `AGENTS.md`.

## Alternatives rejected

- Overwrite `~/.codex/AGENTS.md` directly: it is Home Manager-managed and
  would lose the change at the next activation.
- Replace the entire generated file with Claude's file: loses existing NixOS
  rules and artifact approval gates.
- Read `~/.claude/CLAUDE.md` during evaluation: depends on a file outside
  the flake and breaks reproducibility.
- Link to Claude's mutable file or add a synchronization service: introduces
  an unmanaged dependency and unnecessary runtime machinery.
- Make Claude's global file declarative too: expands scope and changes its
  existing Syncthing ownership.

## Risks

- The maintained copy can drift from Claude; its provenance and update
  procedure must be explicit.
- More detailed instructions consume more context; check the generated size
  against the installed Codex configuration's document limit.
- Missing Agent OS files on another host must be reported, not assumed present.
- A refactor could alter Antigravity or omit workflow gates; compare its
  generated bytes and assert required content in Codex's output.
