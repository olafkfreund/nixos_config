# Spec: Remove zellij and tmate

## Design

Delete zellij at every layer it reaches, from the flake input down to the
docs. Every reference is listed, so the finished diff can be checked
against it.

### Module and option

- Delete `home/shell/zellij/` entirely: `default.nix`,
  `default_layout.nix`, `zjstatus.nix` and `README.md`.
- `home/shell/default.nix`: drop the `./zellij/default.nix` import. This
  removes the `multiplexer.zellij` option. Anything still setting it fails
  evaluation, which is how the removal proves itself complete.

### Feature flag

- `Users/common/features.nix`: drop
  `multiplexers.zellij = mkEnableOption ...`.
- `Users/common/features-impl.nix`: drop
  `zellij.enable = cfg.multiplexers.zellij;`.
- Setters of the flag, each loses its `zellij` line:
  `Users/olafkfreund/profile.nix` (`zellij = mkDefault false` and its
  comment), `Users/olafkfreund/p620_home.nix` (and its comment),
  `Users/olafkfreund/razer_home.nix` (and its comment),
  `Users/olafkfreund/p510_home.nix`,
  `home/profiles/developer/default.nix` and
  `home/profiles/server-admin/default.nix`.

### Flake and zjstatus

- `flake.nix`: drop the `zjstatus.url` input, `zjstatus` from the outputs
  arguments, `./home/shell/zellij/zjstatus.nix` from the shared module list
  (it is an empty stub that every host imports), and `zjstatus` from
  Home Manager's `extraSpecialArgs`.
- `overlays/default.nix`: drop the overlay that defines `pkgs.zjstatus`.
- `flake.lock`: drop the `zjstatus` node with `nix flake lock`, which
  prunes inputs that are no longer declared. Do not run `nix flake update`
  here: this change must not move any other input.

### Bare packages

- `home/desktop/terminals/default.nix`: drop `zellij` from
  `home.packages`. tmux stays.
- `modules/nixos/packages/host-specific/laptop-packages.nix`: drop
  `zellij # Better than tmux for mobility`.

### Dead host files

`hosts/p620/home-manager-options.nix` and
`hosts/razer/home-manager-options.nix` are imported nowhere, so their
settings never take effect. Drop only their zellij lines, so a repo-wide
grep comes back clean. Deleting these two files is a separate question
and out of scope here.

### Docs and tool config

- `README.md` (two lists) and `docs/architecture/theming.md`: remove
  Zellij from the Stylix-surface lists. Zellij gets its colours from the
  deleted module, so no theming code changes.
- `home/shell/README.md`: drop the `zellij/` bullet.
- `.agent-os/product/{mission,roadmap,tech-stack}.md`: remove Zellij from
  the shell-environment descriptions. The roadmap entry
  `Modern Zellij multiplexer setup` is removed rather than unchecked,
  because the feature is gone rather than undone.
- `.typos.toml`: drop the `zellij` allow-list entry.
- `.claude/settings.local.json` and `.gemini/settings.local.json`: drop
  `Bash(zellij:*)`.
- `intent/` and `spec/` for this task keep their mentions: they are the
  record.

### Hosts

Aliases (`zj*`) and `~/.config/zellij/layouts/*.kdl` are Home
Manager-managed, so the next activation removes them. No manual cleanup,
as the intent proposed.

## Alternatives rejected

- **Disable the flag everywhere and keep the module.** That leaves the
  flake input, the stub module every host imports, and the bare packages,
  which is exactly the dead wiring the intent wants gone. The tmate
  breakage came from a disabled-by-default corner in the same way.
- **Keep `zjstatus` for some future use.** Nothing else consumes it, and
  it can be added back from upstream in one line if that ever changes.
- **Delete the two unimported `home-manager-options.nix` files as well.**
  They may hold settings someone means to wire up later. That is a
  separate decision from zellij.

## Risks

- **A missed setter.** Removing the option turns any leftover
  `multiplexers.zellij` or `multiplexer.zellij` into an evaluation error.
  That is caught at eval time on p620, razer and p510 before anything is
  deployed, and never fails at runtime.
- **The lock moves more than zjstatus.** `nix flake lock` only prunes. The
  diff should remove `zjstatus` and the nodes only it uses (today
  `crane_2`, `flake-utils_7`, `nixpkgs_12`, `rust-overlay_5`), and no
  locked rev should change.
- **Something runs zellij at startup.** A grep found no terminal profile,
  keybinding or autostart that launches zellij. If one exists outside
  Nix, it fails with "command not found", which is harmless and visible.
- **p510.** It sets the flag today, so its config changes. It is evaluated
  here and deployed only when the user asks.

## Verification

- `grep -rni 'zellij\|zjstatus\|tmate' --exclude-dir=.git .` returns only
  `intent/`, `spec/` and `plan/` for this task.
- `nix eval ...toplevel.drvPath` passes for p620, razer and p510.
- The `flake.lock` diff removes only `zjstatus` and its private nodes;
  no remaining node's `rev` changes.
- `just test-host p620` builds.
- After a deploy, `command -v zellij` finds nothing on the deployed host.
- CI `check-configurations` passes for all three hosts.
