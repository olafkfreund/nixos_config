## Alternatives rejected

- **Crash watcher: mask the unit for the sddm user.** It's per-host state and
  breaks again on any new greeter user. A unit condition fixes it at the
  source.
- **omarecorder: create `state.json` at login.** That fakes the CLI's state.
  Silencing the expected failure is the honest fix.
- **Patch stale items blind (winvm, hyprforge, ai-mirror):** the logged lines
  no longer exist, so the patches would target code that has moved.
- **Remove omarecorder:** not in your removal list.

## Risks

- **Item 1 lands on p510 too** (nixarchy is flake-wide). It's only a start
  condition, but p510's deploy stays your call.
- **Item 2** changes a file nixarchy builds into the shell tree. A bad edit
  breaks every panel load, so it's verified with nixarchy's own session check
  (`checks.session`).
- **Item 5:** a new flake input. The winvm module expects the plugin under the
  same id, `nixarchy.winvm`, so the hand copy must be moved first, or nixarchy
  keeps the real directory ("your own directory, not replacing it").
- **Upstream PRs** are outward-facing; each text gets your OK first.
