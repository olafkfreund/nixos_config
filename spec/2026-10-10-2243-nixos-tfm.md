# Spec: package tfm-tui as the nixos-tfm flake and install it on p620 and razer

## Design

Two deliverables. The first is a new public repo, `github:olafkfreund/nixos-tfm`,
shaped like `nix-craftapps`. The second is a small wrapper module in this repo
that consumes it.

### 1. `nixos-tfm` repo layout

```text
flake.nix            packages, overlay, nixosModules, homeManagerModules, checks, formatter
package.nix          the derivation (callPackage-able)
sources.json         { version, x86_64-linux: {url, hash}, aarch64-linux: {url, hash} }
modules/common.nix   options shared by both modules
modules/nixos.nix    environment.systemPackages
modules/home-manager.nix  home.packages + settings seeding
scripts/update.sh    rewrites sources.json from the latest GitHub release
.github/workflows/ci.yml      nix flake check on x86_64 + aarch64 runners
.github/workflows/update.yml  daily: update.sh → flake check → PR
README.md            what it is, Getting started, options, update, how it is built
LICENSE              MIT (upstream tfm is MIT)
```

`flake.nix` has one input, `nixpkgs` (nixos-unstable), and supports
`x86_64-linux` and `aarch64-linux`. Outputs:

- `packages.<system>.{tfm,default}`
- `overlays.default` (adds `pkgs.tfm`)
- `nixosModules.default` and `homeManagerModules.default`
- `checks` and `formatter` (nixfmt)

### 2. Package (`package.nix`)

- `fetchurl` the release asset `tfm-<arch>-linux.gz`, using the per-arch hash
  from `sources.json`. The upstream `.sha256` sidecar is the source of truth;
  `update.sh` converts it to SRI.
- `gunzip` the asset, install it as `$out/libexec/tfm`, and run
  `patchelf --set-interpreter "$(cat $NIX_CC/nix-support/dynamic-linker)"`.
  The binary's only `NEEDED` libraries are glibc's (libc, libm, libdl,
  libpthread, ld-linux). The NixOS loader resolves them from its own glibc,
  which the p620 probe confirmed: `--version` works and the UI ran for 5
  seconds with no errors.
- Use `patchelf` only, not `autoPatchelfHook`. Set `dontStrip = true`: the app
  is an embedded payload in the ELF `.bun` section, and stripping or
  rewriting more than the interpreter is an untested risk.
- `makeWrapper $out/libexec/tfm $out/bin/tfm`:
  - `--set-default TFM_FFMPEG ${ffmpeg}/bin/ffmpeg` when `withFFmpeg` is set.
    tfm checks `$TFM_FFMPEG` before its sidecar and never reads `PATH` for
    ffmpeg (`src/fs/videobin.ts`).
  - `--suffix PATH : ${lib.makeBinPath extraPackages}`, so system tools still
    win and the helpers only fill gaps.
- Arguments: `withFFmpeg ? true`, `ffmpeg ? ffmpeg-headless`,
  `extraPackages ? [ unzip zip p7zip ]`. Archives are a core feature; the
  other optional tools (`xdg-open`, `gio`, `udisksctl`, `wl-clipboard`,
  `magick`) are normally present on a desktop, so they are documented rather
  than bundled.
- `meta`: MIT licence, Linux only, `mainProgram = "tfm"`,
  `sourceProvenance = binaryNativeCode`.

### 3. Module options (`modules/common.nix`)

These options are under `programs.tfm` in both modules:

| Option | Type | Default |
| --- | --- | --- |
| `enable` | bool | `false` |
| `package` | package | `pkgs.tfm` from this flake |
| `ffmpeg.enable` | bool | `true` |
| `ffmpeg.package` | package | `pkgs.ffmpeg-headless` |
| `extraPackages` | list of package | `[ unzip zip p7zip ]` |
| `finalPackage` | package (read-only) | `package.override { withFFmpeg; ffmpeg; extraPackages; }` |

The NixOS module adds `cfg.finalPackage` to `environment.systemPackages`.

### 4. Home Manager only

- `settings`: an attribute set in TOML format (`pkgs.formats.toml`),
  free-form. Example: `{ ui."view-mode" = "list"; theme.name = "..."; }`.
  Keys are the upstream ones from `config.example.toml`.
- `forceSettings`: bool, default `false`.

When `settings != { }`, a `home.activation.tfmConfig` step runs after
`writeBoundary`. Let `$f` be `${XDG_CONFIG_HOME:-~/.config}/tfm/config.toml`.

- If `$f` is missing, or `forceSettings` is set: replace a symlink at `$f` if
  there is one, then `install -Dm644` the generated TOML there. The result is
  a regular, writable file.
- Otherwise leave `$f` alone. tfm's Settings screen owns it from then on.
- Use `run` and `$DRY_RUN_CMD` so `home-manager switch --dry-run` stays dry.

The NixOS module has no `settings`, because a system module cannot reach a
user's `~/.config`.

### 5. Updates

`scripts/update.sh`:

1. `gh api repos/clarkarch/tfm-tui/releases/latest`, taking the newest
   non-prerelease tag.
2. If it equals `sources.json`'s `version`, exit 0 with no change.
3. Fetch each arch's `.gz.sha256`, convert it to SRI
   (`nix hash convert --hash-algo sha256 --to sri`), and write `sources.json`.

`update.yml` runs daily and on `workflow_dispatch`. It bumps `nixpkgs` on
Mondays, runs `update.sh` and `nix flake check -L`, then opens a PR with
`peter-evans/create-pull-request`. It ends with `gh workflow run ci.yml` on the
branch, the same trick nix-craftapps uses, because PRs from `GITHUB_TOKEN` do
not trigger CI.

### 6. Checks (`nix flake check`)

- `package`: builds; `tfm --version` prints `tfm <version>`; the wrapper
  contains `TFM_FFMPEG`.
- `module`: a `lib.nixosSystem` with `programs.tfm.enable = true;
  ffmpeg.enable = false;` asserts that the final package is in
  `environment.systemPackages` and has no `TFM_FFMPEG`.
- No Home Manager evaluation check, to avoid a `home-manager` input in a
  public flake. This repo's p620 build exercises the Home Manager module.

### 7. Consuming it here

- `flake.nix`: input `nixos-tfm = { url = "github:olafkfreund/nixos-tfm";
  inputs.nixpkgs.follows = "nixpkgs"; };`, placed next to `nix-craftapps`.
- `modules/desktop/tfm.nix`, imported from `modules/desktop/default.nix` next
  to `./craftapps.nix`:
  - `options.features.tfm.enable` (mkEnableOption).
  - `options.features.tfm.settings` (attrs, default `{ }`), passed through.
  - When enabled:
    `home-manager.sharedModules = [ inputs.nixos-tfm.homeManagerModules.default
    { programs.tfm = { enable = true; inherit (cfg) settings; }; } ];`
  - It installs per user through Home Manager, so seeded settings are
    possible; nothing is added at system level.
- `hosts/p620/configuration.nix`: `features.tfm.enable = true;` next to
  `features.craftapps`. A small `settings` block seeds a config for the test,
  for example `ui."preview-enabled" = true;`.
- razer: the same line in `hosts/razer/configuration.nix`. It is a separate
  step, done only after p620 is verified and the user agrees.
- Docs: `docs/applications/tfm.md`, linked from the nav in both `mkdocs.yml`
  and `mkdocs-full.yml`.

## Alternatives rejected

- **Build from source with Bun.** The user chose the release binary. A source
  build needs Bun 1.4 plus a fixed-output `node_modules` (opentui native
  library, `ffmpeg-static` postinstall). It is fragile and buys nothing for a
  personal install.
- **`autoPatchelfHook`.** Unnecessary, since only glibc is needed. Rewriting
  more of an ELF that carries a Bun payload is an untested risk.
- **A read-only `xdg.configFile` link for config.** tfm's Settings screen
  renames over the file, which breaks the link, and Home Manager then complains
  at the next switch.
- **Bundling the upstream ffmpeg sidecar.** It is another 68 MB binary blob
  per arch; nixpkgs' `ffmpeg-headless` does the same job and is cached.
- **System-wide install on p620 through the NixOS module.** This would work,
  but the user wants seeded config, which needs Home Manager. Installing
  through both would put tfm in two profiles.
- **Our own `home-manager` flake input in `nixos-tfm`, for checks.** It adds a
  heavy input to a public flake for one eval check that this repo's build
  already covers.

## Risks

- **A future Bun release changes the payload layout** so that interpreter
  patching breaks it. Mitigation: the `--version` check runs in CI on every
  update PR, so a broken release never merges.
- **The opentui native library is extracted at runtime** (to a temporary
  directory) and `dlopen`ed. It worked in the probe, but it depends on the
  library needing only glibc. The p620 test runs the full UI, not just
  `--version`.
- **Seeding writes into a user-owned file.** It writes only when the file is
  missing or `forceSettings` is set, so an existing config is never touched
  silently.
- **A daily PR could carry a broken upstream release.** It merges only if
  `flake check` passes; a human merges.
- **p620 deploy:** a new package plus Home Manager changes only, with no
  service or kernel change. razer builds on p620. p510 is untouched.

## Verification

1. `nixos-tfm`: `nix flake check -L` passes locally on p620 (x86_64) and in
   CI on both arches. `nix run github:olafkfreund/nixos-tfm -- --version`
   prints `tfm 1.0.0`.
2. This repo: `just check-syntax`, and `just test-host p620` and `razer` build.
   CI `check-configurations` passes on all three hosts. p510 evaluates
   because it imports the option with the feature off.
3. p620 after deploy:
   - `command -v tfm` resolves to the Home Manager profile.
   - `tfm --version` prints `tfm 1.0.0`.
   - `~/.config/tfm/config.toml` is a regular, writable file containing the
     seeded key.
   - `tfm` opens the UI in the terminal, with a video file showing a
     thumbnail (proving `TFM_FFMPEG` works).
   - Changing a setting in tfm's Settings screen persists, and the next
     Home Manager activation leaves it alone.
4. razer, after approval: the same as step 3.
