# Spec: a first agent-bus read returns the newest messages

## Design

Add one helper, `_page(client, room_id, key, limit)`, used by both
`read_new` (key: the agent name) and `peek` (key: name + `\0peek`):

- With no cursor: `dir=b`, reverse the chunk, and store the response's
  `start` token (the live end) as the cursor.
- With a cursor: `dir=f` and `from=cursor`; store `end` when present, as
  today.

This is the same code as nixarchy#1275, so the two copies stay identical in
this part.

## Alternatives rejected

- `/sync` with a filter for the first read: another token format and code
  path, for a one-call difference.
- Calling `recent` first: two requests, plus a race between them.

## Risks

A homeserver that omits `start` on `dir=b`: no cursor is stored, and the
next call repeats the newest page. That loses nothing.

## Verification

- `test_agent_bus_mcp.py` gains a case: the first `read_new` sends
  `dir=b` with no `from` and returns the newest two in order, and the
  second sends `dir=f` from `start`. It must be seen failing on the
  current code.
- `nix build .#agent-bus-mcp`: the package's checkPhase runs the tests.
- The live check already done for nixarchy#1275 used this exact function
  against the real homeserver.
