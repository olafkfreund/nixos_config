# Spec: install Flow Desktop via the nixos-FlowTube flake

## Design

**The flake, `github:olafkfreund/nixos-FlowTube`, in its own repo (done):**

- `package.nix` builds Flow-Tube/Flow-Desktop v0.1.0-beta2 from source:
  Tauri 2 via `cargo-tauri.hook`, the frontend via `fetchPnpmDeps` and
  pnpm 11, wrapped by `wrapGAppsHook3`. It carries GStreamer base, good, bad,
  ugly and libav, and sets `FLOW_NODE` (nodejs-slim 22) and
  `FLOW_INTEGRITY_SCRIPT` for the BotGuard sidecar.
- Two upstream behaviours are patched out: the self-updater (it would replace
  a read-only store path), and runtime `flow://` registration (it wrote
  `~/.local/share/applications/.flow-wrapped-handler.desktop` pointing at the
  unwrapped store binary). The packaged `Flow.desktop` declares
  `x-scheme-handler/flow`, so the profile's `mimeinfo.cache` routes the
  scheme.
- `homeManagerModules.default` offers `programs.flow-desktop.enable` and
  `programs.flow-desktop.package`.
- Its CI builds on x86_64 and aarch64 and launches the app under Xvfb, and
  passes only if the frontend rendered. A daily workflow opens an update PR
  when upstream releases.

**In this repo**, mirroring `modules/desktop/tfm.nix` (#2243), which is the
same shape: our own flake that ships a Home Manager module.

1. `flake.nix` gains a new input, next to `nixos-tfm`:

   ```nix
   flowtube = {
     url = "github:olafkfreund/nixos-FlowTube";
     inputs.nixpkgs.follows = "nixpkgs";
   };
   ```

2. A new file, `modules/desktop/flow-desktop.nix`:

   ```nix
   # Flow Desktop YouTube client (Issue #2317), from the nixos-FlowTube flake.
   { config, lib, inputs, ... }:
   let
     cfg = config.features.flow-desktop;
   in
   {
     options.features.flow-desktop.enable =
       lib.mkEnableOption "Flow Desktop, a privacy-respecting YouTube client";

     config = lib.mkIf cfg.enable {
       home-manager.sharedModules = [
         inputs.flowtube.homeManagerModules.default
         { programs.flow-desktop.enable = true; }
       ];
     };
   }
   ```

   `modules/desktop/default.nix` imports it, after `./tfm.nix`.
3. `hosts/p620/configuration.nix` and `hosts/razer/configuration.nix` set
   `features.flow-desktop.enable = true;` next to `features.tfm`.

`sharedModules` reaches every user on the host. Each host's `hostUsers` lists
only `olafkfreund`, as tfm already relies on. p510 never sets the flag. The
HM module is imported only inside `mkIf`, so p510 neither evaluates it nor
builds it, and its toplevel drvPath must not change.

## Alternatives rejected

- **`pkgs.flow-desktop` in `Users/olafkfreund/profile.nix`, like herdr:** it
  has no per-host switch. The profile is shared by the interactive hosts, so
  enabling it would need a host conditional in the profile, which is the job
  the feature flag already does.
- **The flake's overlay in `environment.systemPackages`:** it skips the HM
  module the flake was written to provide, and installs the app for every
  user.
- **No `follows`:** a second nixpkgs evaluation and a WebKitGTK/GStreamer
  stack that differs from the session's. Verified: the package builds against
  our pinned nixpkgs `7fd4004` without a hash change.
- **Upstream's AppImage or `.deb`:** opaque binaries with a bundled media
  framework and a self-updater, which is what building from source avoids.

## Risks

- **Build time.** There is no binary cache: about 23 minutes on a CI runner,
  and less on p620. razer must not build it, so it deploys through
  `just deploy-via-p620 razer`. The package is already built on p620 against
  our pin, so the p620 build reuses that store path until the pin moves.
- **The pnpm-deps hash depends on the pnpm in nixpkgs.** A future
  `nix flake update` that changes `pnpm_11` could make the fixed-output hash
  mismatch, and the host build would fail. The flake's CI uses its own lock,
  so it would not catch that. Mitigation: the failure is loud and happens at
  build time, before any switch. The fix is a hash bump in nixos-FlowTube.
- **NVIDIA + Wayland on razer (Optimus).** WebKitGTK may render blank on the
  first launch. Upstream's crash sentinel escalates the workarounds on the
  next launch: DMABUF off, then software compositing, then X11.
- **Beta software that talks to YouTube.** Playback can break when YouTube
  changes. The daily update PR is the remedy.

## Verification

1. Eval: `nix eval .#nixosConfigurations.{p620,razer}.config.home-manager.users.olafkfreund.programs.flow-desktop.enable`
   returns `true`. p510's toplevel drvPath is identical before and after.
2. Build: `just test-host p620` and `just test-host razer`, the latter built
   on p620.
3. After deploying p620: Flow appears in the launcher and starts.
   `xdg-mime query default x-scheme-handler/flow` names `Flow.desktop`. A
   video plays, and the log shows
   `gstreamer_decoder_probe avdec_h264="present"`.
4. No file matching `~/.local/share/applications/*flow*-handler.desktop` is
   created.
