# Spec: K3D_FIX_DNS for every k3d call, reattach a detached serverlb

## Design

In the bootstrap script of `modules/containers/k3d.nix`:

1. Put one `export K3D_FIX_DNS=0` near the top of the script, with a one-line
   why-comment. It then covers create, both `k3d cluster start` calls and stop.
   The create-only prefix and its DNS-fix comment are replaced accordingly;
   the serverlb/nginx explanation of the resolver mount stays.
2. In the self-heal loop, before `k3d cluster start`, if
   `docker inspect -f '{{json .NetworkSettings.Networks}}' k3d-$CLUSTER-serverlb`
   does not contain `k3d-$CLUSTER`, run
   `docker network connect "k3d-$CLUSTER" "k3d-$CLUSTER-serverlb" || true` and
   log it.

## Alternatives rejected

- Prefix `K3D_FIX_DNS=0` on each call: easy to miss on the next call added.
- Restart the whole cluster via `docker restart` only: does not fix the DNS
  failure on `k3d cluster start`.

## Risks

Low. The export only disables a k3d fix the nodes already opt out of on create.
The reconnect is a no-op when the LB is attached and guarded by `|| true`.
Affects p620 only.

## Verification

Build the rendered script derivation, grep for the export and the reconnect,
run `bash -n` on it. No deploy.
