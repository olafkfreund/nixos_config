# Spec: nixarchy-meetingai meeting copilot on p620

## Decisions (from the approved intent)

1. `ollamaCloud.keyFile` (raw token) in the meetingai module, pointed at
   `/run/agenix/api-ollama`.
2. The bar widget goes in the right section, next to meeting-mode.
3. The module's default keybindings (`SUPER+ALT+M` overlay, `SUPER+ALT+R`
   record, `SUPER+ALT+SHIFT+R` stop, `SUPER+ALT+SHIFT+M` mic,
   `SUPER+ALT+S` system audio, `SUPER+ALT+SHIFT+S` screenshot).

## Design

### In this repo

- **`flake.nix`:** a new input next to `nixarchy-meeting-mode`:

  ```nix
  nixarchy-meetingai = {
    url = "github:olafkfreund/nixarchy-meetingai/refactor/omarchy-quickshell-rewrite";
    inputs.nixpkgs.follows = "nixpkgs";
  };
  ```

  `nix flake lock --update-input nixarchy-meetingai` pins it.
- **`hosts/common/nixos/omarchy-meetingai.nix`** (new), same shape as
  `omarchy-meeting-mode.nix`:

  ```nix
  { inputs, ... }:
  {
    home-manager.users.olafkfreund = {
      imports = [ inputs.nixarchy-meetingai.homeManagerModules.default ];
      programs.nixarchy-meetingai = {
        enable = true;
        ollamaCloud.keyFile = "/run/agenix/api-ollama";
      };
    };
  }
  ```

  The header comment lists the two one-time steps below, as the other
  plugin files do.
- **`hosts/p620/nixos/nixarchy.nix`:** imports the new file next to
  `omarchy-meeting-mode.nix`.

### In meetingai (its own repo, before this PR)

- **`ollamaCloud.keyFile`** (nullable string, outside the store): the
  daemon service gets `LoadCredential=ollama:<path>`, and the daemon reads
  the key from `$CREDENTIALS_DIRECTORY/ollama` at start (trimmed), before
  falling back to `OLLAMA_API_KEY` and the vault. The existing
  `environmentFile` option stays.
- **Plugin through `programs.nixarchy.plugins`:** when
  `programs.nixarchy` exists, the module sets
  `programs.nixarchy.plugins."nixarchy.meetingai".src` instead of writing
  `~/.config/omarchy/plugins/nixarchy.meetingai` itself, so nixarchy
  validates the manifest at build time like every other plugin here.
- These go through meetingai's plan as a small deviation, then the branch
  is pushed to GitHub so this flake can lock it.

### One-time steps after the first deploy (owner's desktop, like the other plugins)

1. `omarchy plugin enable nixarchy.meetingai --section right`: nixarchy
   installs plugins but never enables them; the shell records the choice.
2. Add `pcall(require, "hypr.meetingai-binds")` to
   `~/.config/hypr/bindings.lua` (user-owned), as for `meet-binds`, `gog-binds`
   and `ai-mirror-binds`.

### Services and first run

- User services `nixarchy-meetingai.service` (daemon) and
  `nixarchy-meetingai-whisper.service` (whisper.cpp Vulkan build,
  large-v3-turbo model, ~1.6 GB downloaded once at build time by a fixed
  hash). The daemon's PATH is the user and system profiles, so `claude`,
  `codex`, `agy`, `opencode` resolve as in a shell.
- No new secrets, no changes to `secrets.nix` or other hosts.

## Alternatives rejected

- **A new agenix secret in `KEY=value` form:** duplicates `api-ollama`.
- **A local `git+file` input:** only p620 has the path, so other hosts'
  evaluations could break on the lock.
- **Writing `bindings.lua` or `shell.json` from Nix:** both are user-owned
  here; every other plugin uses the one-time step.

## Risks

- **First build time:** whisper.cpp with Vulkan and the 1.6 GB model.
- **Branch input:** the input tracks a branch, so `nix flake update` moves
  it; pin to a commit if that becomes a problem.
- **GPU:** whisper and the RX 7900 XT are shared with Ollama; heavy
  local models plus transcription may compete for VRAM.
- **Untested end to end:** real-call detection still uses meeting-mode's
  current behaviour until the call-detection work lands.

## Verification

- `nix flake check` and `nixos-rebuild build --flake .#p620` in the
  worktree.
- After deploy (`just` recipe from `main`): both user services active,
  `nixarchy-meetingai ctl state.get` answers, the whisper server answers on
  127.0.0.1:8178, the overlay opens with `SUPER+ALT+M`, a typed question gets
  an answer, a 30-second recording produces a transcript and notes, and
  `providers.status` shows Ollama Cloud as ready without typing a key.
