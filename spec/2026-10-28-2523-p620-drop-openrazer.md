# Spec: drop openrazer from p620

## Design

Make `ps.openrazer` in `user-python3` conditional, and let the host's NixOS
setting decide.

- `pkgs/default.nix`: wrap `user-python3` in `pkgs.callPackage` with a
  `withOpenrazer ? true` argument and add `ps.openrazer` through
  `lib.optional withOpenrazer`. The default keeps today's derivation for any
  other consumer, and `callPackage` makes it `.override`-able.
- `Users/olafkfreund/profile.nix`: bind once in `let`:
  `userPython3 = pkgs.customPkgs.user-python3.override { withOpenrazer =
  osConfig.hardware.openrazer.enable; }`, and use it at all three call sites
  (`home.packages`, the gitlab and github `defaultPluginSet` overrides) so the
  profile still holds exactly one python3.

`hardware.openrazer.enable` is true on razer (`hosts/razer/nixos/laptop.nix`)
and false on p620, so it states exactly "this host has Razer hardware".

## Alternatives rejected

- Mask the unit with `/dev/null` in `p620_home.nix`: one line, but it leaves
  the unused library and daemon in the closure. The user chose real removal.
- A new Home Manager option for the flag: duplicates `hardware.openrazer`.
- Two named packages (`user-python3`, `user-python3-razer`): duplicates the
  package list.

## Risks

- `osConfig` is missing if `profile.nix` is ever evaluated as standalone Home
  Manager. Not the case here: Home Manager is a flake module, and other home
  modules already read `osConfig`.
- If a call site is missed, p620's buildEnv collides on `bin/python3`. The
  host build catches it.
- razer's closure must not change: the default and razer's value are both true.

## Verification

- p620: the home-manager path has no `openrazer` in its closure, and
  `nix build` of the p620 toplevel succeeds.
- razer: the `user-python3` out path is identical before and after, and the
  toplevel builds.
- After deploying to p620: `systemctl --user status openrazer-daemon` reports
  the unit as not found.
