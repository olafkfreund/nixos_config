# Spec: hello-lock lock screen on p620 and razer

## Design

### 1. Package: `pkgs/hello-lock/default.nix`

A `stdenvNoCC.mkDerivation`, registered in `pkgs/default.nix` as
`hello-lock = pkgs.callPackage ./hello-lock { };`, next to `omateams`.

- **Source:** `fetchFromGitHub` with owner `denonmaryland`, repo `hello-lock`,
  rev `b52d2c2f34cb44e85dd950148ec41696f300c594` and its hash.
  That rev is upstream HEAD on 2026-11-02, the one previewed. `version`
  comes from `manifest.json` (`0.5.3`). A header comment gives the bump
  command, as in `pkgs/omateams`.
- **Install:** copy the tree to `$out/share/hello-lock/plugin`, without
  `docs/`, `tests/` and `preview.png`. Those are about 8.5 MB, and nothing
  at runtime uses them. `sounds/` stays.
- **Shebangs:** run `patchShebangs` on `bin/` with `python3` and `bash` in
  `buildInputs`. The helpers use only the Python standard library. This
  pins their interpreter, so they do not depend on the session `PATH`.
  `bin/` gets no other patching.
- **No build step, no runtime fetch.** The weather lookup (`curl` to
  wttr.in) is upstream's runtime behaviour, configurable in its settings.

### 2. Host wiring: `hosts/common/nixos/omarchy-hello-lock.nix`

This follows `omarchy-omateams.nix`:

```nix
{ pkgs, ... }:
{
  imports = [ ./omarchy-enable-once.nix ];
  home-manager.users.olafkfreund = {
    programs.nixarchy.plugins.hello-lock.src = "${pkgs.customPkgs.hello-lock}/share/hello-lock/plugin";
    local.omarchy.enableOnce = [ "hello-lock" ];
  };
}
```

- **Imports:** imported from `hosts/p620/nixos/nixarchy.nix` and
  `hosts/razer/nixos/nixarchy.nix`, beside `omarchy-omateams.nix`. p510
  does not import it.
- **Install:** `programs.nixarchy.plugins` symlinks the store path into
  `~/.config/omarchy/plugins/hello-lock`. It validates `manifest.json` at
  build time, so a bad bump fails the rebuild instead of failing at login.
- **Enable:** `enableOnce` enables the plugin once per host at the next
  login (post-boot hook, after `rescanPlugins`). After that the user
  controls it, and `omarchy plugin disable hello-lock` persists.
- **Lock route:** Omarchy's `PluginRegistry` sends the lock route to any
  enabled plugin whose manifest says `clonedFrom: "omarchy.lock"`.
  Disabling the plugin sends it back to the stock lock screen. No stock
  plugin setting is touched.

### 3. Decisions on the intent's open questions

The user approved the intent without answering these, so this spec takes
the recommended defaults. They can be changed at spec review.

- **Weather:** upstream default (on). It can be turned off per host in
  hello-lock's settings (Style → Lock Screen), which stores
  `"weather": false` in `~/.config/hello-lock/config.json`.
- **First-run setup:** runs once per host. `~/.config/hello-lock/` stays
  user state, and the settings screen stays writable. Nothing is declared
  in Nix.

### 4. Docs: `docs/applications/hello-lock.md` (new)

- **Contents:** what it is; the hosts; the pinned rev and the bump
  procedure; first-run setup and settings (`omarchy-shell lock settings`);
  previews (`omarchy-shell lock preview`); the doctor
  (`hello-lock-doctor` from the plugin's `bin/`); and recovery.
- **Recovery:** from a TTY (Ctrl+Alt+F3) or SSH, run
  `omarchy plugin disable hello-lock && omarchy restart shell`. The stock
  lock screen is back.
- **Nav:** a new page, so the entry goes in **both** `mkdocs.yml` and
  `mkdocs-full.yml`, in the Applications section, beside `agent-voice.md`.

## Alternatives rejected

- **`omarchy plugin add … --enable` on each host:** unpinned (follows
  upstream HEAD), outside Nix, can differ between hosts, and is not
  reverted by a rollback.
- **A bare `fetchgit` as `src`**, like the nixarchy option example: it
  leaves the helpers' `#!/usr/bin/env python3` depending on the session
  `PATH`, and ships 8.5 MB of docs. A small derivation fixes both for a
  few lines.
- **A flake input:** another lock entry and `follows` work for a
  non-flake QML tree. `fetchFromGitHub` in `pkgs/` matches `omateams`, and
  a bump is one rev and hash.
- **Declaring `config.json` in Nix:** it makes upstream's settings screen
  read-only, and the user's setup answers are personal state.
- **Stopping the stock lock plugin from Nix:** not needed. The
  `clonedFrom` route does it, and leaving the stock plugin alone is what
  makes disabling hello-lock a clean fallback.

## Risks

- **A plugin that fails to load (worst case).** If hello-lock is enabled
  but its service fails, the lock route may still point at it, and
  locking could fail on that host (p620 or razer). Mitigations:
  - verification proves a real lock and unlock on each host before done;
  - `hello-lock-doctor` runs as part of verification;
  - the recovery commands are in the docs;
  - the deploy happens with someone at the machine, not unattended.
- **Not locking at all.** Upstream refuses to lock when
  `/etc/pam.d/omarchy-lock-password` is missing. It exists on both hosts
  today, from nixarchy's lock module. A future nixarchy change that
  removed it would quietly stop locking, so `hello-lock-doctor` and the
  docs both point at it.
- **A shell restart is needed.** Lock services load only at a shell
  restart, so the first deploy needs one `omarchy restart shell` per host.
  Known traps:
  - the restart race (memory);
  - a stale `OMARCHY_PATH` in the login session (memory: if
    `current-system` changed since login, a restart can leave no shell);
  - the restart is done from a terminal on the host, and the shell is
    checked to come back.
- **Upstream moves fast.** v0.5.3 is from today, with one author. It is
  pinned, and a bump is reviewed like any package bump. Upstream
  `omarchy plugin update` does not apply to a store symlink.
- **Arch-only helpers.** `hello-status` uses `checkupdates`, which is
  pacman-only, for the pending-updates status. It degrades to no count.
  Locking does not depend on it.
- **Fingerprint.** Fingerprint unlock is unused, because neither host has
  `/etc/pam.d/omarchy-lock-fingerprint`.

## Verification

1. `nix build .#nixosConfigurations.p620.pkgs.customPkgs.hello-lock`
   succeeds. The `bin/` shebangs point into `/nix/store`. `docs/` and
   `tests/` are absent.
2. `just test-host p620` and `just test-host razer` both build. This
   includes nixarchy's manifest validation.
3. Live on p620:
   - deploy;
   - `ls -l ~/.config/omarchy/plugins/hello-lock` points into the store;
   - `omarchy plugin enable hello-lock` (or wait for `enableOnce` at
     login), then `omarchy restart shell`, and the shell comes back;
   - `hello-lock-doctor` has no failures;
   - `omarchy-shell lock preview` renders;
   - the user locks (Super+Ctrl+L or the menu) and unlocks with their
     password. A wrong password shows the failure state and does not
     unlock;
   - first-run setup completes.
4. The same on razer after `just deploy-via-p620 razer`, by the user at
   the machine.
5. Recovery is tested once on p620:
   - `omarchy plugin disable hello-lock && omarchy restart shell` gives
     the stock lock screen;
   - re-enable it.
6. The docs pass the pre-push markdownlint, and both mkdocs navs list the
   page.
