# Spec: herdr-run passes only an allow-list to its pane

## Design

### 1. One list, in one file

A new file, `home/development/agent-env.sh`, holds the names and one function that reads them:

```bash
# shellcheck shell=bash
# #2757's sandbox: what both tools get. agent-sandbox.sh gives each name its own value.
agent_env_base=(PATH HOME LANG TERM TMPDIR SSL_CERT_FILE NIX_REMOTE NIX_CONFIG)
# #2757's per-tool markers: CODEX_CODER for codex; AGY_CODER, AGY_WORKTREE, AGY_GUARD_LOG for agy.
agent_env_markers=(CODEX_CODER AGY_CODER AGY_WORKTREE AGY_GUARD_LOG)
# What a herdr pane or agent-env passes on from its caller (#2762).
agent_env_names=("${agent_env_base[@]}" "${agent_env_markers[@]}" XDG_RUNTIME_DIR
  XDG_CACHE_HOME USER LOGNAME SHELL AGY_IMPLEMENT_PROBING)
# Prints, NUL-separated, each name on agent_env_names that the caller exported.
agent_env_exported() {
  local -A exported=()
  local entry name
  while IFS= read -r -d '' entry; do exported[${entry%%=*}]=1; done < <(env -0)
  for name in "${agent_env_names[@]}"; do
    if [[ -n ${exported[$name]:-} ]]; then printf '%s\0' "$name"; fi
  done
}
```

- `env -0` is the source of what is exported, because minimal bash has no `compgen`
  (`herdr-run.sh:118`). `[[ -v ]]` would not do: bash sets `SHELL` and `TERM` itself in a
  fresh process without exporting them (checked: `env -i PATH=… bash --noprofile --norc`).
- `if`, not `&&`, because `writeShellApplication` sets `errexit`, and a false last test would
  end the loop with status 1.

It is shared the way #2757's spec shares `agent-sandbox.sh`: by concatenation in Nix, never
sourced at run time (#2757 spec, section 1). Every consumer is assembled with it first:

- `herdr-run`: `text = builtins.readFile ./agent-env.sh + builtins.readFile ./herdr-run.sh;`
  (`agent-run.nix:7`).
- `agent-env` (section 4).
- `agent-review` and `agent-implement`: `agent-env.sh + agent-sandbox.sh + <launcher>.sh`, and
  the same order in the assembled copy that `agent-review.test.sh` builds (#2757 spec,
  section 1).

How `agent-sandbox.sh` uses it, without widening #2757's boundary:

- It builds the base environment by walking `agent_env_base`. A `case` gives each name its
  sandbox value, as #2757's spec sets them: `HOME` is the sandbox home, `TMPDIR` the work
  directory, `PATH` the filtered path, `NIX_REMOTE` and `NIX_CONFIG` the read-only values,
  `LANG` and `TERM` the caller's. A name with no `case` arm aborts before the tool starts, so
  adding a name to the list without deciding its value fails closed.
- It does not use `agent_env_markers` or `agent_env_names`. `agent-implement` still adds only
  the markers for its own tool (#2757 spec, section 7): `CODEX_CODER=1` for codex;
  `AGY_CODER=1`, `AGY_WORKTREE` and, when set, `AGY_GUARD_LOG` for agy.
- Its test checks, by name only, that inside the sandbox codex sees exactly `agent_env_base`
  plus `CODEX_CODER`, and agy sees exactly `agent_env_base` plus its markers. A review sees
  `agent_env_base` alone.

`CODEX_CODER`, `AGY_CODER` and `AGY_WORKTREE` are set by the launchers themselves
(`codex-cli.nix:28`, `antigravity-config.nix:197`). They are on `agent_env_names` because
the list in #2757 has them, and passing a marker the caller set can only keep a guard on.
`agy-guard-probe` sets `AGY_GUARD_LOG` and `AGY_IMPLEMENT_PROBING` for the `agy-implement`
it starts (`antigravity-config.nix:222`). `AGY_IMPLEMENT` is set by `agy-implement` when it
starts the probe (`:171`).

Not on the list, by the owner's decisions: every `HERDR_*` name, `SSH_AUTH_SOCK`, and every
credential. Also not on it: `DBUS_SESSION_BUS_ADDRESS`. Its value here is
`unix:path=$XDG_RUNTIME_DIR/bus`, the default that D-Bus clients fall back to, and `gh auth
status` exits 0 under `env -i` with only `HOME` and `PATH` (checked on p620).

### 2. herdr-run writes only the list

`herdr-run.sh:114-125` becomes:

```bash
# Only allow-listed names (agent-env.sh), one `declare -p` each so values with newlines survive.
while IFS= read -r -d '' name; do declare -p "$name"; done < <(agent_env_exported) >"$dir/env"
```

- The readonly scan (`:116-117`) and the internals `case` (`:122`) go. No name on the list is a
  shell internal or read-only, so they no longer guard anything.
- `cwd=` is still appended (`:126`).
- The runner's `env -i … source "$0/env"` (`:194-197`) is unchanged. The command's
  environment is now the list and nothing else. The runner itself still has herdr's pane
  environment, which it needs for `"$herdr_bin"` and nothing more.
- The helper (outside the pane) keeps the caller's `HERDR_*` variables. It needs them to make
  the tab, mark the row and report state. Only the file loses them.
- The headless path (`:11`, `:76-84`) is unchanged: `exec "$@"` with the full environment.

### 3. The `run` file and argv: no change

`run` (`:128-220`, renamed at `:265`) holds the command's arguments, including an agy prompt.
It stays:

- The arguments are what the caller chose to run. The helper's own `/proc/<pid>/cmdline`
  holds the same bytes for the whole run, readable by the same user, whether herdr is used
  or not.
- The file is `0600` inside the `0700` directory and goes with it.
- Moving argv elsewhere still needs a file, and the pane has to run it.

A credential in a prompt is the caller's mistake to avoid. The allow-list limits names, not
values, as the intent says.

### 4. A small `agent-env` command for the skill's agy runs

The `second-opinion` skill's two agy commands move to a cleared environment. One more copy of
the list in the skill would drift, so `agent-run.nix` gets one more package:

```nix
(pkgs.writeShellApplication {
  name = "agent-env";
  text = builtins.readFile ./agent-env.sh + ''
    args=()
    while IFS= read -r -d "" name; do args+=("$name=''${!name}"); done < <(agent_env_exported)
    exec env -i "''${args[@]}" "$@"
  '';
})
```

`writeShellApplication` puts its `runtimeInputs` in front of `PATH`. There are none here, so
`PATH` passes as the caller had it. In `herdr-run` it already carries that prefix today.

The skill's commands become (`second-opinion/SKILL.md:157-159` and `:188-190`):

```bash
herdr-run agy timeout 600 agent-env \
  agy --mode plan --output-format json --print-timeout 10m \
  -p "$(cat "$prompt")" > "$work/agy.json" < /dev/null
```

and the same for the `--agent "$agent"` form with `timeout 900`. `env -u GEMINI_API_KEY
-u GEMINI_API_KEY_FILE -u GOOGLE_API_KEY` goes, because `env -i` drops those names too. The
Codex paths (`:92`, `:145`) stay as they are: `agent-review` already clears the environment.

The team-rules agy form also passes `XDG_CONFIG_HOME` and `XDG_DATA_HOME`. The owner's list
does not have them, and on p620 both equal their defaults, so `agent-env` without them gives
agy the same paths. The live check (Verification 4) runs agy through `agent-env` before the
skill changes.

The skill's text that explains why the three names are unset changes to say why `agent-env`
is there.

### 5. Tests

`herdr-run-test.sh`:

- **The in-pane commands that write to `$TEST_STATE`** (`:119,126,143,159,175,201,238,256,
  275,283,307,354,376`) write to `$TMPDIR/state` instead. The test exports
  `TMPDIR="$tmp"` (`:9`) and `TEST_STATE="$tmp/state"`, so that is the same directory, and
  `TMPDIR` is on the list. The fake `herdr` runs in the caller's environment and keeps using
  `$TEST_STATE`.
- **`multiline-env`** (`:296-303`) uses an allowed name, `AGY_GUARD_LOG`, for the multi-line
  value. What it proves stays the same.
- **New cases, last in the file**, because the harness runs under `set -e` (`:5`) and stops at
  the first failure:
  - **`headless-env`.** With `HERDR_ENV=0` a decoy still arrives, which proves the headless
    path is unchanged.
  - **`env-allow-list`.** The test exports decoys: `GITHUB_API_TOKEN`, `HERDR_RUN_TEST_DECOY`,
    `SSH_AUTH_SOCK` and `HERDR_PANE_ID`, each holding one random marker string generated by
    the test (not a real secret). The command signals that it has started, then waits for a
    flag. While it waits:
    - **The file.** `grep -rF` for the marker over the private directory (`$tmp/tmp.*/`, since
      the test sets `TMPDIR`) finds nothing, in `env`, `run` or any other file. The names on
      the `declare` lines of `env` are all on `agent_env_names`. The `cwd=` line is skipped.
    - **The command.** After the flag, it prints its environment's names
      (`env -0 | cut -z -d= -f1`), never values. No decoy is among them, and every name is
      on `agent_env_names` or is one bash adds itself (`PWD`, `SHLVL`, `_`, `OLDPWD`).
    The list comes from the built script. A list widened to take in a decoy's name still
    fails, because the decoys are fixed in the test.
- **Mutation check.** `herdr-run-test.sh` already takes the script as `$1` (`:6`). The plan
  builds two copies and runs the test against each. It expects a non-zero exit, every `ok`
  line before `env-allow-list`, and no `ok env-allow-list`:
  - **Old loop.** The `:114-125` loop restored. Decoys reach the file and the command.
  - **File only.** The filtered `env` kept, and the old loop's output also written to
    `$dir/env.all`. The command is clean and the file check still has to catch it.

`agent-env` gets a `checkPhase` of three lines: a decoy exported to it does not reach
`env -0` in the child, `HOME` and `PATH` do, and the exit code passes through. A copy that
runs `exec "$@"` must fail it.

### 6. Docs

`docs/applications/herdr.md:176-184` gets one bullet: the pane's command gets only the
allow-listed variables from `agent-env.sh`, not the caller's whole environment (#2762).

### 7. Order of landing

The owner decided this lands after #2757's `agent-sandbox.sh` exists. #2757 has an approved
spec and no plan yet. So this plan is implemented on a branch rebased on `main` once #2757
has merged. If #2757's merged base list differs from `agent_env_base` in section 1, the
merged one wins, and the plan records the difference.

## Alternatives rejected

- **No env file, using herdr's pane environment.** The owner chose the allow-list (intent,
  decision 2). The pane's environment is a second unknown set.
- **A deny-list of names with `TOKEN`, `KEY`, `SECRET` or `PASSWORD`.** It misses a credential
  under any other name, and the next one added to `api-keys.nix` may have one.
- **Writing the list inline in the skill**, in the tested team-rules form. That is a third copy
  of the list, which the owner asked to avoid.
- **Putting the list in `agent-sandbox.sh` and concatenating that into `herdr-run`.** It
  brings #2757's checks and exec functions into a script that uses none of them. A file that
  holds only the names and one reader keeps both sides small.
- **`[[ -v name ]]` instead of reading `env -0`.** Bash sets `SHELL` and `TERM` in a fresh
  process, so `-v` would pass names the caller never exported.
- **A test-only allowance for `TEST_STATE`.** That is production code that exists only for
  the test. `$TMPDIR/state` needs no such hook.
- **Filtering the headless path too.** The owner kept it as it is (decision 6).
- **Moving argv out of `run`.** Section 3.

## Risks

- **`agy-guard-probe` and `agy-implement`.** Checked read-only
  (`antigravity-config.nix:146-268`). Their needs:
  - `agy-implement` reads `XDG_CACHE_HOME` and `HOME` (`:163`). Both are on the list.
  - The probe sets `AGY_IMPLEMENT_PROBING` and `AGY_GUARD_LOG` for its own `agy-implement`
    child (`:222`), and `agy-implement` sets `AGY_IMPLEMENT` for the probe (`:171`). Both
    happen inside the pane, after the filter, so neither is affected.
  - It uses `$HOME/.gemini` (`:211`) and `mktemp`, which uses `TMPDIR`.
  - On failure it files an issue with `gh` (`:256-266`), which reads its login from the
    keyring over D-Bus. `gh auth status` passes under `env -i` with only `HOME` and `PATH`
    on p620, so the default bus address is found. If `gh` fails there, the probe prints
    "file this by hand" and still exits 1, so `agy-implement` still refuses. It fails closed.
  - Not checked live: a full probe run inside a pane after the change. The live check runs
    it.
- **The `↳` rows.** The helper keeps every `HERDR_*` variable, so the tab, the mark, the
  placement and `report-agent` do not change. A herdr hook in the child, such as
  `claude-code-managed.nix:609-647`, now finds neither `HERDR_ENV` nor `HERDR_PANE_ID`, and exits 0
  at its first guard (`:609`). It used to report against the lead's pane, so this fixes that.
- **Tools that need a variable not on the list.** Codex and agy logged in with the
  team-rules list (lead's test, 2026-11-07). `timeout` and `agent-review` need nothing.
  `LANG` and `TERM` pass. Anything else shows up as a failed run in the live check.
- **A `bash` child can reload the session's variables.** Bash reads `~/.bashrc` when its stdin
  is a socket, even when it is not interactive. On p620, `env -i PATH=… HOME=… bash -c env`
  with Claude Code's socket on stdin has 85 variables, `SSH_AUTH_SOCK` among them, and none of
  the six credentials. With stdin from `/dev/null` it has 5. The command in a pane reads the
  FIFO (`herdr-run.sh:197`), not a socket, so this does not happen there. Callers of
  `agent-env` outside herdr pass `< /dev/null`, as both skill commands already do, and the
  live checks do too. A shell a tool starts with its own stdin is outside this issue.
- **razer.** Same modules and the same session variables, but nothing is checked there.
  Nothing in this change is host-specific, so the first agent run on razer after the deploy
  is the check.
- **p510.** It has claude-code, but is not built or deployed by this work.
- **Landing order.** See section 7. If #2757 changes its list during its plan, section 1
  follows.

## Verification

1. **Build.** `just test-host p620` and `just test-host razer`. The `herdr-run` `checkPhase`
   runs `shellcheck` and `herdr-run-test.sh`, including `env-allow-list` and `headless-env`.
   `agent-env` runs its own `checkPhase`.
2. **Mutation.** Both copies in section 5, the old loop and the file-only leak: the test exits
   non-zero with every `ok` line before `env-allow-list` and without `ok env-allow-list`.
   `agent-env`'s check against a copy that runs `exec "$@"` fails.
3. **The #2757 test** checks, by name, that codex sees `agent_env_base` plus `CODEX_CODER`, agy
   sees `agent_env_base` plus its markers, and a review sees `agent_env_base` alone. It passes,
   and fails against a copy whose `case` leaves a name out.
4. **Live, inside herdr on p620, after the deploy (names only, never values):**
   - `export HERDR_RUN_CANARY=1`, then `herdr-run codex bash -c 'env -0 | cut -z -d= -f1 |
     tr "\0" "\n" | sort'`. The output is a subset of `agent_env_names` plus `PWD`, `SHLVL`
     and `_`. `HERDR_RUN_CANARY`, `GITHUB_API_TOKEN`, `SSH_AUTH_SOCK` and every `HERDR_*`
     are absent. A `↳ codex` row appears and closes.
   - The same with `agent-env bash -c '…' </dev/null`, with and without herdr.
   - Each caller path, in a pane, finishes as it does today: both `second-opinion` agy forms
     (plain and `--agent`) return `SUCCESS`; both Codex review forms (`review --base` and
     `exec`) write their output; `agent-run` completes one codex step and one agy step.
   - One agy review through `agent-env` outside herdr returns `SUCCESS`.
   - `herdr-run agy agy-guard-probe`, run by hand in a pane so the probe runs whatever the
     cache says: every check prints `PASS` and it exits 0.
   - While a run is going, the names in its `env` file are listed with `cut -d= -f1`, never
     printed in full.
5. **No leftovers.** After the runs, no `/tmp/tmp.*` directory holds `env` and `run`.

## Open questions

The design follows the owner's list and landing order as decided. One question, only because
the tested agy form and that list differ:

1. **Should the list also take `XDG_CONFIG_HOME` and `XDG_DATA_HOME`?** The lead's tested agy
   form passes them, and the owner's list does not. On p620 both equal their defaults, so
   leaving them out changes nothing there. The spec leaves them out, as decided. Adding them
   would change an owner decision, so it is the owner's call. Recommendation: leave them out
   unless the live check fails.

## Owner decision, 2026-11-07

The owner approved the spec, and added `XDG_CONFIG_HOME` and `XDG_DATA_HOME` to `agent_env_names`. They are paths, not secrets, and the tested agy form already passes them. The plan carries both.
