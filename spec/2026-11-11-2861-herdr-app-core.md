# Spec: the Herdr desktop app and herdr-core (hc) on p620 and razer

Approved intent decisions:

- packages in `pkgs/`;
- `hc` starts on demand (no Nix service);
- installed as `hc` next to `herdr-core`;
- telemetry off through the launch environment;
- linger declared on for the owner on p620 and razer.

**Adoption is gated on verification:** the packages stay in the profile
only if every on-host check below passes on both hosts. Otherwise they come
back out (Rollback in the plan).

## Design

### 1. `pkgs/herdr-core/default.nix` (new)

- `fetchurl` of
  `https://releases.herdr.dev/core/${version}/herdr-core-linux-x86_64.tar.gz`
  (0.1.20, sha256 from `core/latest.json`: `ac6b8689…14e74`). The binary
  is static-pie, so there is no patchelf.
- Install `$out/bin/herdr-core` and a symlink `$out/bin/hc -> herdr-core`
  (as the upstream installer does), plus `LICENSE` and
  `THIRD-PARTY-NOTICES` under `share/doc`.
- `passthru.skill`: a `runCommand` that runs `herdr-core --skill` with
  `HOME=$TMPDIR` and writes `SKILL.md` with YAML frontmatter prepended:
  `name: hc` and a `description` saying when to use it (long-lived
  terminals and agents through herdr-core; not the Herdr TUI). `hc --skill`
  prints no frontmatter, and Claude Code needs it to list the skill.
- `meta.platforms = [ "x86_64-linux" ]`. The comment holds the bump
  checklist (manifest URL, hash, Verification 2-7 on p620, the core-bump
  check in Verification 9).

### 2. `pkgs/herdr-app/default.nix` (new)

Modelled on `pkgs/okena/default.nix` (another prebuilt GPUI app):

- `fetchurl` of
  `https://releases.herdr.dev/app/${version}/herdr-app-linux-x86_64.tar.gz`
  (0.1.15, sha256 from `app/latest.json`: `f99e1e04…655dd`).
- `autoPatchelfHook` with `buildInputs = [ libxkbcommon libxcb
  stdenv.cc.cc.lib ]` (its NEEDED entries).
- Install `bin/herdr-app`, and the icon **only** to
  `share/icons/hicolor/scalable/apps/herdr-app.svg`, plus a
  `makeDesktopItem` desktop entry (`Name=Herdr`, `Exec=herdr-app`,
  `Icon=herdr-app`, `Categories=Development;TerminalEmulator;`).
- **Self-update off. The primary guard is the layout.** The app's updater
  (`herdr_app::update::find_root`) canonicalises its own executable and
  only runs when `herdr-app.svg` sits next to it. The upstream tarball puts
  it there; we don't, and after `wrapProgram` the real binary is
  `bin/.herdr-app-wrapped` with no SVG beside it. The updater thread then
  never calls `update::check`: no download, no staging, no hourly fetch.
  The package comment says never to install the SVG next to the binary.
- **Backstop:** `--set HERDR_RELEASES_URL file://${releases}` (no trailing
  slash). `releases` is a `writeTextDir` tree holding
  `app/latest.json = {"version":"<app version>"}` and
  `core/latest.json = {"version":"<core version>","generation":1}`. The
  app appends `/app/latest.json` and `/core/latest.json` to that base, and
  fetches them with `curl -fsSL --max-time 30`, with no protocol
  restriction. A manifest whose version isn't newer returns "current"
  before `targets` or release notes are read. So if a future version
  dropped the SVG check, it would still find itself current, offline.
- Other `wrapProgram` settings:
  - `--prefix LD_LIBRARY_PATH` for what it loads at runtime:
    `vulkan-loader`, `libglvnd` (`libEGL`), `wayland`, `libxkbcommon` (as
    in okena).
  - `--prefix PATH` for `curl`, `pipewire` (`pw-play`, for sounds) and
    `herdr-core`. `xdg-open` and `gsettings` come from the desktop session
    `PATH`, as for the other desktop apps.
  - `--set HERDR_CORE_DIRS ${herdr-core}/bin` (a `PATH`-style list; one
    directory is enough).
  - `--set HERDR_TELEMETRY 0` and `--set DO_NOT_TRACK 1`: telemetry is off
    on every launch, from the menu or a shell. `settings.json` stays
    writable, and we don't touch it.
- **Core selection.** The app tries a `core` path saved in its
  `settings.json` *before* `HERDR_CORE_DIRS`. We never write that key, and
  on a fresh setup it is absent, so our core is picked. If the owner later
  chooses another core in the app ("Use this herdr-core"), that is their
  explicit override. Verification 2 checks the key is absent and the
  running core is ours.
- `passthru.skill`: as for the core, from `herdr-app --skill`, with
  `name: herdr-app` frontmatter and a description (driving the person's
  Herdr window).

## Alternatives rejected

- **Upstream `curl | sh` installers:** they write into `~/.local`, update
  themselves, and aren't declarative.
- **Our own flake (like `nix-craftapps`):** rejected at the intent gate.
- **A systemd user service for `hc`:** rejected at the intent gate, because
  `hc` runs its own `systemd-run --user` server and the app starts it on
  demand.
- **A dead `HERDR_RELEASES_URL`:** every check would fail, and the intent
  forbids update errors.
- **Patching the binary's update code:** fragile on every bump. The layout
  guard needs no patch.
- **Telemetry or core selection through `settings.json`:** the app rewrites
  that file, so a Nix-managed copy would be read-only and a seeded one
  could be overwritten.

## Risks

- **The update guard depends on upstream internals:** the SVG check, with
  the local manifest as backstop. If a later version found its root another
  way *and* ignored `HERDR_RELEASES_URL`, it would try to write into
  `/nix/store` and fail visibly. Verification 6 runs on every bump.
- **GPU on razer.** wgpu picks a Vulkan adapter itself, and on razer's
  hybrid Intel/NVIDIA it could wake the dGPU or pick a device that can't
  present to Wayland. Verification 3 checks this on razer. A fix (an
  adapter choice in the wrapper) would be a plan deviation with its own
  check, not a fleet-wide offload change.
- **A rebuild while an older core server runs.** The running server keeps
  its old store path (Nix GC treats running processes' paths as roots), and
  `hc` documents that older holders "run their terminals to the end". The
  app may show "Herdr needs a newer herdr-core" until `hc server restart`,
  which keeps terminals. Verification 9 checks the restart now and the
  version change at the first real core bump.
- **Linger on razer** keeps the owner's user units, including `hc` and
  anything an agent left running, alive after logout on a laptop. The owner
  accepted this at the intent gate.
- **0.1.x churn:** frequent bumps, two hashes each.
- **Binary trust:** prebuilt, unsigned upstream tarballs pinned by
  sha256, the same trust level as okena and the other prebuilt apps.

## Verification

Gate: checks 1-9 pass on both hosts, or the packages come back out.

1. **Build:**
   - `nix-instantiate --parse` on each new or changed file.
   - `just test-host p620` and `just test-host razer`.
   - Each skill output's frontmatter parses as YAML, with `name` (`hc`,
     `herdr-app`) and a non-empty `description`.
   - `$out/bin` of `herdr-app` has no `herdr-app.svg`.
2. **Cold start** (each host, after the deploy, announced):
   - Stop any `hc` server, then start Herdr from the launcher (desktop
     entry or `uwsm-app`).
   - A window opens, and `hc ls` lists its terminal.
   - The core process's `/proc/<pid>/exe` is our store path.
   - `~/.config/herdr-app/settings.json` has no `core` key.
3. **Native Wayland and rendering:**
   - `hyprctl clients -j` shows the Herdr window with `xwayland: false`.
   - A command typed in its terminal shows output.
   - On razer, the app log has no render or adapter errors; note which
     adapter it picked.
4. **Persistence:** close the window and reopen it; the terminal and its
   scrollback are still there. `hc attach` / `hc read` from a shell reach
   the same terminal.
5. **Telemetry off:**
   - The running app's `/proc/<pid>/environ` has `HERDR_TELEMETRY=0` and
     `DO_NOT_TRACK=1`.
   - The app's telemetry state under `~/.config/herdr-app` shows nothing
     queued or sent after the session.
   - This proves the switch is set, not that nothing was ever sent. A
     short `ss` snapshot is no proof of absence.
6. **No self-update:**
   - Settings > Updates shows no available update and no error.
   - No `.download` / `.new` staging files under `~/.config/herdr-app`.
   - Nothing in `~/.local/bin` or `~/.local/share/herdr-app`.
   - `which herdr-app hc herdr-core` all resolve to the Nix profile.
   - With `strace -f -e trace=execve` on a launch of a minute or more,
     there is no `curl` call to `releases.herdr.dev`, and no `curl` at all
     for updates.
7. **Coexistence:**
   - `herdr` (the TUI) starts.
   - `.claude/skills/herdr` is unchanged.
   - `herdr-team status` works.
   - `claude` started in an `hc` terminal is plain `claude`, not
     `herdr-claude-teams`.
8. **Linger:**
   - `loginctl show-user olafkfreund -p Linger` gives `yes` on both hosts.
   - On razer, no other user got linger.
9. **Core restart:** with a live `hc` terminal running a command,
   `hc server restart` keeps it running and the app reconnects. The real
   version-change case (an old server plus a new store core) is checked at
   the first core bump, using the bump checklist in the package comment.
