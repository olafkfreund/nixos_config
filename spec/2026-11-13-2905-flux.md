# Spec: Flux on p620 and razer

## Decisions carried from the intent's open questions

- The Omarchy shell plugin comes (Flux in the bar). The browser extension does not.
- The Tab S8 Ultra stays as it is. Pairing razer is a manual step on the phone, done once.

## Design

### 1. Flake input

In `flake.nix`'s `inputs`, next to the other desktop flakes (pattern at `flake.nix:132-135` and `:147-151`):

```nix
nixarchy-flux = {
  url = "github:olafkfreund/nixarchy-flux";
  inputs.nixpkgs.follows = "nixpkgs";
};
```

`flake.lock` pins it to master after nixarchy-flux#59 merges. Inputs reach modules through `specialArgs`
(`flake.nix:396-406`), and Home Manager through `extraSpecialArgs` (`:451-463`).

### 2. `modules/desktop/flux.nix`: `features.flux`

Imported from `modules/desktop/default.nix`, beside `tfm.nix` (the chain `modules/desktop/default.nix:9-10` →
`modules/desktop.nix:5` → `hosts/templates/desktop.nix:7` reaches both hosts). The shape copies `modules/desktop/tfm.nix:7-20`.

```nix
{ config, lib, inputs, username, ... }:
let cfg = config.features.flux; in
{
  imports = [ inputs.nixarchy-flux.nixosModules.default ];

  options.features.flux = {
    enable = lib.mkEnableOption "Flux, the phone link (fluxd, flux-cli, the shell plugin)";
    inboundInterfaces = lib.mkOption {
      type = lib.types.nullOr (lib.types.listOf lib.types.str);
      default = null;
      description = "If set, Flux's listening ports accept connections only on these interfaces (and lo).";
    };
  };

  config = lib.mkIf cfg.enable { ... };
}
```

When enabled:

- **NixOS side.** `services.flux = { enable = true; users = [ ]; openFirewall = false; approve.services = [ ];
  webcam.enable = false; }`. This installs `flux`, its runtime tools and the udev rule (upstream `nix/nixos.nix:90-91`).
  With `users = [ ]`, it defines no user unit (`:114`).
- **Home Manager side.** `home-manager.users.${username}`:
  - `imports = [ inputs.nixarchy-flux.homeManagerModules.default ]`
  - `services.flux = { enable = true; plugin.enable = true; browser.enable = false; }`

  This is the hybrid Flux documents (`docs/nix.md:89-91`). Home Manager owns the single `fluxd` user unit, wanted by
  `graphical-session.target` (`nix/home-manager.nix:121-139`), and copies the shell plugin to
  `~/.config/omarchy/plugins/flux` as a real folder (`:143-152`). It isn't a symlink, because `fluxd`'s plugin sync
  refuses symlinks (`internal/plugin/plugin.go:174-184`). The plugin is turned on once with `flux-cli setup`; that is
  a manual step, documented.
- **Avahi.** Flux's module sets four Avahi options with `lib.mkDefault` (`nix/nixos.nix:93-100`). This module sets
  nothing further about Avahi:
  - **p620:** `hosts/p620/configuration.nix:635-648` sets Avahi at normal priority, so its `allow-interfaces = [
    "enp1s0" ]` pin (#2293) and publish settings win over Flux's defaults. The pin stays.
  - **razer:** Avahi already runs on every interface through `features.gnome-remote-desktop`
    (`modules/desktop/gnome-remote-desktop.nix:79-87`). Flux adds no new exposure there. Limiting razer's Avahi is
    outside this task, and the plan files a follow-up issue for it.
- **Service hardening exception.** It is recorded in the module and in `docs/`, with the same argument as
  `modules/programs/claude-swarm-reaper.nix:25-26`. `fluxd` is a user unit that serves the user's own files, clipboard
  and phone link: `DynamicUser` and `ProtectHome` would break that, and `ProtectSystem=strict` needs mount namespacing
  that a user unit lacks. What fits is added through
  `home-manager.users.${username}.systemd.user.services.fluxd.Service`: `NoNewPrivileges = true` and
  `LockPersonality = true`.

### 3. The razer network guard: `features.flux.inboundInterfaces`

`fluxd` binds every address. TCP 12100–12108 and UDP 12100 are listened on through `":<port>"` (Flux
`internal/lan/provider.go:168,179`), and the payload ports are 12070–12099 (`docs/security.md:165`). No option binds
them to an interface (`internal/config/config.go:29-109`). razer has the firewall off (`hosts/razer/configuration.nix:91`),
so no `nixos-fw` chain exists, and the `networking.firewall.interfaces` rules other modules use (for example
`modules/services/whisper-server.nix:128-130`) don't take effect there.

When `inboundInterfaces` is set, the module adds a systemd oneshot `flux-guard.service`, wanted by
`network-pre.target` and ordered before it. It loads a standalone nftables table with `nft -f`. Neither
`networking.nftables.enable` nor the NixOS firewall changes, so Docker's own rules are untouched.

```nft
table inet flux_guard {
  chain input {
    type filter hook input priority filter - 1; policy accept;
    iifname { "lo", <inboundInterfaces> } accept
    tcp dport { 12070-12108 } drop
    udp dport 12100 drop
  }
}
```

- **The rule is idempotent.** `ExecStart` first deletes the table if it is there, then loads it. `ExecStop` deletes
  it. `RemainAfterExit = true`.
- **Per host:**
  - razer: `features.flux.inboundInterfaces = [ "tailscale0" ]`.
  - p620 (trusted home LAN behind the router): `null`, no guard.
- **What it costs razer away from home:** a phone can't open links to razer, or pair from the phone, over Wi-Fi.
  razer still dials out to the phone (`docs/security.md:168`). Over Tailscale both directions work, once the phone's
  Tailscale address is added (`docs/tailscale.md`). On the home LAN razer is covered too, with the same Tailscale
  address. That is acceptable for a roaming laptop and matches the intent.

### 4. Hosts

- `hosts/p620/configuration.nix`, next to `features.tfm` (`:518-521`): `features.flux.enable = true;`
- `hosts/razer/configuration.nix`, next to `features.tfm` (`:339`): `features.flux = { enable = true;
  inboundInterfaces = [ "tailscale0" ]; };`

### 5. The handover on p620

The hand-started `fluxd` (pid 2397965, started from agent session `9f0892`'s scratchpad) and the new unit share the
user's state:

- config: `~/.config/flux/config.toml`
- pairings and identity: `~/.local/share/flux/devices.json`, `certificate.pem` and `privateKey.pem`
  (`internal/config/config.go:205,219`, `internal/proto/cert.go:26-27`)
- socket: `$XDG_RUNTIME_DIR/flux/fluxd.sock`

The pairings carry over: the hand-started process uses the default XDG paths (checked 2026-11-13 from
`/proc/2397965/environ`: `XDG_DATA_HOME=~/.local/share`, `XDG_CONFIG_HOME=~/.config`), and `~/.local/share/flux` holds
the certificate, key and `devices.json`. Flux has no single-instance lock, so the old process
stops before the unit starts. The order is:

1. announce on `#agents` and tell session `9f0892`
2. stop the old process
3. switch
4. check

### 6. Docs

`docs/applications/flux.md` (new, short) covers:

- what is enabled, the hybrid, and why
- the hardening exception
- the razer guard
- the manual steps: `flux-cli setup`, pairing razer, and the phone's Tailscale address as an extra address

## Alternatives rejected

- **NixOS `users = [ "olafkfreund" ]` only:** no shell plugin. The intent wants it.
- **Both modules owning the unit:** Flux's docs forbid it (two `fluxd.service` definitions).
- **Turning razer's NixOS firewall on:** a host-wide change far beyond this task, and it touches Docker and libvirt.
- **`networking.nftables.enable` on razer:** it switches the firewall backend and conflicts with Docker's iptables use.
- **A bind-address patch in Flux:** a cross-repo change for a single host. It can come later, and then the guard goes.
- **Restricting Avahi on razer here:** that exposure exists today without Flux, and it gets its own issue.

## Risks

- **The guard drops something it shouldn't.** It touches only Flux's own ports; everything else is `accept`. A
  mistake shows as "razer can't be reached by the phone". `systemctl stop flux-guard` removes it.
- **The handover loses pairings:** unlikely, since the paths were checked. Re-pairing is the fallback.
- **The Flux input build:** the first build compiles Go and Qt (`flux-gui`). The CI cache doesn't have it, so time is
  spent on p620. Razer builds through p620.
- **Shared hosts:** p620 runs CI runners and agents, and razer has a linger session. The deploy is announced, and
  `fluxd` is a user service that disturbs nothing else.
