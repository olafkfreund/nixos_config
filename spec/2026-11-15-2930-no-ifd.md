# Spec: stop evaluation from building the omarchy package

## Design

The package is built from `inputs.nixarchy.inputs.omarchy` (both at rev `723072a`), and its `themes/*/colors.toml`
are identical to the source tree (all 23 compared). Read from that flake source, which is a plain path, not a
derivation.

1. **Stylix.** `omarchySrc = inputs.nixarchy.inputs.omarchy;` and
   `omarchyColorsPath = "${omarchySrc}/themes/${omarchyThemeName}/colors.toml";`.
   `useOmarchyTheme = builtins.pathExists omarchyColorsPath;`. A theme that only the package carries
   (`osaka-jade`) keeps the old package path, so IFD happens only while that theme is selected:
   `colorsPath` = the source path if it exists, else the package path when the theme is `osaka-jade` and that file
   exists, else `null` (the yaml fallback).
   The current theme `japan-night` is a user theme, in neither, so the checked-in yaml fallback stays in use.
2. **fastfetch.** Read `${inputs.nixarchy.inputs.omarchy}/etc/fastfetch/config.jsonc` and apply the package's one
   patch with `lib.replaceStrings` (same old/new strings as nixarchy's `--replace-fail`). Guard it like
   `--replace-fail`: assert that the old text is in the source before replacing, so an upstream change fails
   evaluation instead of silently changing the banner.

## Alternatives rejected

- Keep IFD and document an exception: evaluation stays slower and depends on the package being buildable.
- Copy the files into this repo: they would drift from the pinned omarchy.

## Risks

- nixarchy adds another patch to these files later: fastfetch would lose it silently except for the guarded line.
  Mitigation: a `checks/` test is out of scope (it would itself need the package); note it in the module comment.
- `inputs.nixarchy.inputs.omarchy` path changes when nixarchy renames the input: evaluation fails loudly.

## Verification

- `nix eval` of `config.stylix.base16Scheme` and HM `programs.fastfetch.settings` equal before/after on all hosts.
- `scripts/config-snapshot.sh` before/after: all identical except the toplevel.
- IFD gone: `nix eval --option allow-import-from-derivation false .#nixosConfigurations.<h>.config.system.build.toplevel.drvPath`
  succeeds for the stylix and fastfetch paths (fails today).
