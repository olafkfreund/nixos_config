# Spec: rewrite p510's Home Manager file without the mkForce wall

## Design

Map (Fable review on `5a01ce4c8`): both profiles import the same 14 modules; ten already come from
`Users/common/imports.nix`. The four the profiles add are `home/browsers`, `home/shell`, `home/media/music.nix`,
`home/files.nix`. p510-only content is developer's package list, `programs.claude-powerline`, `programs.delta`, git
settings, and server-admin's `dig` and `whois`.

New `p510_home.nix`:

- `imports = [ ../common/default.nix ./private.nix ../../home/browsers/default.nix ../../home/shell/default.nix
  ../../home/media/music.nix ../../home/files.nix ];` (same relative order as the profiles imported them).
- `features`: `editors = { enable = true; neovim = true; }` (enable is what turns VS Code off),
  `development = { enable = true; languages = true; workflow = true; productivity = true; }`, the unchanged
  `cli` and `multiplexers` blocks. `desktop`, `browsers` and `terminals` are left unset (default off), which is what
  the forces produced.
- Terminals as today: `ghostty.enable`, `foot.enable`, `kitty.enable`, `alacritty.enable` set to `true` without
  `mkForce` (nothing else defines them while `features.terminals.enable` is off).
- `home.packages`: the existing list plus developer's packages (git-lfs, delta, difftastic, nodejs_24, python3,
  rustc, postman, insomnia, xmlstarlet, pandoc, graphviz, buildah, terraform, ansible) and `dig`, `whois`. Copy
  developer's list from the file, not from this summary.
- `programs.claude-powerline.enable = true;`
  `programs.delta = { enable = lib.mkForce true; enableGitIntegration = true; };`
  (the one force, against `private.nix:87`); developer's git settings merged into the existing `programs.git.settings`.
- Delete `home/profiles/developer/` and `home/profiles/server-admin/` (no other importer) and their README mentions.

## Alternatives rejected

- Import `profile.nix` like p620/razer: adds claude-code, tesseract, GNOME, proton, steam and ~25 packages to p510.
- Keep `developer` only: still needs six forces.

## Risks

- `home.packages` order changes, so the `home-path` derivation hash differs even with the same content. Equality
  is therefore checked on content (see Verification), not on the `.drv`.
- Import order of the four modules changes for order-sensitive merges (`programs.bash.initExtra`,
  `home.shellAliases`): caught by the generated-file comparison.

## Verification

On p510's configuration (evaluated and built on p620), before (`main`) and after:

1. `scripts/config-snapshot.sh diff`: `syspkgs`, `hmpkgs` (sorted names), `units`, `userunits`, `etc`, `hmfiles`
   all the same; `nix store diff-closures` of the toplevels empty.
2. Home Manager generated files: `diff -r` of the two `home-manager.users.olafkfreund.home-files` outputs shows no
   difference other than store-path hashes of `home-path`.
3. `home-path` trees identical: `find <home-path> -printf '%P\n' | sort` equal.
4. p620 and razer `IDENTICAL` (they must not change).
