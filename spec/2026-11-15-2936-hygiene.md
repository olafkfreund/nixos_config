# Spec: fleet constants, allowBroken and honest aggregator names

## Design

1. **`hosts/common/fleet.nix`** (new, plain data, imported with `import`): `{ p620 = { tailnet = "100.69.100.115";
   lan = "192.168.1.65"; }; }`. The seven literals use it (string interpolation, or `${fleet.p620.tailnet}` as the
   `networking.hosts` attribute name on razer). Comments may keep the literal.
2. **allowBroken**: delete `allowBroken = true;` from the three hosts. If evaluation then fails on a broken package,
   that host keeps it with a comment naming the package. `modules/services/citrix-workspace.nix:33` stays (scoped to
   that package's need, off on every host).
3. **Aggregators**: `modules/development.nix` also imports `./development/default.nix`; the three hosts drop their
   explicit import. Path imports keep their module key wherever they are imported from, so this is order-safe.
   `modules/overlays/default.nix` moves into `modules/core.nix`'s neighbour only if the `.drv` stays identical
   (overlay order matters); otherwise it stays and the reason is recorded.

## Alternatives rejected

- A `fleet` NixOS option: data that only feeds string literals does not need the module system.
- Renaming aggregator files: churn in imports and docs; fixing what they import is enough.

## Risks

- `allowBroken` removal can fail evaluation: per host, restore with a comment.
- Overlay move can reorder `nixpkgs.overlays`: verified by the `.drv`; reverted if it changes.

## Verification

`scripts/config-snapshot.sh` against the `main` baseline: p620, razer, p510 `IDENTICAL`; `git grep` shows the two
addresses only in `hosts/common/fleet.nix` and comments.
