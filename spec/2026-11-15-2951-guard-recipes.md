# Spec: the guards catch every disruptive Justfile recipe

## Design

One shared `just` prefix for the text-matching hooks: `just` followed by any number of `-f X`, `--justfile X`,
`-d X`, `--working-directory X` or `NAME=value` words, then the recipe. Written as an extended regex:

```text
JUST='just([[:space:]]+(-f|--justfile|-d|--working-directory)[[:space:]]+[^[:space:]]+|[[:space:]]+[A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*)*[[:space:]]+'
```

1. `busAnnounceScript` (`modules/programs/claude-code-managed.nix`): the two existing `just` alternatives use the
   prefix, and a new one adds `${JUST}(gc|cleanup|boot-space-clean|fix-agenix-remote|p510-clear-sessions|update)
   ([[:space:]]|$)`. `update-commit`, `boot-space`, `check-updates` and the rest do not match, because the name must
   end at whitespace or end of line.
2. `deployGuardScript` (same file): add `${JUST}p510-clear-sessions([[:space:]]|$)` and
   `${JUST}(boot-space-clean|fix-agenix-remote)[[:space:]]+p510([[:space:]]|$)`. The existing `just p510` and
   `deploy` alternatives use the prefix too.
3. `claude-coder-guard.sh`, `just)` case: the recipe loop skips `*=*` words as well as options. The block list grows
   to `*deploy* | p620 | p510 | razer | nhs | gc | cleanup | boot-space-clean | fix-agenix-remote |
   p510-clear-sessions | update | update-commit | build-on-p620 | _sign-drv`, with the reason "changes a host, its
   history or its signing key".
4. `Justfile`: the `update` body becomes `nh os switch --update`, the nh 4 spelling of what it meant. A one-line comment
   above each guarded non-deploy recipe names the guards, so a rename shows up in review. `test-guards` also runs the
   new bus test.
5. Tests:
   - new `scripts/test-bus-guard.py` extracts `busAnnounceScript` the way `test-p510-deploy-guard.py` extracts the
     p510 guard, with base64 cases. It denies each new recipe, plain, with `--justfile Justfile` and with
     `GENERATIONS=3`. It allows them with `AGENT_BUS_ANNOUNCED=1`. It allows `boot-space`, `update-commit`,
     `check-updates`, `status` and `test-host p620`.
   - `test-p510-deploy-guard.py` adds `p510-clear-sessions`, `boot-space-clean p510` and `fix-agenix-remote p510`
     (denied; allowed with `P510_DEPLOY_APPROVED=1`), and `boot-space-clean razer` (allowed).
   - `claude-coder-guard.test.sh` blocks every new name, the `VAR=value` and `--justfile` forms, and blocks with
     `AGENT_BUS_ANNOUNCED=1` too. It keeps `boot-space`, `check-updates`, `test-host` and `validate` allowed.
   - `agy-guard-adapter.test.sh` adds one non-deploy recipe (`gc`).

## Alternatives rejected

- **Expand recipes with `just --show` inside the hook:** slow, depends on the working directory, and still blind to
  what a script the recipe calls does.
- **Rename the recipes to contain `deploy`/`gc` markers:** breaks muscle memory and docs for no gain over exact names.
- **Delete `update`:** about 18 doc references; the one-line repair is smaller.

## Risks

- A wrong regex could block every `just` command for agents (annoying, loud) or miss one (silent). The offline tests
  cover both directions for each guard.
- The prose false positive on "just update" inside quoted text: accepted, see intent.
- Managed settings change on every host. Verified on p620 and razer after deploy. p510 keeps the old hooks until the
  owner deploys it.
