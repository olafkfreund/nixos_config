# Spec: omaPOD on p620 and razer

Decisions from the intent approval: document a user-unit hardening exception
(new `docs/applications/omapod.md`, AGENTS.md exception list); hourly refresh
on both hosts.

## Design

### flake.nix

New input next to the other Omarchy app inputs (`nixarchy-meetingai`, line ~144):

```nix
# omaPOD: podcast app + Omarchy bar widget; hosts/common/nixos/omarchy-omapod.nix (#2977).
omapod = {
  url = "github:olafkfreund/nixarchy-omapod";
  inputs.nixpkgs.follows = "nixpkgs";
  inputs.home-manager.follows = "home-manager";
};
```

`nix flake lock --update-input omapod` (only this input changes in `flake.lock`).
omaPOD's `home-manager` input is used only by its own VM check, so following ours
costs nothing.

### hosts/common/nixos/omarchy-omapod.nix (new)

Shaped like `omarchy-altscape.nix` and `omarchy-meetingai.nix`:

```nix
{ inputs, pkgs, ... }:
let
  id = "io.github.arikisonfire.pod";
  omapod = inputs.omapod.packages.${pkgs.stdenv.hostPlatform.system}.omapod;
in
{
  imports = [
    inputs.omapod.nixosModules.default
    ./omarchy-enable-once.nix
  ];

  programs.omapod.enable = true; # package, desktop entry, podcast/OPML handlers

  # Bound by omaPOD's omapod-binds.lua; declared so the duplicate-chord assertion
  # (omarchy-keys.nix) and hypr-keys-check see them. Descriptions match upstream's.
  local.omarchy.keys.external = map (k: { key = "SUPER + CTRL + SHIFT + ${k.key}"; description = "omaPOD: ${k.action}"; }) [
    { key = "K"; action = "toggle"; }
    { key = "COMMA"; action = "rewind"; }
    { key = "PERIOD"; action = "forward"; }
    { key = "N"; action = "skip"; }
    { key = "O"; action = "show"; }
  ];

  home-manager.users.olafkfreund = { lib, ... }: {
    imports = [ inputs.omapod.homeManagerModules.default ];
    programs.omapod = {
      enable = true;
      refreshTimer.enable = true; # hourly; auto-downloads skip battery by default
      # keybindings: module defaults, Super+Ctrl+Shift + K/COMMA/PERIOD/N/O, nixarchy backend
      # widget.enable stays false: the plugin comes from programs.nixarchy.plugins below
    };

    # User units cannot take DynamicUser/ProtectHome/ProtectSystem (docs/applications/omapod.md).
    systemd.user.services.omapod-refresh.Service.NoNewPrivileges = true;
    systemd.user.services.omapod-settings.Service.NoNewPrivileges = true;

    programs.nixarchy.plugins.${id}.src = "${omapod}/share/omapod/widget";
    local.omarchy.enableOnce = [ id ];

    # Append-only so bindings.lua stays the user's (as altscape-binds, #2503).
    home.activation.omapodRequire = lib.hm.dag.entryAfter [ "writeBoundary" ] ''
      f="$HOME/.config/hypr/bindings.lua"
      if [ -f "$f" ] && ! grep -qF '"hypr.omapod-binds"' "$f"; then
        run ${pkgs.bash}/bin/bash -c 'printf "\n%s\n" "$2" >> "$1"' _ "$f" \
          'pcall(require, "hypr.omapod-binds") -- managed by NixOS (#2977)'
      fi
    '';
  };
}
```

- The package is the one the modules use by default (`inputs.omapod.packages`),
  so the widget, launcher and binds all point at one store path.
- The widget is symlinked from the store by nixarchy; with no app source beside
  it, it starts `uwsm-app -- omapod` from `PATH` (omaPOD README, NixOS section).
- `local.omarchy.enableOnce` turns the widget on once per host after boot; turning
  it off later sticks.
- The nixarchy plugin option validates `manifest.json` at build time, so a bad
  manifest fails the build, not the login.

### Hosts

One line each, next to `../../common/nixos/omarchy-altscape.nix`:

### Docs

- `docs/applications/omapod.md` (new): what it installs, keys, widget, refresh,
  where the library lives, how to remove it, and a "Hardening exceptions"
  section: `omapod-refresh` and `omapod-settings` are Home Manager user units
  that read and write `~/.local/share/omapod` and `~/.config/omapod`;
  `DynamicUser` and `ProtectHome` would hide that data and `ProtectSystem =
  "strict"` needs mount namespacing user units lack (as for `fluxd`);
  `NoNewPrivileges = true` is kept.
- AGENTS.md rule 2: add "omaPOD's `omapod-refresh` and `omapod-settings` user
  units, see `docs/applications/omapod.md`" to the exception list.
- `mkdocs.yml` and `mkdocs-full.yml`: one nav line each next to Flux (the nav is
  hand-synced, AGENTS.md "Read first").
- `docs/architecture/desktop.md`: five rows in the "declared but bound
  elsewhere" table (`SUPER+CTRL+SHIFT+K` | `omaPOD: toggle`, … `+O` |
  `omaPOD: show`), so `hypr-keys-check --docs` finds chord and description on
  one line.

## Alternatives rejected

- **omaPOD's own `widget.enable`**: copies into the same plugin folder that
  `programs.nixarchy.plugins` manages; the repo already has one way to install
  plugins.
- **Asking the user to add the require line by hand** (meetingai style): Altscape's
  append-only activation is the newer pattern and needs no manual step.
- **A `features.omapod.enable` module under `modules/`**: rule 1 is for services;
  every Omarchy app here lives in `hosts/common/nixos/omarchy-*.nix` and is
  enabled by import.
- **Branch deploy with `ALLOW_BRANCH_DEPLOY=1`**: not needed; merge first.

## Risks

- **Keys**: `Super+Ctrl+Shift` K/O/N/comma/period are free on both hosts today
  (p620 listing, razer Lua files). A later bind on those keys would shadow one.
- **Widget start**: depends on `uwsm-app` and `omapod` on the session `PATH`;
  both are present on these Omarchy hosts.
- **Settings merge lock message**: if the refresh timer is running at login,
  `omapod-settings` skips until the next login (omaPOD PR known limit). No
  `settings` are declared here, so nothing depends on it.
- **razer build load**: built on p620 by `just deploy-via-p620 razer`.
- **p510**: untouched; not built, not deployed.
