# Spec: less Omarchy shell startup work (keepLoaded, app-dir rescans, dead bar keys)

## Design

### 0. Measure the reveal (before and after)

The startup cover is an Overlay layer with namespace `omarchy-background`
(`services/BackgroundIntro.qml:294-308`); its `closelayer` event marks the
reveal. Hyprland's log has no timestamps, so a temporary probe records them:

- `startup-probe`: a user script in the scratchpad that reads Hyprland's
  `.socket2.sock` and writes `<epoch.ns> <event>` for every `openlayer` and
  `closelayer` line to `~/.local/state/startup-probe/<login-epoch>.log`.
- Started by a hand-placed user unit
  `~/.config/systemd/user/startup-probe.service` (`PartOf` and `WantedBy`
  `graphical-session.target`), enabled for the measurement logins only, then
  disabled and deleted. Not committed: measurement scaffolding, not config.
- Per login, the report joins the probe log with journal timestamps (ms
  precision): `sddm-helper` "Starting Wayland user session", omarchy-shell
  "Launching config" and "Configuration Loaded", owed "shell background
  enabled", plus the count of "performing full rescan" lines in the shell's
  `.qslog` within 60 s of launch.
- The gates inside the shell (`desktopReady`, `backgroundReady`,
  `startupSettled`) are not observable from outside without patching the
  shell. The report gives reveal time and the owed hand-off, and says so.
- Baseline: two logins before any change. After: two logins after deploy.
  The owner logs out and in; the herdr panes survive a re-login (the current
  pane has outlived three logins on 2026-11-17).

### 1. keepLoaded (own plugins)

Drop `"keepLoaded": true` from the manifest of the seven plugins the audit
cleared (2026-11-19, batch A and B). Every caller uses
`omarchy-shell shell toggle|summon <id>`, which loads a panel on demand
(`shell.qml:1226-1241`, `1282-1287`); none has a service entry point;
all state lives in a singleton or is reset on open.

| Plugin | Repo | Manifest | Note |
|---|---|---|---|
| nixarchy.devenv | olafkfreund/nixarchy-devenv | `manifest.json:64` | state in `DevenvState` singleton |
| nixarchy.distrobox | olafkfreund/nixarchy-distrobox | `manifest.json:76` | `DistroboxState` singleton |
| nixarchy.microvm | olafkfreund/nixarchy-microvm | `manifest.json:72` | `MicrovmState` singleton |
| nixarchy.flatsnap | olafkfreund/nixarchy-flatsnap | manifest | build runs in a systemd unit; reattaches on open |
| nixarchy.winvm | olafkfreund/nixarchy-winvm | manifest | stops a 4 s `virsh` poll while closed |
| nixarchy.herdr | olafkfreund/nixarchy-herdr | manifest | drops a second herdr-app subscription |
| olafkfreund.govee | local folder, p620 only | `manifest.json` | not under Nix; edit in place |

Kept loaded, with the reason recorded in each PR description: pkg (a
rebuild runs as a menu child process), podman (stop or prune in flight),
github-actions and gitlab-pipelines (watched runs live in the panel),
ai-mirror (consent dialog daemon), nixi (pinned conversations). rebuild and
olafkfreund.menu: flag has no effect, left alone.

Delivery to this repo: each plugin PR merges in its own repo; this repo pins
the merge commit with the existing override pattern under `inputs.nixarchy`
(`flake.nix:77-84`, e.g. `inputs.nixarchy-herdr.url = ".../<rev>"`) and a
"remove once nixarchy pins <rev> or later" comment. winvm is a direct input
(`flake.nix:130-133`), bumped with `nix flake update nixarchy-winvm`. herdr
already has an override (`flake.nix:79`): move its rev forward.

### 2. Application-folder rescans

- **hyprforge** (`olafkfreund/nixarchy-hyprsettngs`, `Service.qml:63-89`):
  compare the current entry with the wanted text before touching the
  folder, normalising hyprchroma's rewrite (`Icon=<name>` plus
  `X-Omarchroma-Original-Icon=<path>` back to `Icon=<path>`); create the
  temp file only when it differs; drop `removeScript` and
  `Component.onDestruction` so the entry survives service restarts (owner
  decision). Diff: scratchpad `fix/hyprforge.diff`, checked with the repo's
  `test/embedded-sh.js` extraction, `sh -n`, shellcheck and inotifywait.
  Delivered by an override `inputs.nixarchy.inputs.nixarchy-hyprsettngs.url`.
- **omamail** (huacnlee/omamail, `scripts/register-mailto.sh:39-54`): build
  the entry in a variable, compare with the normalised file, and only on a
  difference write it and run `update-desktop-database`. The
  `claim_default` path is unchanged. Applied as a local commit in the
  checkout `~/.config/omarchy/plugins/omamail`, and offered upstream as a
  PR whose text the owner sees before it is posted. Diff: scratchpad
  `fix/omamail.diff`.
- **hyprchroma** is not changed: once the two writers stop reverting its
  edit, it rewrites each entry once and stops.

### 3. Dead bar settings

On p620 and razer, through the shell's own reload path (the same sequence
as upstream's `omarchy-shell-config`): back up `shell.json`, `jq` delete
`bar.hiddenRevealByRegion`, `bar.revealIcons` and every string-valued
`hidden` on a `bar.layout` entry (the tray's array-valued `hidden` is kept,
`Tray.qml:23`), validate `.version == 1`, `mv` into place, then
`omarchy-shell shell reloadConfig` and verify through
`omarchy-shell shell listShellConfig`. Re-check the file after the next
login, since plugins that write back their own settings could restore a
stale copy.

## Alternatives rejected

- **Patch keepLoaded at install time in this repo**: the owner chose PRs to
  own repos (2026-11-19); a patch here would also diverge from what
  nixarchy users get.
- **Waiting for nixarchy edge to pick up each plugin**: edge publishes from
  main once a day and needs a pin bump in nixarchy first; the override
  pattern already exists for this and is removed when edge catches up.
- **Move hyprforge's temp file to `$XDG_RUNTIME_DIR`**: a cross-filesystem
  `mv` loses the atomic, symlink-safe rename the script relies on.
- **Patch hyprchroma** to leave plugin entries alone: it is third-party,
  and fixing the two writers ends the loop.
- **One bar per monitor, cutting plugins**: out of scope (intent).

## Risks

- **First open is slower** for the seven lazily loaded views (cold QML, up
  to about 3.5k lines for herdr). Accepted; measured by eye.
- **Process kill on unload** is assumed from the podman author's comment,
  not read in the quickshell source; it only argues for keeping pkg and
  podman, so a wrong assumption costs speed, not correctness.
- **hyprchroma normalisation** depends on the marker name
  `X-Omarchroma-Original-Icon`; if hyprchroma changes it, the rescan comes
  back, nothing breaks.
- **omamail local patch** is lost on `omarchy plugin update omamail` until
  upstream merges.
- **shell.json race**: a bar change between `jq` and the rename would be
  overwritten; the post-check catches it.
- **Override drift**: each override must be removed once nixarchy edge pins
  the commit, or a later nixarchy bump is silently masked.
- **razer** has a different bar layout and was not audited for callers; the
  plugin changes are caller-neutral (all callers use `shell toggle`), and
  its `shell.json` gets the same jq filter.

## Verification

- Each plugin PR: the repo's own tests or CI pass.
- This repo: `just check-syntax`, `just test-host p620` and
  `just test-host razer`; `nix eval` that the overrides resolve to the new
  revs.
- Runtime on p620 after deploy: each of the seven opens by its keybind or
  menu row; `omarchy-shell shell call` is not used by any caller (audit).
  `jq '.keepLoaded' manifest.json` is null for the seven, true for the six
  kept.
- Rescans: after a shell reload, `quickshell log` of the new instance shows
  no "performing full rescan" within 60 s; `stat` of `hyprforge.desktop` and
  `omamail.desktop` unchanged across two reloads.
- shell.json: `listShellConfig` check returns `[null,null,0]` on p620 and
  razer, and again after the next login.
- Reveal: two after-logins compared with the two baseline logins, reported
  as numbers with the owed hand-off and rescan count.
