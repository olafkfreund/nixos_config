# Spec: less Omarchy shell startup work (keepLoaded, app-dir rescans, dead bar keys)

## Design

### 0. Measure the reveal, per gate (before and after)

A temporary probe times the login from outside the shell. It is measurement
scaffolding: kept in the scratchpad, never committed.

- **Unit.** `~/.config/systemd/user/startup-probe.service`, hand-placed,
  `PartOf=` and `WantedBy=graphical-session.target`, enabled for the
  measurement logins only, then disabled and deleted. It takes
  `HYPRLAND_INSTANCE_SIGNATURE` from the unit environment (uwsm exports it),
  never "newest directory": `/run/user/1000/hypr` holds several instances
  because Linger is on, including a short-lived one before each login.
- **Records**, each as `<epoch.ns> <what>` in
  `~/.local/state/startup-probe/<login-epoch>.log`:
  - the probe's own start;
  - every socket2 `openlayer` / `closelayer` event, each followed by a
    `hyprctl -j layers` snapshot of where `omarchy-background` and
    `omarchy-bar` layers sit (level and monitor);
  - start and exit of `omarchy-theme-bg-boot-intro`, by polling every 50 ms.
- **Gate proxies**, joined with journal timestamps (ms precision):

  | Gate (`BackgroundIntro.qml`) | Proxy |
  |---|---|
  | session start | `sddm-helper` "Starting Wayland user session" |
  | shell up | omarchy-shell "Launching config", "Configuration Loaded" |
  | `desktopReady` (bar present) | first `openlayer` of `omarchy-bar` |
  | `backgroundReady` | owed "shell background enabled" |
  | `startupSettled` | exit of `omarchy-theme-bg-boot-intro` |
  | reveal (end of 420 ms fade) | first snapshot with no level-3 (Overlay) `omarchy-background` on any monitor |

  These are proxies, not gate-opening times: the bar's `openlayer` does
  not show when the registry scan or a plugin reload settled, and owed's
  line shows when owed was ready, not when the shell saw `backgroundReady`.
  The gates themselves are not observable without patching the shell. The
  report labels every number as a proxy and states these limits; this is
  how the intent's "timed per gate" outcome is met. Four windows share the `omarchy-background` namespace
  (`BackgroundIntro.qml:306-308` Overlay cover, `:346-348` Bottom theme
  cover, `Background.qml:455` wallpaper, `:578` placeholder), which is why
  the reveal is read from the level, not from the event name.
- **Rescans**: count of "performing full rescan" in the new shell's
  `.qslog` within 60 s of "Launching config".
- **Validity**: a sample is void if the probe started after "Launching
  config" (except for the cover's `openlayer`, which may be missed: only its
  close is needed) or if no level-3 cover was ever seen.
- **Controls**: two warm re-logins before any change, two after; same
  monitors; no other flake bump in between. The owner logs out and in; herdr
  panes survive a re-login (seen on 2026-11-17).

### 1. keepLoaded (own plugins)

Drop `"keepLoaded": true` from four manifests. For each, every caller opens
it with `omarchy-shell shell toggle <id>` (directly or via `nixarchy-plugin
<id>`, which execs it), which loads a panel on demand
(`shell.qml:1226-1241`, `1282-1287`); none has a service entry point; and
all processes and timers live in a singleton, a systemd unit, or are
launched detached, so destroying the view on a toggle-close kills nothing
in flight.

| Plugin | Repo | Why it is safe |
|---|---|---|
| nixarchy.devenv | olafkfreund/nixarchy-devenv | `DevenvState` singleton owns processes and timers |
| nixarchy.distrobox | olafkfreund/nixarchy-distrobox | `DistroboxState` singleton |
| nixarchy.microvm | olafkfreund/nixarchy-microvm | `MicrovmState` singleton |
| nixarchy.winvm | olafkfreund/nixarchy-winvm | VM actions use `execDetached`; only a status poll lives in the view |

The gain is that none of the four is built at startup, and winvm's 4 s poll
does not run until first use. After a view has been opened once, closing it
with Esc or a click only hides it (the shell keeps it loaded); a toggle-close
or `shell hide` unloads it.

Known small losses, stated in each PR: `shell call <id> status` answers
`unknown` until first open (microvm `Menu.qml:93-94`, distrobox `:92`; no
caller found); winvm's uptime counter restarts after an unload. Stale "keepLoaded, so every open starts clean"
comments are updated in the same PRs.

Kept loaded, each for a reason the audit found:

| Plugin | Reason |
|---|---|
| pkg | an in-panel apply runs `nixarchy-apply` as a menu child process |
| podman | stop or prune runs in the menu's own `PodmanState` instance |
| flatsnap | `_apply` (`FlatsnapModel.qml:401`, owned by the menu, `Menu.qml:44`) can be killed by a toggle-close before `systemd-run` hands the build to its unit |
| herdr | session creation runs `actionProc` owned by the menu's `HerdrModel` (`HerdrModel.qml:1400-1412`) |
| govee | `GoveeClient` (queue, running command) is a menu child, and every close calls `shell.hide` (`GoveeMenu.qml:45-48,126`) |
| github-actions, gitlab-pipelines | watched runs live in the panel |
| ai-mirror | the overlay is the consent-dialog daemon |
| nixi | pinned conversations live in `Ask.qml` |

Quickshell kills a running child process when its `Process` object is
destroyed (`process.cpp:31-37`, quickshell v0.3.2), which is what makes the
kept ones unsafe.

**Delivery.** Each plugin PR merges in its own repo. This repo pins the
merge commit with the existing override pattern under `inputs.nixarchy`
(`flake.nix:77-84`), with a "remove once nixarchy pins <rev> or later"
comment. An override replaces the whole input, so it repeats the attributes
the lock shows:

| Input | Override attributes |
|---|---|
| `nixarchy.inputs.nixarchy-devenv` | `url`, `inputs.nixpkgs.follows = "nixarchy/nixpkgs"` |
| `nixarchy.inputs.nixarchy-distrobox` | same |
| `nixarchy.inputs.nixarchy-microvm` | same |
| `nixarchy-winvm` (root input, `flake.nix:130-133`) | `nix flake update nixarchy-winvm` |

The root `nixarchy-distrobox` and `nixarchy-microvm` already follow
`nixarchy/...` and need nothing. After `nix flake lock`, the lock must gain
no new `nixpkgs_N` node.

### 2. Application-folder rescans

- **hyprforge** (`olafkfreund/nixarchy-hyprsettngs`, `Service.qml:63-89`):
  compare the current entry with the wanted text before touching the
  folder, normalising hyprchroma's rewrite (`Icon=<name>` plus
  `X-Omarchroma-Original-Icon=<path>` back to `Icon=<path>`), create the
  temp file only when it differs, and drop `removeScript` and
  `Component.onDestruction` so the entry survives service restarts (owner
  decision). Update the header comment (`Service.qml:9-10`) and README
  (277-278). Diff: scratchpad `fix/hyprforge.diff`. The Fable reviewer ran
  sh -n, shellcheck, GNU sed and inotifywait over missing, foreign,
  symlink, dangling, unreadable, changed-Exec and themed files; Codex
  checked the quoting and the sed normalisation on a themed entry. Delivered by an
  override `nixarchy.inputs.nixarchy-hyprsettngs` with `url` and
  `flake = false`.
- **omamail** (huacnlee/omamail, `scripts/register-mailto.sh:39-54`): build
  the entry in a variable, compare with the normalised file, and only on a
  difference write it and run `update-desktop-database`; `claim_default` is
  unchanged. Applied to the checkout `~/.config/omarchy/plugins/omamail` as
  an uncommitted change: `omarchy-plugin-update` does `git merge --ff-only`,
  which a local commit would block, while an uncommitted change survives a
  fast-forward as long as upstream leaves the file alone (unchanged on
  `origin/main` today). The unrelated dirty `ui/tests/qml/tst_setup_name_field.qml`
  is left as it is. The same diff goes upstream as a PR, posted only after
  the owner has seen its text.
- **hyprchroma** is not changed: once the two writers stop reverting its
  edit, it rewrites each entry once and stops.

### 3. Dead bar settings

On p620 and razer, through the shell's own reload path (the sequence of
upstream's `omarchy-shell-config`):

1. Copy `shell.json` to `shell.json.bak-3107` and record its sha256.
2. `jq 'del(.bar.hiddenRevealByRegion, .bar.revealIcons) | .bar.layout |=
   map_values(map(if type == "object" and (.hidden | type) == "string" then
   del(.hidden) else . end))'` into `.shell.json.new`. The tray's
   array-valued `hidden` is kept (`Tray.qml:23`).
3. Check `.version == 1`, and that the new file equals the backup with only
   those keys removed (apply the same filter to the backup and compare).
4. Re-hash `shell.json`; if it changed since step 1, start again. Otherwise
   `mv` into place and run `omarchy-shell shell reloadConfig`.
   A write landing between this hash and the `mv` is still lost: nothing
   locks out the shell's own writers. This residual risk is accepted; the
   window is milliseconds, and `shell.json.bak-3107` is the recovery.
5. Verify with `omarchy-shell shell listShellConfig`: the three kinds of
   key are gone, and every other value equals the filtered backup. Repeat
   the file check after the next login, since plugins that write back their
   own settings (omamail, herdr, omadroid) could restore a stale copy.

## Alternatives rejected

- **Patch keepLoaded at install time in this repo**: the owner chose PRs to
  own repos (2026-11-19).
- **Wait for nixarchy edge**: edge publishes from main once a day and needs
  a nixarchy pin bump first; the override pattern exists for this.
- **Move hyprforge's temp file to `$XDG_RUNTIME_DIR`**: a cross-filesystem
  `mv` loses the atomic, symlink-safe rename.
- **Patch hyprchroma**: third-party, and fixing the two writers ends the
  loop.
- **Make govee, herdr, podman, pkg or flatsnap safe to unload** (singleton state,
  detached jobs): real work in each plugin, beyond this task. Listed as
  follow-ups in the PR.
- **Commit the omamail patch locally**: blocks every `omarchy plugin update`.

## Risks

- **First open is slower** for the four lazily loaded views (cold QML).
- **hyprchroma marker**: the normalisation depends on
  `X-Omarchroma-Original-Icon`; if hyprchroma renames it, the rescan
  returns and nothing breaks.
- **omamail upstream change** to `register-mailto.sh` would make the
  fast-forward refuse to overwrite the uncommitted file; the update then
  fails until the patch is dropped or merged upstream.
- **Override drift**: each override must be removed once nixarchy edge pins
  the commit, or a later nixarchy bump is masked.
- **razer** has a different bar layout and was not audited for callers. The
  four plugin changes are caller-neutral (all callers open by
  `shell toggle`), and its `shell.json` gets the same checked filter.
- **Small samples**: two logins per side can hide noise; the report gives
  every sample, not an average alone.

## Verification

- Each plugin PR: the repo's own tests or CI pass.
- This repo: `just check-syntax`, `just test-host p620`, `just test-host
  razer`; `jq` on `flake.lock` shows each override at its new rev and no
  new `nixpkgs_N` node.
- After deploy on p620: each of the four opens by keybind or menu row;
  `jq .keepLoaded` on the installed manifests is null for the four and true
  for the kept ones.
- Rescans: after one shell reload and one login, no "performing full
  rescan" within 60 s of launch, and `stat` of `hyprforge.desktop` and
  `omamail.desktop` unchanged across two reloads.
- shell.json: step 5 holds on p620 and razer, and again after the next
  login.
- Reveal: the gate table for two baseline and two after logins, every
  sample shown.
