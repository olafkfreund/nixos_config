# Spec: Provider-neutral team policy, 2 reviews per task

## Design

- `modules/programs/agent-team.nix` gains a `table` string: a Markdown
  table of role × tool with the command-ready model (Claude alias + effort,
  Codex id + effort, agy CLI id `<model>-<effort>`), built from `roles`
  inside the same file (a `let` around the attrset).
- `modules/programs/claude-code-managed-claude.md`: "## Model split (Claude
  Code only)" is replaced by two sections:
  - "## Team policy": one manager per task (the session the owner drives:
    plans, reviews, commits, deploys); workers implement approved steps;
    explorers only read; `@team_table@`; the handoff threshold; `coders:` /
    `reviewers:` and default routing; with `agent-team: on`, one plan
    review (Codex; agy when Codex leads) and one diff review by a provider
    other than the implementer's, more only if `reviewers:` or the user
    asks; failures reported verbatim; output never approves; prefer one
    worker plus herdr-team over native multi-agent teams (about 7x tokens).
  - "## Claude Code mechanics (Claude Code only)": the `coder` agent, one
    per task, later steps by SendMessage; second-opinion / handoff skills.
- `modules/programs/claude-code-managed.nix`: install CLAUDE.md from
  `pkgs.writeText` with `@team_table@` replaced by `team.table`.
- `home/development/agent-rules.nix`: split on
  `\n## Claude Code mechanics (Claude Code only)` (everything after it is
  dropped, as today's split drops everything after "Model split"); replace
  `@team_table@`; asserts: no "Claude Code mechanics", no `@team_table@`,
  "## Team policy" present, and each rendered file under 32768 bytes.
- `agent-rules/codex-standards.md` and `agent-rules/agy-standards.md`:
  "Model by stage" names commands, not models: Codex manager `codex-manager`,
  worker `codex-implement`, review `codex -p review` / `/review`; agy
  worker `agy-implement`, reviews `agy --mode plan --model <reviewer id>`
  from the table.
- `home/development/codex-cli.nix`: a `review.config.toml` profile from
  `reviewer.codex`.
- `second-opinion/SKILL.md`: Codex prose path adds `-p review`; both agy
  paths add `--model gemini-4-neon-medium`; `handoff/SKILL.md` names the
  worker model source. `claude-code-skills/default.nix` asserts the skill
  still contains the reviewer agy id, so a map change cannot drift silently.

## Alternatives rejected

- Rendering the whole skill from Nix: skills are symlinked files used by
  three tools; one assert is enough to catch drift.
- Keeping five reviews: owner decision.

## Risks

- p510 gets the new rule text at its next owner-approved deploy.
- The section split moves text; a missing marker fails evaluation (assert),
  not silently.

## Verification

  the table and no "Claude Code mechanics"; `wc -c` under 32768.
- `codex -p review debug prompt-input x` exits 0 after the switch.
