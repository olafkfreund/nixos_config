# Spec: Claude Code as a herdr-team member

## Design

- **Turn reporting.** A new sink, `home/development/claude-sink.py`, packaged
  as `herdr-team-claude-sink` in `agent-run.nix`, runs as two Claude Code
  hooks given through the member's `--settings` JSON, each with the turns
  directory as its argument:
  - `UserPromptSubmit`: writes the prompt text (`.prompt` from stdin) to
    `<turns>/.claude-input`.
  - `Stop`: reads `.transcript_path` from stdin, takes the text blocks of
    the assistant messages after the last user prompt in that JSONL file
    (or `.last_assistant_message` when the hook provides it), and writes
    `<turns>/<uuid>.json` = `{turn_id, input: <saved prompt>, reply, source: "claude"}`
    through a temp file, refusing symlinks and oversize input, like
    `notify-sink.sh`. Always exits 0 and prints nothing.
- **herdr-team.sh** (both backends):
  - roles `claude-review` and `claude-implement`, kind `claude`;
  - argv `agent-env env -u ANTHROPIC_API_KEY -u ANTHROPIC_API_KEY_FILE claude
    --model <model> --effort <effort> --permission-mode <mode> --settings <file>`
    where model and effort come from the role map (`reviewer.claude`,
    `worker.claude`), overridable with `--model` / `--effort` (#3266), and
    the mode is `plan` for the reviewer and `bypassPermissions` for the
    implementer; `<file>` is a JSON file in the member's work dir with the
    two sink hooks, plus, for the implementer, a `PreToolUse` `Bash` hook
    running the coder guard at `/etc/claude-code/hooks/coder-guard`
    (installed from the existing `coderGuardScript` by
    `claude-code-managed.nix`);
  - the ask loop accepts turn files with `source == "claude"`;
  - readiness waits for herdr to report agent `claude` in the pane; while
    waiting, if the screen shows Claude Code's workspace-trust question,
    herdr-team accepts it once (it has already refused the shared checkout
    and `main`, so only a task worktree reaches this point).
- **Tests:** `claude-sink` unit tests against fixture transcripts; herdr-team
  test cases with a fake `claude` that records its argv and plays both
  hooks; a live smoke test after the switch (one `claude-review` member,
  one `ask`, `down`).

## Alternatives rejected

- `claude -p` per prompt: no warm session, so every turn re-reads the
  repository and pays a fresh cache.
- The Claude Agent SDK: subscription use needs an OAuth token in the
  environment, and a stray API key silently wins (Phase 1 research).
- Native Claude agent teams: interactive inside one Claude session only, and
  about 7x the tokens.

## Risks

- Claude Code's Stop hook fields could change; the sink falls back between
  `last_assistant_message` and the transcript, and an unreadable turn means
  no answer (a timeout), never a wrong one.
- Accepting the trust question automatically could, if herdr-team's
  worktree checks were wrong, trust a directory the owner would not.
- The implementer runs with `bypassPermissions`; the coder guard is the
  barrier, as for the other implementers (#2812).

## Verification

- `just test-host p620`, `just test-host razer` (both run the new tests).
- After the switch: a live `herdr-team up <task> claude-review` in a scratch
  worktree, `herdr-team ask` with a one-line question, the answer file
  holds a reply, `herdr-team down`.
